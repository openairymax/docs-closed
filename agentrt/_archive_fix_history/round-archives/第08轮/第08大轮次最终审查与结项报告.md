### 5.2 CI/CD 失败根因分析

GitHub Actions 全部失败的最可能原因（按可能性排序）：

| # | 根因 | 影响范围 | 修复方案 |
|---|------|---------|---------|
| **A** | **cmocka 测试框架缺失** | ci.yml test-suite job | `apt-get install -y libcmocka-dev` 未在依赖安装中列出 |
| **B** | **构建产物路径不匹配** | ci.yml matrix-build | 第104-111行验证的路径 `agentos/lib/libagentos_common.a` 等可能与实际构建输出路径不同（CMake目录结构差异） |
| **C** | **Repository secrets/环境变量未配置** | ci.yml + release.yml + security-audit.yml | `GH_TOKEN`、`DOCKER_USERNAME` 等变量未在 GitHub Secrets 中设置 |
| **D** | **workflow_dispatch inputs 语法兼容性** | ci.yml 第82行 | `${{ github.event.inputs.run_tests || 'ON' }}` 在 push 事件中 `github.event.inputs` 为 undefined，需要更健壮的默认值处理 |
| **E** | **libjson-c-dev 重复声明** | ci.yml 第70/72行 | 重复但不会导致失败 |
| **F** | **缺少 `github.token` 权限配置** | stub-check.yml 等 | 部分工作流可能需要 `contents: read` 显式声明 |

### 5.3 工作流整理建议

**核心保留（3个）**：
1. `ci.yml` — 主CI管道（构建+测试+质量门禁一体化）
2. `toolkit-ci.yml` — SDK构建与测试
3. `stub-check.yml` — 反模式检测（独有功能）

**建议合并（4个→2个）**：
- `docs-check.yml` + `api-docs.yml` → 合并为 `docs-ci.yml`
- `quality-gate.yml` + `tests-test.yml` → 合并入 `ci.yml` 的jobs

**建议保留但解耦（4个）**：
- `build-desktop.yml`（trigger on tag only）
- `release.yml`（trigger on tag only）
- `security-audit.yml`（定时运行，非阻塞）
- `protocol-compatibility.yml`（特定路径触发）

**建议移除（3个）**：
- `dependency-update.yml` — 依赖更新可用 Dependabot 代替
- `quality-monitoring.yml` — 功能被 ci.yml 的 SEC-016/SEC-017 覆盖
- `stale.yml` — GitHub 内置功能
