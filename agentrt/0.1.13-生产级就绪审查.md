## 0. 审查方法

三项独立审查交叉定案：

1. **产品运行态**：以 G4b macOS 干净真机核验（最近一次 rc 资产的端到端实启）
   + e2e-clean-room（洁净 Linux 容器 daemon 群/CLI/升级/回滚）为运行态证据；
2. **流水线建设**：release.yml 全环节（触发→构建→测试→e2e 门禁→打包→预检
   →publish→三端镜像）逐环节取证；
3. **社区问题清零**：历史 1000 轮对话中社区用户报告的启动/更新/安装/对话/
   执行任务/稳定性问题逐项复核（§5 台账）。

"就绪"判定口径：八平台门禁腿全绿 + 发布完整预检 fail-closed + 洁净环境
e2e 全链绿 + 干净真机 daemon 群可启 + 已知缺陷清零或归宿明确。

## 2. 产品运行态（审查项 B）

### 2.1 干净真机端到端（G4b macOS Clean-Host）

**终局证据 run 21**（id 34294100622，head 4bae84c51，2026-09-09）：

- arm-64 腿（job 102286816160）：干净 macOS runner 安装（install.sh
  --prefix）→ daemon 群自启 → gateway online（127.0.0.1:8080）→ CLI 冒烟
  **online 14/14** → `[OK] macOS 干净真机核验通过`；
- x86-64 腿（job 102286816405）：同链路全绿（CLI 冒烟 online 14/14）；
- 覆盖验证点：dylib 自包含（rc9 修复后的 bundle-macos-dylibs.sh，gateway_d
  首位依赖 `@executable_path/../lib/libmicrohttpd.12.dylib`，全 bin/ 零构建
  机绝对路径残留）、安装器、daemon 群、gateway HTTP 面、CLI 全命令连通。

首跑 run 20（rc10）失败经 run 21 全绿复核定性为 runner 网络间歇 flaky
（非产品缺陷；取证脚本 4bae84c51 加固，复发可直接定位）。

### 2.2 洁净容器 e2e（Linux 主力平台）

rc4 实证（run 34135340289）起 e2e-clean-room 全链 SUCCESS：安装 → daemon
群（15 服务）→ gateway 8080 → CLI 冒烟 → U9 升级 → 回滚。rc2 期曾 FAIL
（exit 127）验证了门禁语义真实生效（publish 被正确阻塞）。

### 2.3 运行稳定性专项（社区"一个对话就卡"根因链）

- 根因：v0.1.12 TUI 普通对话走 legacy `/api/v1/chat/stream` 且 gateway 收尾
  帧缺失 → 流完成后 TUI 永收不到结束帧、界面挂起；
- 修复：TUI 全量切 `agent.run_stream`（tui e9bb7f3 → ffcce22，run_end 事件
  终态语义）+ gateway SSE 心跳（notify_d 25s 注释帧，daemons 07a2a23）+
  legacy 410 退役（gateway 5046b6d；C CLI legacy 消费面终审为零调用）；
- 附带结案：gateway PEP epoch watch 60s 断线噪声（心跳后复位 idle，实测
  24.9s 收帧）；
- rc10 携带上述全部修复，目标机 `airymaxrt update` 自愈。
