# agentrt 0.1.9 架构改进方案

> 状态：已评审定稿（基于近 20 轮逐行代码复核 + 2026-09-02 近 100 轮回顾终审补充，全部结论附一手证据路径）
> 目标版本：**0.1.9**
> 总纲：**机制留内核并强化（稳定思考）、策略沉 daemon 快速演化（灵活执行）、地基归 commons（稳定运行）**

## 0. 总体结论与裁决框架

### 0.1 两基石定性（本轮确立的架构判据）

| 层 | 定性 | 判据 |
|---|---|---|
| **commons** | agentrt 在宿主机上的统一地基 | 零 intra-agentrt 上游依赖（commons/README_zh.md L20/L30/L218 明文）；类型系统（airy_types.h）与错误契约（airy_err_t）唯一权威；`commons/include/airymax/*.h` 为契约层，允许内核态独立编译 |
| **atoms** | 微内核系统层，操作系统级设计 | coreloopthree = 三层认知循环（cognition/execution/memory）机制框架，控制论闭环本体；corekern = 纯原语 |
| daemons | 用户态服务层 | 机制之外的策略/服务语义 |
| gateway | daemon 世界唯一进程边界 | K-1 内核极简：只做协议翻译，零业务逻辑 |
| CLI / TUI | 用户世界引擎入口 / 渲染仪表盘 | CLI 组织（不自持核心逻辑）、TUI 渲染 |

### 0.2 机制/策略分离判据（coreloopthree 裁决框架）

三循环本质是"系统工程 + 工程控制论"的实现：**传感器（GCCP）→ 决策器（双思考）→ 执行器基底（work_hall）→ 校正器（GRAD）→ 记忆反馈（memory）**。

> 判据一句话：**控制闭环的结构 = 机制（留 coreloopthree）；闭环内可参数化的决策内容 = 策略（迁 daemons）。**

## 1. 阶段 0：commons 地基归位 + utils 扁平化

### 1.1 0a — 摘除 commons→atoms 反向依赖

- **改动**：commons/CMakeLists.txt 删除 `${CMAKE_CURRENT_SOURCE_DIR}/../atoms/corekern/include` 这一行 PUBLIC include；需要 `airy_memory.h` 等内核头的消费者改由 atoms 自己的 CMake 接口（INTERFACE target）获取。

### 1.2 0b — error.h 体系确认已收敛（原"3→1"降级，2026-09-02 终审修正）

- **修正**：原"error.h 三份并存=冗余，3→1 合并"为**误判**——实测三份 error.h 职责分离、零重复定义，是 S-1 收敛（2026-08-14）后的既定 SSoT 分层：
  - `commons/include/airymax/error.h`（[SC] 契约，AIRY_E* 正幅值，内核 UAPI 专用，sc-dual-ci 校验）；
  - `commons/include/airy_types.h`（用户态权威：include [SC] 后 `#undef` 重定义 POSIX 码为负值 + 用户态专属码，AIRY_EINVAL=-22 等硬定义唯一源）；
  - `commons/utils/error/include/error_codes.h`（AIRY_ERR_* 用户态扩展码，仅 `#ifndef` 补充别名）；
  - `commons/utils/error/include/error.h`（错误处理框架：chain/severity/str，不含重复枚举）；
  - `atoms/corekern/include/error.h`（聚合转发头：airy_types.h + utils/error.h + 内核扩展 AIRY_ECYCLE——**已达成**"include 契约层"）。
- **保留动作（防回归）**：核心码（AIRY_EINVAL/ENOMEM/EBUSY 等）硬定义唯一性核对入库——仅 airy_types.h（负值）与 airymax/error.h（正幅值）两处，禁止第三处硬定义；error_codes.h 维持 `#ifndef` 别名模式。
- **验收**：`grep -rn '^#define AIRY_EINVAL' commons/` 仅命中 airy_types.h 与 airymax/error.h；sc-dual-ci 全绿。

### 1.4 0d — utils 扁平化（目录=内聚模块、文件=原子功能）

**规范文本**（落入 commons/README Layout 节）：

```
utils/<feature>/             # 一个目录 = 一个内聚模块
utils/<feature>/*.h *.c      # 公共头与实现平铺，禁止子目录
utils/<feature>/*_internal.h # 内部头同目录平铺，_internal 后缀
utils/<feature>/data/        # 仅非代码资产（如 ime 词典）——可选
域语义用文件名前缀承载        # config_core.c / config_source.c，不用子目录表达
测试一律入 commons/tests/    # 模块内禁止 test/ 目录
```

### 2.4 1d — agent.run_stream 流式事件帧协议（v1，预留冗余设计）

> **背景（实际状态）**：现 `agent.run` 为非流式 JSON-RPC，一次 `POST /` 返回 `RunResponse` 整体体；网关内部虽有 `run_start/plan/tools` 事件记录（经 `gw_agent_record_event(session_id,"chain",evt)` 写入会话），但只落本地，不向客户端流式推送；`agent.cancel` 依赖 `sess_` 前缀会话 ID。M1 将引擎下沉 agent_d 后，改为 agent_d 进程内引擎**以流式事件向 gateway 推送**，gateway **纯翻译**为 SSE 帧。本协议即该下行的结构化契约。

#### 2.4.1 传输层

- 调用：JSON-RPC 2.0，`method=agent.run_stream`，`POST /`，`Content-Type: application/json`。
- 响应：`200 + text/event-stream`（SSE）；每事件一个 `data:` 帧，单行 JSON，`\n` 收尾。
- 兼容：HTTP 连接复用；协议线上版本走 `?version=1`；SSE `retry:` 给出重连间隔。
- 中断：客户端 Ctrl+X → `agent.cancel`（携带 `session_id` + `run_id`）；服务端 terminate 后发 `run_end(status=cancelled)`。

#### 2.4.2 事件信封（所有事件的公共外层——**序列号/时间戳/元数据预留是冗余核心**）

```jsonc
{
  "v": 1,                    // 协议版本（整型，最高位为向后兼容提示；未来 2.x 增字段不删字段）
  "type": "<event_type>",    // 事件类型，见 2.4.3 枚举
  "id": 73,                  // 帧序列号：同一 run 内单调递增，用于去重/对齐/断点后重播对齐
  "run_id": "run_2f8c...",   // 本次运行唯一；跨重连/多请求辨识同一次运行
  "session_id": "sess_...",  // 会话标识（sess_ 前缀，与 agent.cancel 对齐）
  "ts": 1786195200123,       // 单调毫秒墙钟
  "epoch": 7,                // 策略/版本 epoch（M2 后用于 PEP 相关帧失效标记；预留）
  "trace": { "trace_id": "…", "span_id": "…", "parent_id": null }, // 可观测贯穿（预留）
  "meta": { /* 预留扩展槽：任意附加键值，禁止影响解析 */ },
  "data": { /* 类型化负载，见各类型 */ }
}
```

#### 2.4.3 事件类型（分层枚举，三类已落地 + 预留 X 类）

> 设计原则：**每层一个 namespace，各自向后加类型；未知 type 客户端必须忽略不崩（宽容读取）**。

| 层 | type | data 负载 | 状态 |
|---|---|---|---|
| **control** | `run_start` | `{prompt, agent, model, config_hash, resumed}` | 现网有 |
| | `run_end` | `{status: completed\|cancelled\|failed, duration_ms, use_ticks}` | 须新增 |
| | `error` | `{code, message, detail, recoverable, suggest_action}`（替代旧 `__airy_evt:error`信封） | 现网有信封→原生帧 |
| | `ping` | `{}`（保活/心跳） | 预留 |
| | `run_pause` / `run_resume` | 交互式中断/续做（GCCP 澄清期调起） | 预留 |
| **cognition** | `think_start` / `think_end` | `{phase, model, token_meta}` | 预留（现网关两段式直接透传） |
| | `gccp_questions` | `{questions:[{qid,q,kind,choices}]}` —— 第二段 `gccp_answers` 回填 | **现网 gccp 两段式** |
| | `plan` | `{plan, steps:[{id,title}]}` | **现网有** |

| | `tool_delta` | `{tool_id, partial}`（CLI 工具流式输出） | 现网缺失→新增 |
| | `tool_end` | `{tool_id, status, truncated, result_hash}` | 现网有→结构化 |
| | `agent_event` | 编排子事件（spawn/invoke 生命周期） | 预留 |
| | `channel_push` | 数据面通道推送（channel_d 集成，预留） | 预留 |
| **outcome** | `token_delta` | `{delta, finish_reason?}`（流式 token 增量） | 现网 llm_d 流式 |
| | `message` | `{role, content, reasoning, refs}`（整条最终消息） | 现网 RunResponse |
| | `attachment` | `{kind, uri, mime, size, refs}`（产物/附件） | 预留 |
| | `usage` | `{prompt_tokens, completion_tokens, cost}` | 现网 llm_d 成本 |

#### 2.4.4 冗余与演进约定（为更强功能预留的机制性承诺）

1. **语义版本**：信封 `v` 为主版本；类型各自带小版本（`type:tool_delta` 视为 v1）。**只加不删**、**只弱化不收紧**校验。
2. **枚举外延**：新层/新类型仅追加 namespace；客户端对未知 `type` 忽略、未知字段透传。
3. **容量预留**：`id` int64、`ts` int64、`meta` object、`trace` object——未来多 rid、多租户、多模态均落在现有槽位。
4. **一致性钩子**：`run_id`（单次运行）+ `id`（帧序）+ `epoch`（策略版本）三者构成**可对齐、可去重、可断点续传**的锚点；为大历史虚拟渲染（W8）预留分页游标 `cursor=next_id`。
5. **替代关系**：本协议上线后，旧 `gateway_sse_stream.c` 的 `__airy_evt:error` 错误信封检测退役（HH5）；`agent.run`（同步体）保留为 `run_stream` 的降级别名直至 0.2.0。

#### 2.4.5 端到端落地归位

```
agent_d 引擎 → 结构化事件流(本协议数据模型)
   →(process 内)   （agent.run_stream 处理器聚合）
gateway_d → SSE 翻译（仅帧封装，零业务）
   → sdk-*：sdk-rust/sdk-python = 原生事件解码器；
     sdk/cli = 引擎壳消费；sdk/tui = W1 三区渲染
```

- 协议 schema 唯一权威：落 `sdk/sdk-rust`（解码器）与 `gateway`（编码器）共引，避免双份定义（SSoT，同 0d 纪律）。
- 验收：agent_d 不下沉前，gateway 可用本协议对 `agent.run` 现有事件做**包装直译**先行落地，TUI W1 先行接入，再随 M1 引擎下沉切换真流式——**协议先行、引擎后迁**，降低 M1 一次性风险。

### 3.1 现状（复核确凿）

### 3.2 PDP/PEP 拆分（XACML 模式）

```
策略包(yaml/包工件) → PAP：market_d 分发（与 skill/agent 包同构流水线）
                        ↓
PDP：cupolas_d（唯一策略持有者）
  · 实现 dynamic_policy_engine：版本/冲突消解/热更/回滚（epoch 单调递增 SSoT）
  · vault / entitlements / netsec 集中持有（密钥单点）
  · RPC：policy.load / activate / rollback / status
        │ epoch 变更广播（notify_d topic=airy.cupolas.epoch）
        ▼
PEP：各 daemon 进程内最小 guard（保留，零延迟热路径）
  · sanitizer（纯函数变换，必须本地）
  · 裁定缓存（以 epoch 为失效键）
  · workbench 本地强制执行（策略来自 PDP）
  · audit 事件 → 汇聚 cupolas_d 审计 sink
```

### 3.3 策略演化工具链

1. **热更新**：`policy.load → 冲突检测 → activate（epoch+1）→ 广播 → PEP 缓存自动失效`；出问题 `policy.rollback` 秒级回退（32 版历史）。
2. **影子评估**：新版本"只裁定不执行"并行运行，对照差异日志后 activate——策略灰度不停机。
3. **策略即工件**：策略包走 market_d 分发/版本/安装流水线——策略从"改码发版"变"发包"。
4. **离线兜底**：最小 profile 保留本地 yaml 回退。

### 3.4 前置与验收

- 前置：现有 cupolas_d `cupolas.check_permission` RPC p50/p99 基准；PEP 缓存命中率 ≥ 覆盖热路径。
- 验收：各 daemon 引导不再本地初始化 permission/vault/netsec；策略变更全runtime生效时间 < 1s；单进程内存下降可测量。

### 5.1 整编后的边界深化（15 daemon 契约表）

进程数 15 为稳态（hook/a2a/channel/maths 各有隔离或协议价值，不再减）；深化的是**每 daemon 的边界契约**——职责一句话、独占 namespace、禁区。以 gateway cap registry 为执行点：

| daemon | 边界（职责一句话） | 独占 namespace | 禁区（明确不做） |
|---|---|---|---|
| gateway_d | 唯一进程边界：协议翻译（HTTP/WS/SSE/MCP/A2A/OpenAI ↔ JSON-RPC） | gateway.* | 任何业务逻辑：会话、编排、工具、权限裁定（M2 后仅转发） |
| agent_d | agent 本地生命周期 + 执行循环引擎（M1 承接工具循环/会话表/agent.run_stream） | agent.* | LLM 调用细节（→llm_d）、工具实现（→tool_d）、认知决策（→think_d） |
| llm_d | LLM 推理服务：流式补全、成本核算、Token 预算 | llm.* | 工具执行、对话编排 |
| tool_d | 工具注册表与执行（内置 + 插件 dlopen；M4 吸收 plugin_d） | tool.* / plugin.* | 认知决策、直接调 LLM |
| sched_d | 调度域：DAG、分发策略、Roadmap Sched（M3 承接）、治理槽位 | sched.* / roadmap.* | 任务执行本身（→agent_d/tool_d） |
| think_d | 认知服务面：CDF→GCCP→双思考→GRAD（M3 吸收 lang_gateway/orchestrator）；**认知引擎唯一服务面** | think.* | 工具执行、持久记忆（→mem_d）、LLM 直调（经 llm_d） |
| mem_d | 持久化记忆服务（跨会话、MemoryRovol L1-L4 语义检索） | mem.* | 运行期工作记忆（atoms memory 引擎）——分层声明：mem_d 只做持久层与检索 |
| market_d | 扩展工件分发：agent/skill/template/**策略包（M2 PAP）**的安装/版本/注册 | market.* | 工件执行（→tool_d/agent_d） |
| monit_d | 可观测域唯一出口：指标/告警/tracing（M4 吸收 observe/info） | monit.* | 业务健康判断（只采集与告警） |
| notify_d | 事件扇出 pub/sub（WS/SSE/Unix，topic 语义） | notify.* | 数据面传输（→channel_d）、策略裁定 |
| channel_d | 数据面应用级通道工厂（socket/shm，/airy_ch_*） | channel.* | 控制面 RPC（svc_common 总线）、事件扇出（→notify_d） |
| a2a_d | 跨 agent 协议：Agent Card 注册/发现、A2A 任务状态机、消息投递 | a2a.* | 本地进程生命周期（→agent_d）、协议翻译（→gateway_d） |
| cupolas_d | 安全 PDP：策略裁定/版本/回滚（M2 收权）+ vault/entitlements/netsec 单点 | cupolas.* / policy.* | 业务逻辑、PEP 本地执行（各 daemon 自留 guard） |
| maths_d | 数学引擎沙箱（隔离不受信计算） | maths.* | 通用工具执行（tool_d 仅转发） |
| hook_d | coreloopthree 拦截挂点 IPC 适配壳（M3 后只链 airy_coreloop_hooks） | hook.* | hook 执行器实现（内核机制）、策略裁定（→cupolas_d） |

**边界深化的执行机制（防漂移，不是写文档了事）**：

1. **namespace 独占性门禁**：gateway cap registry 启动时校验 `namespace → daemon` 唯一映射，冲突 fail-closed 拒启——边界从"约定"变"启动期断言"；
2. **deps.txt 登记 15 节点**：每 daemon 的依赖白名单入 DAG 门禁（如 tool_d 禁 link llm 客户端、think_d 禁直接调 tool_d）；
3. **跨界调用必须走总线**：禁区列中所有 `→` 关系即 svc_common ipc_service_bus 调用，daemon 间禁止进程内符号引用（链接期由 depgraph 校验）。
