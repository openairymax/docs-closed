# agentrt 0.1.11 架构改进方案

> 状态：规划（2026-09-05 立项，2026-09-05 定版）
> 目标版本：**0.1.11**
> 范围：发布链全迁 GitHub Actions + 平台矩阵全覆盖（linux/macOS/windows × 32/64）+ 命名体系固化
> 前身：本文件由 `0.2.0-架构改进方案.md` 改写重立项（版本口径变更：原 0.2.0 规划并入 0.1.11 工程链目标；架构层遗留后移见 §6）
> 编写纪律：每项必须附一手证据路径（真实问题）；禁止为凑规划而发明任务

## 0. 决策记录（2026-09-05 定版）

经用户逐项裁决，以下决策为 0.1.11 的硬约束：

| # | 决策 | 含义 |
|---|---|---|
| D0 | **正式制品全流程迁移 GitHub** | 构建、集成、打包、签名、manifest、上传 atomgit release、push `latest/` 全部由 GitHub Actions 流水线完成；本机只边开发边测试，不再承担正式二进制包发布 |
| D1 | **签名私钥进 CI** | GPG / cosign 私钥存 GitHub Actions **Environments secrets**（受保护 Environment，人工审批 + 分支限制），并建立轮换/应急恢复口径 |
| D2 | **tag 自动全链 + 审批阀** | tag push 自动跑完整矩阵；发布 job 绑定受保护 Environment，人工 Approve 后才执行签名上传 |
| D3 | **平台全覆盖** | linux / windows / macOS 的 32、64 位全部覆盖（见 §1 矩阵）；macOS 无 32 位为现实约束 |
| D4 | **RISC-V 后移至 0.3.x，预留设计** | 0.1.11 不做 RISC-V 腿，但命名/schema/流程**预留**并同步修改流程；0.3.x 实施 |
| D5 | **平台命名规范固化** | 全链统一 `OS-架构族-位宽`（gen3），不再出现 i686/armv7l/x64/arm64 等行话做交付命名（见 §1.2） |

## 1. 平台矩阵与命名体系

### 1.1 0.1.11 发布门禁矩阵（8 腿）

| 平台键 | OS | 架构族-位宽 | runner / 容器 | 0.1.10 状态 | 0.1.11 要求 |
|---|---|---|---|---|---|
| linux-x86-64 | linux | x86-64 | ubuntu:20.04 container | ✅ gate | 保持 gate |
| linux-x86-32 | linux | x86-32 | debian:bullseye-20240812-slim（linux/386） | ✅ gate | 保持 gate |
| linux-arm-64 | linux | arm-64 | ubuntu:20.04（qemu arm64） | ✅ gate（本版 run 验证中） | 保持 gate |
| linux-arm-32 | linux | arm-32 | ubuntu:20.04（qemu arm/v7） | ⚠️ experimental | **升为 gate**（cmake armhf 供给收敛后） |
| windows-x86-64 | windows | x86-64 | windows-latest 原生 MSVC | ⚠️ policy 跳过 | **入 tag 自动矩阵，gate** |
| windows-x86-32 | windows | x86-32 | windows-latest（MSVC x86 工具集 / vcpkg x86-windows） | 无 | **新增 leg，gate** |
| macos-arm-64 | macos | arm-64 | macos-latest（arm64） | ✅ gate | 保持 gate |
| macos-x86-64 | macos | x86-64 | macos-15-intel | ✅ gate | 保持 gate |

**现实约束（写入口径）**：
- macOS 自 10.15（Catalina）起无 32 位运行环境与工具链，**不存在 macos-32 包**；“32 位全覆盖”对 macOS 不可行，文档化即不施工。
- Windows ARM 生态只有 arm-64（无 arm-32）；windows-arm-64 未列入 0.1.11（无 hosted ARM runner，需交叉工具链，待 0.3.x 与 RISC-V 一并评估）。
- RISC-V：linux-riscv-64 / linux-riscv-32 命名与 schema **预留**，0.1.11 不出 tag 自动腿（dispatch-only 保留与否见 §3 B4）。

### 1.2 平台命名规范（三代兼容，SSoT）

| 代 | 时期 | 形式 | 示例 |
|---|---|---|---|
| gen3 | 0.1.10 起（本版主键） | `OS-架构族-位宽` | linux-x86-64 / linux-arm-32 / macos-x86-64 / windows-x86-32 |
| gen2 | 0.1.6e–0.1.10 | `OS-arch-word` | linux-x64 / macos-arm64 / win-x86-64 |
| gen1 | ≤0.1.6d | uname 原名 | linux-x86_64 / linux-i686 / linux-aarch64 / linux-armv7l |

**兼容策略（0.1.10 已实现，0.1.11 固化入文档）**：
- 发布侧：manifest `ALIAS` 为新键补两代旧别名（`tools/scripts/ci/release/publish-release.sh`）。
- 消费者侧：`scripts/install.sh`、`sdk/tui/scripts/airymaxrt`、`scripts/install.ps1` 用 `plat_legacy_name()` 依序反查；包内 `platform-*` marker 由 `plat_markers()` 三代白名单放行（异架构族仍拒绝）。
- 架构族词表：`x86`、`arm`、`riscv`（预留）；位宽词：`64`、`32`。
- RISC-V 族词已入词表与 `ALIAS`，仅缺实际矩阵腿 → 满足 D4“提前设计预留”。

## 2. 阶段 A：发布链全迁 GitHub Actions（D0/D1/D2）

### A1 — 签名私钥迁入 Environments secrets（安全红线）

- **现状**：GPG（agentrt.gpg.secret.asc，fpr `86C37F7C5CDDCC40E7BB3E62E435F7F1CC24FF84`）与 cosign（`~/.airymaxrt-signing/cosign.key`）私钥、ATOMGIT_TOKEN、GPG_PASSPHRASE 均只在本机 `~/.config/airymax-release.env` + `~/.airymaxrt-signing/`。
- **动作**：
  1. 仓库 Settings → Environments 新建 `release`（保护规则：仅 `refs/tags/v0.1.*` 可触发；发布 job 需 1 名指定 reviewer Approve）。
  2. `release` environment secrets 注入：`GPG_PRIVATE_KEY`(ascii armored)、`GPG_PASSPHRASE`、`COSIGN_PRIVATE_KEY`、`COSIGN_PASSWORD`、`ATOMGIT_TOKEN`。
  3. 本机私钥标注“已托管 CI”，本地文件降级为紧急 fallback（chmod 600 保留），轮换口径写入本文档附录。
- **验收**：`release` 发布 job 在干净 runner 上可独立完成 GPG + cosign 双签名，且无任何明文私钥出 log/artifact。

### A2 — release.yml 新增 publish job（签名→manifest→上传→latest）

- **现状**：release.yml 只到“上传 GitHub artifact 聚合”为止；签名 + manifest + atomgit release 上传 + `latest/` push 由本机 `publish-release.sh` 手工执行（最后一公里在本地，违反 D0）。
- **动作**：
  1. release.yml 尾部新增 `publish` job：`needs` 8 腿矩阵（§1.1）→ 下载聚合 artifact → 解包校验（sha256）→ 调 CI 化的 publish 脚本 → 上传 atomgit release + push `latest/`。
  2. `publish` job `environment: release`（A1 保护阀，D2）。
  3. tag 事件自动触发；workflow_dispatch 保留作人工补发/重发通道（幂等）。
- **验收**：tag push 后**零人工本机操作**即完成全链发布；publish job 失败时 rerun 幂等，无残留旧附件。

### A3 — publish-release.sh 参数化 CI 化

- **现状**：`tools/scripts/ci/release/publish-release.sh` 从本机环境读取密钥路径与 token（`~/.config/airymax-release.env`），交互式程度不满足 CI。
- **动作**：改为从标准 env 输入（`GPG_PRIVATE_KEY` / `COSIGN_PRIVATE_KEY` / `ATOMGIT_TOKEN` …），不依赖本机路径；支持 `--yank <tag>`（DEL 附件 + manifest 排除，见 C4）与重发自动 DEL+PUT。
- **验收**：同一脚本在本机与 CI 双跑结果一致；无网络密钥路径残留。

### A4 — atomgit → GitHub tag 镜像通道打稳

- **现状**：SSoT 在 atomgit；GH 侧 main/tag 由 sync-mirror workflow 同步，但 v0.1.10 出现过 tag force-move 后**未自动同步**，最终靠手工 REST API DELETE+POST tag 才触发 Release run（run 33939952174 即为手工重建 tag 触发）。
- **动作**：sync-mirror 对 `main` 与 `refs/tags/*` 双触发；atomgit 侧建 webhook → GH `repository_dispatch`（或等效）作为可靠 tag 通道；同步失败告警 + 文档化 fallback SOP（REST DELETE+POST）。
- **验收**：atomgit 打 tag 后 GH Release run 自动出现，连续 3 次无需手工介入。

### A5 — 本机发布职责下线

- **动作**：0.1.11 首个正式版起，本机不再执行 publish-release.sh 正式发布；本机保留 dev/test（受控容器仅作开发基线）与紧急 fallback（A3 脚本 + A1 本地副本）。流程文档同步改写（发布 SOP 指向 GH Actions）。
- **验收**：发布 SOP 无“本机执行”步骤；紧急 fallback 有独立文档路径。

## 3. 阶段 B：平台门禁全覆盖（D3/D4）

### B1 — windows-x86-64 入 tag 自动矩阵（解除 policy 跳过）

- **现状**：release.yml windows leg 带 `if: github.event_name == 'workflow_dispatch'`，tag push 自动跳过；MSVC 门禁硬阻塞 = atoms C11 `stdatomic`（`refcount.h` 的 `_Atomic`，MSVC C2143/C2059 级联）。
- **动作**：B1.1 MSVC stdatomic 两案探针（`/std:c11`+compat 映射 vs atoms 内存域全量换 compat atomic API），按实证定案；B1.2 门禁绿后 windows leg 移除 policy 跳过，纳入 tag 自动矩阵并置 required。
- **验收**：v0.1.11 发布日志出现 windows-x86-64 自动构建成功产物。

### B2 — windows-x86-32 新增 leg

- **问题**：windows 32 位缺失；x64 hosted runner 上需 MSVC x86 交叉工具集（`-A Win32`）+ vcpkg `x86-windows` triplet 依赖供给，当前零验证。
- **动作**：先做**可行性探针**（x86 工具集可用性、vcpkg 32 位依赖、stdatomic 同源问题），探针绿后建 leg 并入矩阵 gate。
- **验收**：windows-x86-32 产物存在且安装器/更新器（install.ps1 已含 windows-x86-32 分支）可用。

### B3 — linux-arm-32 升为 gate

- **现状**：arm-32 在 `build-linux-32` 矩阵内 experimental:true（qemu arm/v7 + ubuntu:20.04），cmake/Kitware APT armhf 供给收敛中，先发后修。
- **动作**：cmake armhf 供给验证通过后置 experimental:false；qemu 超时护栏 + fail-fast:false 已在流程（沿用）；0.1.11 作为发布门禁腿。
- **验收**：arm-32 腿在 tag run 中 required 且绿。

### B4 — RISC-V 撤 tag 矩阵，0.3.x 预留（D4）

- **现状**：riscv64 leg 现为 dispatch-only（0.1.10 起已不阻塞 tag 发布）。
- **动作**：0.1.11 明确 RISC-V 不进 tag 矩阵；保留 `linux-riscv-64` / `linux-riscv-32` 命名键、manifest ALIAS、词表与流程注释（预留位）；0.3.x 方案内补齐 hosted runner 评估与腿。
- **验收**：0.1.11 文档与 release.yml 注释均标注“riscv reserved for 0.3.x”；无半启用残腿。

### B5 — macOS dylib 自包含收口

- **现状**：macOS 包运行时依赖本机 brew 前缀，未接 lib-package.sh 体系（0.2.0 原 B2 遗留）。
- **动作**：lib-package.sh 增 darwin 分支（otool -L 递归收集 + 系统库豁免），build-macos-* 打包接入；包内自包含校验。
- **验收**：macos-arm-64/x86-64 制品在干净 macOS 上 daemon 群可启。

## 4. 阶段 C：发布链可复现与原子性（随迁自原 0.2.0 必要子集）

### C1 — 基础镜像钉版治理
- 浮动 tag 清理：容器腿全部日期钉版镜像或 snapshot 源（0.1.10 i686 bullseye 实证：deb.debian.org 删套件 → held broken）；x86-32 腿已用 `debian:bullseye-20240812-slim`，0.1.11 全容器腿复核。
- 验收：所有容器腿无需 `--allow-downgrades` 亦可幂等安装。

### C2 — 打包入口唯一化
- `pkg_assemble_full`（lib-package.sh）作为所有平台唯一打包入口（linux ELF ldd / mac otool / win DLL 复制）；release.yml 各腿与受控构建台同源调用；`.collected` 标记 + fail-closed。
- 验收：任一平台产物缺失运行时依赖即发布失败。

### C3 — 本机构建台角色重定义（随 D0 变化）
- 原 0.2.0 C3（修复本机受控构建台）因全迁 GH 而降级：本机容器仅作 dev/test 基线，不再是发布 SSoT；文档改为“本机开发容器使用说明”，WSL2 overlayfs/registry 问题不再阻塞发布。

### C4 — yank / 重发原子化
- `publish-release.sh --yank <tag>`（DEL 附件 + 标记 yanked + manifest 排除）；同 tag 重发自动先 DEL 再 PUT（atomgit 附件无覆盖语义，实测）。
- 验收：yank 后更新器立即无法选中该版本；重发无残留旧附件。

### C5 — 安装/更新/运行 e2e 回归并入发布门禁
- 三 shell（bash/zsh/fish）安装、binary 模式启动、`airymaxrt update` 走真实 manifest 验签链、卸载清理；`latest/manifest.*.json` 与安装器快照一致性入发布预检。
- 验收：发布 job 内一键跑通，任何版本落点均有 manifest 凭据。

## 5. 阶段 D：CI 持续改进（充分利用 GitHub 流水线）

- **D1 workflow 收敛**：平台构建逻辑抽共享脚本/复合 action（build-test 与 release 复用，消除 0.1.10 多次“release 独有缺陷晚暴露”）；门禁依赖图显式化。
- **D2 flaky 治理成文**：门禁单测自动重试一次；时间敏感断言上限 ≥10× 抖动余量；近 10 轮无“首轮失败 rerun 通过”假红。
- **D3 排障通道**：失败日志全量 artifact 化，issue 仅摘要（沿用 ci-debug 机制）。
- **D4 清理**：删除 probe/实验 workflow 与一切无用途旧 job 引用（随 leg 增删巡检）。

## 7. 里程碑与施工序

```
M0  基座准备     Environments(secrets+保护规则) → publish-release.sh CI 化(A3)
               → sync-mirror 双触发(A4) → 本机角色下线文档(A5)
M1  平台矩阵     B1.1 MSVC stdatomic 探针 → B1.2 windows-x86-64 解除跳过
               → B2 windows-x86-32 探针+leg → B3 arm-32 升 gate
               → B5 macos dylib 自包含 → B4 RISC-V 预留注释
M2  发布全链     A2 publish job 上线（签名→manifest→上传→latest/）
               → C1 钉版复核 → C2 打包入口唯一化 → C4 yank/重发 → C5 e2e 门禁
M3  出口验证     tag 自动全链试发布（0.1.11-rc1）→ 8 腿全绿 → 正式 0.1.11
               → 三平台(linux/windows/macOS) 32/64 全覆盖产物核验
```

**施工纪律**（沿用 0.1.9/0.2.0）：每模块一 commit；bug fix 落款 `Decheng Li <lidecheng@spharx.cn>`、feature/规划落款 `Liren Wang <wangliren@spharx.cn>`；CI 改动 bash -n / YAML 校验先行（容器脚本注意外层 `bash -c` 单引号约束）；门禁即验收。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 私钥入 CI 泄露 | Environments 保护 + 仅 tag 分支可触发 + reviewer 审批；日志/artifact 明文扫描门禁 |
| windows-x86-32 工具链不可行 | 先探针（MSVC x86 工具集 + vcpkg x86-windows triplet），不预写 leg |
| atomgit→GH tag 同步仍不稳 | sync-mirror 双触发 + webhook/repository_dispatch；SOP fallback 文档化，连续 3 次自动验证为出口 |
| publish job 半程失败残留附件 | A3/C4 幂等语义 + rerun 自动 DEL+PUT；上传前 dist 校验 fail-closed |
| qemu 32 位腿超时占 runner | 超时护栏 + fail-fast:false（沿用）；arm-32 升 gate 前须供给验证 |
| 8 腿矩阵放大发布失败面 | M3 先 rc1 试发布，全绿后才正式 tag |
