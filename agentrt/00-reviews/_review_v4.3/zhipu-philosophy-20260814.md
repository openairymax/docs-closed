## 摘要

智谱工程思想的核心命题是 **「大模型能不能替人干活」**，围绕 phone use / compute use / web use 三个场景同时布局 GUI 智能体。其方法论中最值得借鉴的是 AutoGLM 论文的 **「中间界面（Intermediate Interface）」**——规划与落地显式解耦、各自独立优化；其次是「原生融合优于模块拼装」的架构哲学与「影子上线 + 渐进式部署」的工程可信度建设。

对 agentrt 的借鉴意义：智谱是三家厂商中 **agent 交互范式与产品工程粒度最具参考价值的一家**——「提交即异步、关键节点人工确认」的任务委托交互、按任务复杂度分配思考预算的混合推理、可验证任务驱动的课程式自进化，可直接塑造 agentrt 任务大厅 + CLI 的交互模型与 sched_d 的思考预算调度。

## 一、Agent / 智能体产品设计思想

### 1.1 从「回答者」到「行动者」：GUI 智能体三件套

智谱围绕 phone use（AutoGLM）/ compute use（GLM-PC）/ web use（GLM-Web）同时布局：

- **「云手机/云电脑」云端原生执行范式（AutoGLM 2.0）**：云端为每个用户分配独立虚拟设备、7×24 异步并行执行，AI 干活与用户使用物理设备物理解耦，用户只在支付、发布等关键节点回来「确认」。配套交互是**任务列表 + 进度查看 + 关键节点人工确认**；
- **GLM-PC 的 CUA 技术路线**：不做 API 适配，而是「感知-推理-行动」三阶循环（屏幕截图→思维链推理生成操作序列→虚拟键鼠执行），通过视觉反馈自检操作失误并自动修正（错误容错）；
- **「任务委托式」交互（LUI）**：人机交互从 GUI 进化为 LUI，用户只需说清目标、能力与约束，智能体完成「设定目标即交付成果」。

> 借鉴：任务大厅的交互范式——**CLI 提交任务后异步执行，任务列表实时可见，仅在关键节点（支付/发布/破坏性操作）阻塞等待用户确认**，天然对应 GRAD 的审批/确认原语。

### 1.2 中间界面设计：规划与落地解耦（AutoGLM 论文核心洞察）

智谱在 Agent 工程上最值得学的一条方法论。核心发现：**现有大模型「规划强、落地弱」**——多数错误来自落地（grounding）阶段的元素识别错误，而非规划阶段。因此设计一个**中间界面（intermediate interface）**把两者显式分离：

- 规划（planning）追求**灵活性**与错误恢复能力；
- 落地（grounding）追求**动作准确性**；
- 二者分离后可各自独立优化、独立迭代。

> 借鉴：与 agentrt 蓝图调度与执行解耦同构——**think_d 只做规划（输出蓝图，允许失败重规划），执行 daemon 只做落地（GCCP 动作级精确性）**；为「蓝图失败率」与「动作成功率」建立独立评测指标，各自优化。这是整套调度的根基。

### 1.3 自进化在线课程强化学习（Self-Evolving Online Curriculum RL）

针对智能体训练「决策数据稀缺 + 错误恢复能力无法离线习得」两大难题：

- **课程学习**：任务难度从单步 → 几步 → 50+ 步长程任务渐进式提升；
- **自进化**：每一阶段从未成功的尝试中自动生成新任务，构成在线自进化闭环；
- **稳定性控制**：KL 散度约束策略更新 + 置信度过滤的经验回放，防止过拟合旧知识。

效果：Llama-3.1-8B 在 WebArena-Lite 成功率 4.8%→42.4%；AutoGLM 真实中文 App 人评成功率 89.7%。

> 借鉴：**任务大厅引入「难度分级与课程调度」**——sched_d 对新手 Agent 分配简单任务、对成熟 Agent 分配长程任务；失败任务自动回流生成「复盘任务」，与 L4 模式层联动。

### 1.4 「沉思版」：任务链反思 + 动态策略调整 + 过程记忆

AutoGLM 沉思版把 Agent 从「能执行」推向「能生存」：

- 50+ 步复杂流程，中途失败会**反思**：判断问题类型（网络/点错按钮）→ 回退或换替代方案 → 重试或走新路径；
- 配套**过程日志/Memory**：记录当前在第几步、哪些按钮点过、哪条路径失败过、哪步最耗时，避免死循环和重复犯错。

> 借鉴：**sched_d 为每个任务维护「过程状态卷」（L1 子层）**——任务进度、失败路径、重试计数；CLI 提供 `airy task show <id>` 查看执行轨迹，作为反思与断点恢复的数据源。这是**执行过程记忆**而非语义记忆，与 Kimi 轨迹沉淀、DeepSeek 拒绝采样沉淀三方同构。

### 1.5 ComputerRL：API-GUI 混合范式与规模化 RL 基础设施

- **API-GUI 范式**：统一「程序化 API 调用」与「直接 GUI 交互」两条路径——能走 API 就走 API（步骤可减少至 1/3），否则退回 GUI 操作，兼顾效率与泛化；
- **分布式 RL 基础设施**：编排数千个并行虚拟桌面环境做大规模在线 RL；
- **Entropulse 策略**：RL 与 SFT 交替进行，缓解长程训练的熵坍缩。

> 借鉴：**GCCP 可设计「双通道」**——对已适配的 daemon/工具走强类型协议（快、准、步骤少），对未适配的外部系统走通用交互通道（泛化兜底）；网关 gateway 做通道路由与降级。

## 二、架构与系统工程

### 2.1 「原生融合」而非「应用层拼接」

张鹏核心论点：「分而治之」必然走向「分久必合」——**在模型层面原生融合，而非在应用层用编排框架拼装**。具体工程手段：

- 预训练阶段联合注入多源异构数据，MoE 中设计「共享专家 + 专用专家」协同机制；
- 后训练采用「训练 3 个专项专家模型（推理/智能体/通用）→ 从专家模型蒸馏数据 → 一次全局 SFT 融合 → 再统一 RL」。

> 借鉴：daemon 间协同避免「应用层拼接」——**记忆 daemon 沉淀的结构（L3）应作为 think_d 推理的输入事实而非事后拼装**；17 个 daemon 的能力边界要在运行时统一注册（gateway 能力发现），而不是各自为政。

### 2.2 混合推理模式：按任务复杂度分配思考算力

GLM-4.5 起确立双模式：思考模式（复杂推理与工具使用，输出内部推理链）vs 非思考模式（即时响应，速度约 3 倍）。到 GLM-4.7 演进为三种：

- **交错思考**（Interleaved Thinking）：每个工具调用/代码动作前都先思考；
- **持久思考**（Preserved Thinking）：多轮对话间保留思考历史，保证长流程逻辑一致；
- **轮级思考**（Turn-level Thinking）：按轮控制思考预算。

GLM-5.2 再演进为 High/Max 双档 reasoning_effort。

> 借鉴：agentrt「双思考」扩展为**思考预算调度策略**——sched_d 按任务类型分配思考深度（简单任务非思考、工具链任务交错思考、长程任务轮级思考），思考预算作为调度参数而非模型参数。与 DeepSeek 三档 Think、Kimi reflex/thinking 三方共识。

### 2.3 模型服务分层：开放平台的「能力商品化」

BigModel 开放平台把 Agent 所需工程能力做成**可独立开关的平台服务**：

- 深度思考（thinking on/off）→ 流式输出 → Function Calling → 上下文缓存（KV 缓存复用）→ 结构化输出 → MCP；
- API 完全 OpenAI 兼容；**API Key 作用域（Scope）**：chat / tools / search / file 分级授权，最小化泄露面。

> 借鉴：**gateway 对 LLM 上游能力做统一抽象与开关化**——深度思考、工具、缓存、结构化输出作为可插拔能力项；AIRY_HOME 下按项目/任务级做权限 Scope 分级（对应智谱 API Key 作用域思想）。

### 2.4 长上下文工程是 Agent 的「记忆底座」而非外部记忆系统

智谱解决「Agent 记不住事」的路线是**系统性提升上下文工程**，而非外挂记忆库：中训练 100B 长上下文（best-fit packing 避免截断推理链）；GLM-5.2 达 1M 无损上下文（配套 KV8 量化、HiSparse 稀疏注意力把长上下文算力降 2.9 倍）；平台层提供上下文缓存。

> 对 agentrt 的意义：智谱路线反衬出 agentrt「四层记忆」的差异化价值——**智谱靠模型层大上下文硬扛，agentrt 可在系统层做结构化沉淀**；但「持久思考/过程日志」思想值得融入 L1/L2 层——think_d 的推理过程按轮落盘，L2 特征层做压缩去重，形成「大上下文兜底 + 结构化沉淀升级」的两级记忆策略。

## 三、记忆与个性化

智谱公开资料中没有「四层记忆系统」式的显式架构，其记忆设计思想分散在三点：

1. **用「持久思考 + 大上下文」替代外部记忆**（GLM-4.7 / GLM-5.1 长程任务：单次任务独立工作 8 小时）——**上下文/过程状态的「连续性」是记忆的第一性需求，外部记忆库只是兜底**；
2. **Agent 过程记忆（运行态日志）**：记录任务进度、已点按钮、失败路径、耗时操作——**执行过程记忆而非语义记忆**；
3. **个性化 = 上下文缓存 + 用户偏好注入**：长上下文记忆 + 可配置智能体（知识库上传 + 角色设定 + 工具权限），非专门用户画像系统。

> agentrt 启示：过程状态可持久化、思考历史可落盘，是「大上下文兜底 + 结构化沉淀升级」两级策略的核心，也是相对纯大窗口路线的差异化护城河。

## 四、工程实践方法论

| 方法论 | 要点 | agentrt 借鉴 |
|--------|------|-------------|
| 真实场景评测 | ARC 基准框架（Agentic/Reasoning/Coding 三轴 + 12 项基准）；CC-Bench/ZClawBench 真实平台基准；glm-simple-evals 可复现；真实 query 人工标注 | 建立自己的「ARC 式」评测矩阵：任务完成率、思考效率、工具调用成功率、记忆命中率，随版本发布基准集与复现工具 |
| 部署优化 | 参数效率优先（总参数是藏书、激活参数是翻开页数）；MTP 推测解码、FP8、Ring Attention；Day-0 国产算力适配 | sched_d 资源调度引入「激活成本」概念——一个任务实际消耗的 daemon/上下文量才是成本 |
| 安全对齐 | 双层安全对齐（通用过滤器 + 领域策略）；SLiME 降幻觉；**产品层人工护栏**（支付/发布关键节点强制确认）；渐进式部署哲学 | 破坏性动作强制人工确认（GRAD 审批原语）；agentrt 的 daemon 升级与任务执行内置护栏 |
| 灰度发布 | 1-2 周功能迭代；**「影子上线」（shadow launch）**：匿名身份提前 2-3 周上线，无文档压测收集真实反馈后再官宣 | 新 daemon/蓝图模板「影子上线」：先在真实任务流旁路记录行为对比（不实际生效），达标后再接管；用户可随时「接管/旁观」 |
| 聚焦策略 | CodeGeeX 战略收缩：一个产品线只做一件事，Agent 编排能力集中到统一框架 | 17 个 daemon 明确「一个 daemon 一个职责面」，新能力优先以插件/GCCP 工具形式加入，控制运行时复杂度 |

## 五、最核心可借鉴的 8 条工程思想

1. **规划与落地显式解耦（中间界面思想）**：规划求灵活可恢复、落地求精确，独立评测独立迭代 → think_d（规划）与执行 daemon（落地）分层，是整套调度的根基。
2. **「原生融合」优于「模块拼装」**：能力在一个统一运行时内深度协同（共享事实、统一表征）→ daemon 协同围绕共享记忆卷状态设计，gateway 统一能力注册。
3. **按任务复杂度分配思考预算（混合推理 → 交错/轮级/档位）**：把「思考深度」变成可调度资源参数 → 双思考扩展为 sched_d 可调度的预算策略。
4. **可验证任务驱动 + 课程式自进化训练**：用真实可验证任务做强化学习，难度渐进、从失败自生成新任务、KL/置信度稳定策略 → 任务大厅难度分级调度与失败任务回流复盘。
5. **云端原生异步执行 + 关键节点人机确认的交互范式**：AI 7×24 独立干活、用户只把控关键决策 → 任务大厅 + CLI 的「提交即异步、关键点确认」交互模型。
6. **「大上下文兜底 + 结构化沉淀升级」的记忆两级策略**：过程状态可持久化、思考历史可落盘，记忆命中率作为核心评测指标 → 相对纯大窗口路线的差异化护城河。
7. **真实场景评测体系先行**：为 Agent 定义能力轴并配套真实平台基准与可复现工具 → 调度/思考/工具/记忆基准矩阵随版本发布。
8. **工程可信度建设：灰度「影子上线」+ 渐进式部署 + 关键动作护栏**：新能力先旁路观察再接管、破坏性动作强制人工确认 → daemon 升级与任务执行内置同等护栏。
