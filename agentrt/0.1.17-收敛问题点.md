## 3. 本轮审查登记项（一手取证，逐条可核）

### 3.1 执行面并发与取消（R1）

**R1-a：有界 worker 池 + 单点 deadline —— 已核销**

`daemons f5ecf23 airy/toold: run tool execution on a bounded worker pool`：

- 新增 `tool_d/src/executor_pool.c`（377 行）+ `.h`（77 行）+ 测试 301 行；
- 固定 worker 池（默认 2，上限 8）+ 有界队列 64 提供背压；
- 提交方可携带等待预算，超时返回 `AIRY_ERR_CANCELED` 且任务转 detached 后台完成；
- 销毁先拒新任务再 drain 在途，无任务悬空；
- 伴生并发收口：审批主体参数直传（不再改写共享 `config.agent_id`）、
  审批与桥接计数器改 C11 原子量、限流窗口三步收进专用小临界区；
- TSan 下 executor / executor_pool / service 三目标 0 WARNING；ctest 208/208。

**本轮根因收口（本轮核销理由）**：p9 的池解决了「隔离」未解决「取消真伪」——
deadline 存在双口径（池按 `max(meta, default)` 等待，执行面外部 execvp 路径只取默认值），
导致 per-tool 预算被忽略、被判超时的进程仍在跑、`max_workers` 配置面为死字段。收口为单点：

- `executor_budget_ms(exec, meta)` 为**唯一 deadline 所有者**，内置 / 外部 execvp / 池等待三路径同源；
  外部路径经 `airy_sandbox_invoke` → `sys_tool_execute` → `airy_process_run_capture`，进程到期即 SIGKILL；
- `executor_pool.c` 等待预算收敛为 `executor_budget_ms(...) + WAIT_SLACK_MS (+ 交互审批上限)`，
  进程期限与等待期限 lockstep，detach 降格为「工具不配合预算」的兜底；
- worker 数接线：env `AIRY_TOOL_EXEC_WORKERS` > `executor.max_workers` > 默认 2；
- 缺口 ①（tool_d cancel RPC）裁决：真终止由进程级 deadline 承担，本版不扩 IPC 通路。

**验收证据**：新增 `test_pool_per_tool_budget`（meta=1s、executor 默认 30s → 实测 1022ms 内真终止）；
定向 ctest 2/2 Passed；全量回归 **216/216（100%）**，Total 139.13s，退出码 0。

**处置**：0.1.17 该条目**核销**（不再列为待验收项）；tool_d cancel RPC 登记为后续版本项。

**R1-b：连续失败快速熔断 —— 已核销**

取证：`daemons` 全域 `git grep TOOL_LOOP_CONSECUTIVE_FAILURES` 零命中；
`common/src/svc/svc_monitor.c` 的 `consecutive_failures` 是**服务健康度降级**语义，
与"单次会话内工具连败熔断"不同层，不可复用。

根因：LLM 工具循环在工具持续失败时仍会逐轮重试至预算耗尽，用户看到的是
"卡住"而非"明确失败"。修法：会话内连败计数达 K=3 即以合成错误终止本轮，
并回报可判读原因（与 R2-C 语义失败判定共用同一出口）。

**落地与核销**（`ecosystem/agents 1d900f5` + 本轮补齐契约面）：

- 计数：`_result_is_error()` 判错误载荷（`{"error": ...}` JSON）→ 连败 +1，成功清零；
  未注册工具 / 畸形参数 / 工具抛异常三类结果同样计入（`_invoke_tool` 统一成错误 JSON）；
  纯文本结果不判失败（不误杀）。
- 阈值：`DEFAULT_TOOL_FAIL_LIMIT = 3`，env `AIRY_TOOL_FAIL_LIMIT` 可调（非法值 / <1 回退默认）。
- 回报：`error_code = TOOL_LOOP_CONSECUTIVE_FAILURES`（与 `TOOL_LOOP_DETECTED` /
  `TOOL_LOOP_OVERFLOW` 同族，上一轮的 `TOOL_CONSECUTIVE_FAILURES` 命名已对齐方案契约），
  错误信息汇总最后 K 个原因（`_error_brief()` 折叠空白 + 截断）。
- 与同指纹检测互补：指纹管"同参同果原地打转"，连败计数管"次次失败但参数各异"；
  截断类仍走 `TOOL_ARGS_TRUNCATED` 即时 fast-fail。

**验收证据**：`TestLLMAgentConsecutiveFailures` 4 用例（3 连败熔断 + `llm.calls == 3`
+ 错误含 3 条原因摘要；成功清零；纯文本不计；env 覆盖与回退）。
单文件 8 passed；全量 **187 passed, 1 skipped**。

**R1-c：角色词汇表 C 侧 SSoT —— 已落地（0.1.17 施工，本轮闭合）**

根因：CLI（C）与编排侧（Python）各自持有角色名/阶段名词汇表，任一侧变更即语义漂移，
表现为"节点被判定为成功但产物为空"。修法：以 C 侧为唯一权威（Unify Design SSoT），
编排侧经 A-IPC 取值，禁止并行维护。

**闭合证据**：

- 权威实现唯一：`commons/utils/cognition/agent_vocab.{h,c}`（11 规范角色 + 13 别名
