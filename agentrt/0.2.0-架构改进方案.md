# agentrt 0.2.0 架构改进方案

> 状态：规划草案（2026-09-05 立项）
> 目标版本：**0.2.0**
> 范围：0.1.9 全部遗留项 + 0.1.10 发布链实测暴露的工程债 + 三平台矩阵补全
> 编写纪律：每项必须附一手证据路径（真实问题）；禁止为凑规划而发明任务

---

## 0. 背景与范围

0.1.9（架构改进）M0–M5 已全部闭环并有代码取证（见 `0.1.9-架构改进方案.md` §10 审计轨迹）。
但 0.1.9 文档明确登记的 **0.2.x 遗留项**与 0.1.10 发布实测暴露的**工程链债**尚未处理。
本方案把两类问题一并收口，目标形态：

1. 架构层：消灭 0.1.9 遗留的“登记不施工”项中已具备施工条件的部分，逐条闭环或明确裁决。
2. 平台层：**Linux / macOS / Windows 三平台二进制全部作为发布矩阵常规项**（Windows 以 MSVC 门禁绿为入闸条件）。
3. 发布链：构建、集成、打包、签名、上传、安装、更新各环节**可复现、fail-closed、体验一致**。
4. CI 层：充分利用 GitHub 流水线能力（原生 Linux/macOS/Windows runner + qemu 容器矩阵），无死角。

## 1. 阶段 A：0.1.9 架构遗留收口（M0/M3 登记项）

### A1 — L9：hall 事件流“三份 writer 格式复制” SSoT 收敛

- **问题**：事件流文件写端三份实现——`atoms` 侧 hall_store、`gateway/src/gateway/gateway_hall_store.c`（641 行）、`daemons/common/src/util/hall_writer.c`（242 行）。三者“byte-for-byte aligned”仅靠头注释约定，文件命名/header 字段/prev_file 决策链各自手写；任一处格式演化即静默撕裂事件流。
- **证据**：`gateway/src/gateway/gateway_hall_store.c`、`daemons/common/src/util/hall_writer.c` 实测存在；0.1.9 文档 §1.3bis L9 已登记。
- **动作**：事件流编码/解码抽 **commons 单一权威模块**（头 + 实现 + 格式单测 + 黄金字节向量），三方链接复用；任一格式变更只改一处。golden-file 向量防回归。
- **验收**：`grep` 三处 writer 不再各自实现 header 布局；golden 向量测试覆盖（ts_utc,seq）稳定序与 file_id 语义；读路径 `hall.stream/replay/watch` 与写端同构（沿用 0.1.9 W4 `gw_hall_event_flatten` 统一）。

### A2 — L10①：`AIRY_API` 双权威源（同 guard 不同内容）

- **问题**：`atoms/corekern/include/export.h` 与 `commons/platform/include/export.h` **共用 include guard `AIRY_RT_EXPORT_H`** 且内容近似但为两份拷贝；同 TU 先后包含时后一份被静默跳过（Windows MSVC 移植已出现 C2375 同类风险，见 0.1.9 第 25 轮 atoms oom_handler 修复）。
- **证据**：两份 `export.h` 均 `#ifndef AIRY_RT_EXPORT_H / #define AIRY_RT_EXPORT_H`（实测命中）。
- **动作**：IRON-6 全域推广——`AIRY_API`/`AIRY_PUBLIC` 宏归 commons 平台层单一权威，atoms 改为 include 或独立命名宏（`AIRY_ATOMS_API`），guard 域全局唯一（quality-gate header-duplication R2 覆盖）。
- **验收**：`AIRY_RT_EXPORT_H` 全树仅一处定义；header-duplication-check GATE=0；windows/mac/linux 三平台全绿。

### A3 — L10②：gateway 同 guard 双头

- **问题**：`gateway/src/gateway/gateway.h` 与 `gateway_internal.h` 共用 `AIRY_RT_GATEWAY_INTERNAL_H`；同 TU 双包含时后者静默跳过（L2 同族潜伏缺陷）。
- **证据**：两文件第 5-6 行 guard 相同（实测命中）。
- **动作**：改独立 guard（一行级，可后验）。
- **验收**：guard 域唯一门禁对 gateway 库放行。

### A4 — roadmap 物理迁出 re-schedule

- **问题**：0.1.9 终裁 roadmap 留内核 + ABI 收口；物理迁出 `sched_d` 被 re-schedule 至“work_hall 回灌 ops 注入化”就绪批次。
- **动作**：0.2.0 评估 work_hall ops 注入面（机制服务缝）设计；就绪后 roadmap/ 整目录迁 sched_d 作为批次收尾。若评估结论为收益仍倒挂，登记为“有意留内核”并更新文档口径。
- **验收**：非 sched_d 生产进程零 roadmap 符号（link-whitelist/归档抽取双重取证）。

### A5 — 影子评估 / 策略即工件（0.1.9 登记不施工项）

- **裁决复核**：真实消费者仍缺位（无策略作者工作流/无 policy 包市场流水线）。0.2.0 维持“登记不施工”，但补一条**触发条件**：当出现首个真实消费者（策略编排 CLI/UI 或市场分发用例）时启动 0.1.9 §3.3 工具链设计与实现。
- **验收**：无消费者则零代码改动（防桩纪律）；消费者出现时按 A5 触发链立项。

### A6 — M2-S5 遗留：yaml 基线准入全集单点导入 PDP 运行集

- **问题**：12 非 PDP daemon 收权后，离线兜底 ACL（permission_rules.yaml）仍随各进程 `daemon_security` 装载；规则面 SSoT 未收口——PDP 运行集与 yaml 基线是两套来源。
- **动作**：cupolas_d 启动/`policy.import-baseline` 将 yaml 基线全集单点导入 PDP 运行集；pep 进程 ACL 表仅作 PDP 不可达时最小兜底（量级 ≤ 全量引擎）。
- **验收**：`check_permission` 空运行集时行为 = yaml 基线；激活动态策略后 deny-wins 覆盖基线；rollback 还原基线。

### A7 — daemon 最小档启动画像（0.1.9 §5 自记未闭环）

- **问题**：0.1.9 §5 “启动画像”仅文档化，bootstrap 无 minimal 子集开关实现。
- **动作**：`agentrt-bootstrap.sh` 增 profile 参数（`--profile minimal|full`，minimal = gateway/agent/llm/tool/think 五进程），install 联动；manifest/`bin/*_d` 推导口径不变。
- **验收**：minimal 档 5 进程拉起、健康回归；full 档 15 进程行为不变。

## 2. 阶段 B：平台矩阵补全（Linux / macOS / Windows 三平台二进制）

### B1 — Windows MSVC 全量移植（0.1.9→0.1.10 未收口项）

- **问题**：Windows 门禁逐层收敛后唯一硬阻塞 = `atoms` 原生 C11 `stdatomic` 用法（`refcount.c/refcount.h` 等 `_Atomic`/`<stdatomic.h>`），MSVC 下 C2143/C2059/C2054 级联。其余（cJSON 全局宏、clock_gettime/setenv shim、mcp_client WIN32 门控、oom_handler 声明、svc_common 链接）均已闭环。
- **证据**：#45–#54 Windows build annotations；`refcount.h` 含 `uint32_t _Atomic refcount`。
- **动作**：二选一（先做可编译性探针再定）：
  1. MSVC 启用 `/std:c11` + 与 compat `_Atomic→volatile` 宏映射的互斥校验；
  2. atoms 内存域原子全量改用 compat atomic API（`atomic_*` 封装层）。
  方案 1 侵入最小、方案 2 与 0.2.0 A2（AIRY_API 收敛）同属“atoms 归位 commons 抽象”方向。
- **验收**：windows-build 移除 `continue-on-error` 恢复 required；Windows 纳入 release 矩阵出 `windows-x64` 包；三平台二进制齐。

### B2 — macOS 制品发布矩阵化（0.1.10 已搭骨架，0.2.0 固化为常规项）

- **现状**：release.yml 已含 `build-macos`（arm64）与 `build-macos-x64`（macos-13）双 leg（agentrt db089b223 起）。
- **遗留**：macOS 包运行时自包含（brew dylib 收敛）未接 `lib-package.sh` 体系；`.dylib` 收集策略需 mac 等价物（otool 依赖收集 + 包内 `lib/` + 校验），避免包依赖本机 brew 前缀。
- **动作**：`lib-package.sh` 增加 darwin 分支（otool -L 递归 + 系统库豁免），`build-macos*` 打包步骤接入；包内校验 `pkg_verify_deps` 的 dylib 版。
- **验收**：macos-arm64/x64 制品在干净 macOS（无 brew）上 daemon 群可启（冒烟）。

### B3 — Linux 受控构建台 SSoT 与发布口径

- **问题**：本机 WSL2 docker overlayfs 挂载故障 → 容器（glibc 2.31）基线不可用；`AIRY_NATIVE=1` 宿主原生出包为 glibc 2.39，与发布基线漂移（0.1.10 本地 x64 包仅验证用）。
- **动作**：修复受控构建台容器模式（见 C3 镜像固化）；Linux 发布制品一律由 GitHub ubuntu:20.04 容器 leg 或等价受控容器产出；本地构建产物仅作 smoke/预检，不作为发布 SSoT。
- **验收**：linux-x64 制品 `ldd` 所需最低 GLIBC ≤ 2.31（`objdump --version` 校验）。

### B4 — riscv64 / arm32 制品补齐与 hosted runner 规划

- **问题**：riscv64/armv7l 现为 workflow_dispatch-only（qemu 6h 超时风险），发布矩阵缺位。
- **动作**：评估云托管 riscv64 runner（自托管/竞品 ARM runner）接入 build-test + release；armv7l 收敛 cmake 供给后移 `experimental:false`。
- **验收**：riscv64/arm32 以常规项进入某发布通道（0.2.x 内）。

## 3. 阶段 C：发布链可复现性（0.1.10 实测教训）

### C1 — 基础镜像“浮动 tag”治理（新发现，0.1.10 实证）

- **问题**：`debian:bullseye` 浮动 tag 在 LTS 期持续重建；EOL 后 deb.debian.org 删套件、archive.debian.org 无 security 套件、归档 main 仅到最终 point release → base 含 LTS 版本包时 apt 报 “held broken packages”（0.1.10 Release 第 4 次 i686 实证）。当前缓解：archive main-only + `--allow-downgrades`（agentrt 3ed01adf4/4fc714136）。
- **动作**：容器 leg 全部改用**日期钉版镜像**（如 `debian:bullseye-<date>`）或 snapshot.debian.org 固定时间戳源；禁止浮动 tag 进 CI/发布。
- **验收**：i686 leg 无需 `--allow-downgrades` 也可幂等安装（钉版镜像验证后移 flag 或保留为双保险）。

### C2 — 发布产物“运行时自包含”一致性

- **问题**：v0.1.9 linux 包运行时库缺失（修复在 lib-package.sh 本地链，release.yml 曾未调用）；macOS dylib 未自包含（B2）。
- **动作**：`pkg_assemble_full` 作为**所有平台打包唯一入口**（linux ELF ldd / mac otool / win 复制 DLL），release.yml 各 leg 与受控构建台同源调用；包内 `.collected` 标记 + fail-closed 校验。
- **验收**：所有平台产物经同一打包函数；发布预检（publish-release.sh）在解包后对可执行体做动态依赖自包含断言。

### C3 — 受控构建台容器模式修复（本机）

- **问题**：WSL2 docker overlayfs 对 `tui-cfg` 挂载报 read-only（0.1.10 记录）；docker hub registry 本机不可达（IPv6 超时）。
- **动作**：构建台脚本挂载点收敛（避免把 cfg 目录 bind 进容器源码路径）；配置 docker daemon IPv4 优先 / 镜像代理。
- **验收**：`bash build.sh x86_64`（容器 glibc 2.31 模式）EXIT=0 且产物基线核验通过。

### C4 — 发布/回滚操作原子性（atomgit 附件语义）

- **问题**：atomgit release 附件**无覆盖语义**——同 tag 重发需先 DELETE 再 PUT；v0.1.9 回收（yank）与 0.1.10 重发均踩此约束（0.1.9 会话已记录）。
- **动作**：`publish-release.sh` 增 `--yank <tag>` 子命令：DEL 附件 + 标记 yanked + manifest 排除；重发同 tag 自动先 DEL 再 PUT（AIRY_FORCE_UPLOAD 语义显式化）。
- **验收**：yank 后更新器立即无法选中该版本；同 tag 重发无残留旧附件。

### C5 — 安装 / 运行 / 更新体验端到端回归

- **问题**：跨 25 轮用户反馈集中在安装器 PATH 污染（H3）、TUI “Service error”（H4/H5）、更新误报（1.6c 调查报告，需用户命令输出定位）等体验面。
- **动作**：建 **e2e 体验回归套件**（bash/zsh/fish 三 shell 安装、binary 模式启动、`airymaxrt update` 走真实 manifest 验签链、卸载清理），并入 release 门禁；`latest/manifest.*.json` + 安装器快照一致性纳入发布预检。
- **验收**：三 shell 安装/升级/卸载零残留；更新器在无新版本时输出可读 “已是最新”；任何版本落点均有 manifest 凭据。

## 4. 阶段 D：CI/CD 持续改进（充分利用 GitHub 流水线）

### D1 — workflow 收敛与职责单一

- **现状**：agentrt 四 workflow（build-test / release / sync-mirror / codegen-check）。0.1.10 多次出现“release 侧独有缺陷（容器脚本/归档源/矩阵）”而 build-test 全绿——两类矩阵长期漂移。
- **动作**：
  1. 平台构建逻辑抽**复合 action/共享脚本**（build-linux/build-macos/build-windows/32bit 复用同一 configure/build/package 脚本，入仓 `.github/actions` 或 tools SSoT）；
  2. sync-mirror 对 tag 与 main 双触发（0.1.10 靠手工 SSH push tag 触发 release，欠自动化——在 atomgit 侧建立 tag → sync 的可靠通道或文档化 SOP）；
  3. 门禁依赖图显式化：release 只依赖自身矩阵 leg，build-test 门禁独立，避免 release 缺陷晚暴露。
- **验收**：新平台改动在 build-test 与 release 间零复制粘贴；tag 触发链路无需手工 SSH。

### D2 — flaky 治理成文

- **教训（0.1.10）**：macOS ctest 瞬态失败（corekern_deep / kernel_state 睡眠上限假红）经“上限放宽 + 单次自动 rerun”收敛。flaky 治理策略需成文：门禁单测自动重试一次（rerun 仍败才红）、定时/睡眠断言上限统一 ≥ 10× 且注明 CI 抖动余量、时间敏感测试避免精确计数。
- **验收**：近 10 轮三平台门禁无“首轮失败 rerun 通过”的假红记录。

### D3 — 覆盖率阈值按真实基线渐进上调

- **现状**：COVERAGE_THRESHOLD=25（基线 28.61%）。0.2.0 每补一批测试上调一档，门禁始终低于实测基线但高于 25。
- **验收**：覆盖率单调上升且门禁绿。

### D4 — 排障通道收敛

- **现状**：ci-debug issue 机制（每失败步骤独立 issue + 追加 comment）已建。0.2.0 收尾：失败日志全量落 artifact（upload-artifact，不用 admin 即可下载），issue 只保留摘要与定位信息，减少 issue 噪音。
- **验收**：任一失败步骤，摘要 issue + 全量日志 artifact 双通道可达。

### D5 — Windows/macOS 原生 runner 能力利用

- **动作**：macOS 增加矩阵（x64/arm64 均原生 ctest）；Windows 绿后同口径（原生 MSVC + vcpkg）；riscv64 用云托管 runner（B4）。GitHub 原生 runner 全部投入门禁与 release，本机仅保留受控构建台 Linux SSoT。
