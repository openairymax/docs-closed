## 1. 任务清单与施工序（每完成一个小任务回顾本清单）

> 顺序原则（重要 → 依赖）：先验证已开工项（①），再做无外部依赖的流水线收口
> （H3/P3-I5/I-upload 可自主），再推进平台移植主线（G1 为最长线，G2 依赖 G1，
> G3 依赖 G1 基础库层全绿前提），用户侧依赖项（P9 建 PAT）就绪即插入。

1. **① 确认 v0.1.13-rc1 门禁拓扑验证结果**（run 34033510383）：六腿含 arm-32
   全绿 + release 正确等 arm-32 → 关闭 G3-arm32 项。失败则回退 86aea7c77 并
   记录一手证据。
2. **H3 环境脚本化收口**：将 release environment 配置（branch/tag 两型 policy、
   wait_timer）落 setup-release-environment.sh 幂等脚本 + 文档化 P19 tag 回推
   收敛方案（GitHub 不回推 / marker ref），一次 rc 回归验证。
3. **P3-I5 build-test 同源**：build-test 三腿 configure/build/test 段与
   release.yml lf-* 体系漂移面评估 → 可行段同源化，跑 build-test 回归。
4. **I-upload 上传提速评估**：publish-release.sh 当前 3 并发串行 ~80KB/s 聚合；
   评估更高并发上限/分片续传/传输通道替代，先本地实测定界（不承诺），可行则
   rc 实测对比 publish 段墙钟。
5. **G1 Windows 完整产品移植**（主线，最大项）：以基础库层（atoms/commons/
   cupolas/heapstore/protocols/gateway）MSVC 全绿为起点，逐个移植 daemons
   15 服务与 airy_cli（U4 L1-L9 教训照搬：文件作用域声明、NONSTDC 宏体系、
   纯 Win32 API 分支、taskflow 等第三方守卫、链 daemon 库的测试整目标守卫）；
   release.yml windows 腿自 canary 升 gate 的判据 = publish REQUIRED_BIN
   预检通过（zip 内 daemons/CLI/bootstrap 齐）。
6. **G2 MSVC 运行测试**：G1 后 windows-build ctest（#133 SegFault 面）逐个平台
   域修复 → continue-on-error 升硬门禁。
7. **G4 macOS dylib 自包含**：lib-package.sh darwin 分支（otool -L 递归 +
   Apple 系统库豁免白名单）接入 build-macos-arm-64/x86-64；干净 macOS 真机
   daemon 群可启为验收（可与 G1/G2 并行，独立于 Windows 主线）。
8. **G3 Windows x86-32 探针**：G1 基础库层绿后，vcpkg x86-windows triplet +
   MSVC x86 工具集探针 → leg。
9. **H1/C4 yank 原子化 + H2/C5 e2e 门禁**：publish 失败路径幂等重发原子化
   （U10/P10 基础上补 yank 语义）；安装/更新/运行 e2e + 旧版升级抽测接入
   发布前门禁（需要真机/容器洁净环境载体，评估在 rc 阶段 runner 内执行）。
10. **P9 凭据治理**（用户 UI 建 5 PAT 后执行）：按 §0 表逐个 workflow 替换
    secrets（一次一 workflow，rc 验证）→ 轮换已泄露 PAT → 删旧 secret →
    同步检查 atomgit GT_TOKEN/ATOMGIT_TOKEN 暴露面。
