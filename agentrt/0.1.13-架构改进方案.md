## 1. 任务清单与施工序（每完成一个小任务回顾本清单）

> 顺序原则（重要 → 依赖）：先验证已开工项（①），再做无外部依赖的流水线收口
> （H3/P3-I5/I-upload 可自主），再推进平台移植主线（G1 为最长线，G2 依赖 G1，
> G3 依赖 G1 基础库层全绿前提），用户侧依赖项（P9 建 PAT）就绪即插入。

1. **✅ ① 确认 v0.1.13-rc1 门禁拓扑验证结果**（run 34033510383，2026-09-06）：
   六门禁腿含 arm-32 全绿，release 在 needs 含 arm-32 下 success，windows
   编译 canary 复绿；riscv/publish 无验证价值已取消。G3-arm32 项关闭。
   后续 rc 从②继续。
2. **✅ H3 环境脚本化收口**（2026-09-06）：setup-release-environment.sh
   （agentrt 272d1d7e0）实跑验证幂等——`environment PUT -> HTTP 200`、
   `policy exists: main (branch)`、`policy exists: v* (tag)`、终验 exit=0。
   P19 根因更正 + SOP（先双端打 tag / echo run 取消 / force 终态一致）
   已固化 agentrt `.github/README.md`。静态配置 + 文档，无需 rc 回归。
3. **P3-I5 build-test 同源（评估结论，2026-09-06）**：三腿 checkout+子模块已
   由 lf-init-deps 复合 action 收敛（P3 双实现漂移的主要危险面已关）；残余
   差异为 OS 宿主 install/configure/build 与 ctest-auto-retry 逻辑——Linux/
   macOS 两份 ctest retry 脚本已有细微分叉（annotation grep 不同）。同源化
   与 G2（MSVC ctest 平台适配将重写 windows ctest 路径）强耦合，避免两次
   churn → 决策：与 G2 一并实施，此处不单独改 build-test。
4. **I-upload 上传提速（进行中）**：publish-release.sh 当前 3 并发串行 ~80KB/s
   聚合；UPLOAD_PAR 已参数化（默认 3）。上传速度 A/B 探针（upload-speed-probe.sh
   + workflow，run 34039694252）实测 PAR 3/6/8 聚合吞吐定界 → 定默认并发。
5. **G1 Windows 完整产品移植**（主线，最大项）：以基础库层（atoms/commons/
   cupolas/heapstore/protocols/gateway）MSVC 全绿为起点，逐个移植 daemons
   15 服务与 airy_cli（U4 L1-L9 教训照搬：文件作用域声明、NONSTDC 宏体系、
   纯 Win32 API 分支、taskflow 等第三方守卫、链 daemon 库的测试整目标守卫）；
   release.yml windows 腿自 canary 升 gate 的判据 = publish REQUIRED_BIN
   预检通过（zip 内 daemons/CLI/bootstrap 齐）。
   **2026-09-06 移植基线盘点**（一手数据，Windows 侧 CMake 硬关 3 点：
   CMakeLists L543 http2、L862 daemons/CLI 默认 OFF、L675 ws2_32 链接；
   daemons 15 服务 POSIX 头文件引用文件数由高到低）：
   tool_d 16 / agent_d 6 / gateway_d 5 / monit_d 4 / market_d 4 / channel_d 4 /
   llm_d 3 / sched_d 2 / notify_d 2 / mem_d 2 / maths_d 2 / hook_d 2 /
   think_d 1 / cupolas_d 1 / a2a_d 0（common/ 尚不计）——排序与切分窗口据此定。
6. **G2 MSVC 运行测试**：G1 后 windows-build ctest（#133 SegFault 面）逐个平台
   域修复 → continue-on-error 升硬门禁。
7. **G4 macOS dylib 自包含（实施中，2026-09-06）**：lib-package.sh darwin 分支
   方案收敛为独立 SSoT 脚本 bundle-macos-dylibs.sh（otool -L BFS 递归收集非系统
   dylib → lib/，install_name_tool 重写 @executable_path/../lib/，ad-hoc 重签，
   fail-closed 校验；bash 3.2 兼容）→ 已接入 release.yml 双 macos 腿打包前
   （tools 705177b / agentrt a7d2ec74a）；干净 macOS 真机 daemon 群可启为终验
   （先经 rc2 34039712199 双腿构建+打包验证，再真机抽测）。
8. **G3 Windows x86-32 探针**：G1 基础库层绿后，vcpkg x86-windows triplet +
   MSVC x86 工具集探针 → leg。
9. **H1/C4 yank 原子化 + H2/C5 e2e 门禁**：publish 失败路径幂等重发原子化
   （U10/P10 基础上补 yank 语义）；安装/更新/运行 e2e + 旧版升级抽测接入
   发布前门禁（需要真机/容器洁净环境载体，评估在 rc 阶段 runner 内执行）。
10. **P9 凭据治理**（用户 UI 建 5 PAT 后执行）：按 §0 表逐个 workflow 替换
    secrets（一次一 workflow，rc 验证）→ 轮换已泄露 PAT → 删旧 secret →
    同步检查 atomgit GT_TOKEN/ATOMGIT_TOKEN 暴露面。
