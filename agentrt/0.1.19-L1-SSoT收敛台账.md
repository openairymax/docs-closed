## 3. 错误码副本 [已消除]（0.1.19 D 组）

### 缺陷实证（修复前）

`cupolas_ERROR_WOULD_BLOCK` 存在三处互相矛盾的 `#ifndef` 弱守卫定义，
先 include 者获胜，导致跨翻译单元取值不一致：

| 定义点（修复前） | 值 | 后果 |
|---|---|---|
| `cupolas/include/cupolas.h:79` | `AIRY_ERR_STATE_ERROR`(-56) | audit_overflow.c 比较侧取 -56 |
| `cupolas/src/platform/platform_base.h:105` | 硬编码 `-8` | audit_queue.c 返回侧取 -8（与 TIMEOUT 撞号） |
| `cupolas/src/security/cupolas_error.h:321` | `cupolas_ERR_TRY_AGAIN`(-15) | 测试锁定值 |

遮蔽路径：`audit_queue.c` 经 `audit_queue.h→platform.h→platform_base.h` 取 -8；
`audit_overflow.c` 第 4 行先 include `cupolas.h` 取 -56。队列满时
`try_push` 返回 -8 与比较值 -56 永不相等 → 溢出分支死代码 →
`return result` 透传 + `audit_entry_t` 泄漏（LSan: 223B/5 objects）。

### 修复动作

|---|---|

## 6. error_codes.h 弱守卫 [已消除]（0.1.19 E2 组）

### 缺陷实证（修复前）

`commons/utils/error/error_codes.h` 全文约 110 处宏采用 `#ifndef X / #define X` 弱守卫：头外同名影子定义被静默放行——与 §3 D 组 `cupolas_ERROR_WOULD_BLOCK` 三重定义遮蔽缺陷同源的温床（遮蔽方向取决于 TU 内 include 顺序，比较分支可沦为死代码）。另有两处结构性问题：`AIRY_ERR_CYCLE_DETECTED` 无守卫裸别名；两个 POSIX 兼容别名恒不触发。

### 修复动作

| 项 | 处置 |
|---|---|
| 112 个宏块 | 统一改冲突检测式守卫：`#ifdef X` → `#error "X: duplicate SSoT definition"` → `#endif` → `#define X (value)`（fail-closed，禁止改回弱守卫） |
| 守卫策略注释 | 头部注明原理：头卫兵保证本头单次处理，`#ifdef` 命中只可能来自头外影子定义，编译期立即硬失败 |
| 死别名块删除 | `AIRY_ECANCELED→AIRY_ERR_CANCELED`、`AIRY_EINTR→AIRY_ERR_INTERRUPTED`：airy_types.h:46/:72 对 POSIX 码 `#undef` + 负幅值硬重定义（-4/-125），include 链 types.h:34→airy_types.h 使两别名恒不触发——确证死代码后删除（若改造则每 TU 编译失败）；注释留取证锚点 |
| `AIRY_ERR_CYCLE_DETECTED` | 补齐冲突检测式守卫 |

### 修复验证（构建区，源码区零构建）

- native 全量重编（核心头触发依赖 TU 重编）：构建 EXIT=0，**零 `#error` 引爆**（无影子定义幸存），error_codes.h 零警告
- native `ctest`：**241/241**（含 depgraph 8/8，无 include/链接变更）
