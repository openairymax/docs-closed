## 三、修复实施工作

### 3.1 重复逻辑消除修复

#### 3.1.1 通用错误检查模式抽象
**修改文件**：
- `agentos/commons/utils/sync/src/sync_spinlock.c`
- `agentos/commons/utils/sync/src/sync_semaphore.c`

**修改内容**：
- 添加 `#include "../include/check.h"`
- 将重复的 `if (ptr == NULL) { return ERROR; }` 替换为 `CHECK_NULL_RET(ptr, ERROR)`
- 使用现有的 `CHECK_NULL_RET` 宏统一错误检查

**代码示例**：
```c
// 修复前
if (spinlock == NULL) {
    return SYNC_ERROR_INVALID;
}

// 修复后
CHECK_NULL_RET(spinlock, SYNC_ERROR_INVALID);
```

```python
    if not path: return error("empty")           # 空检查
    if len(path) > max: return error("too long") # 长度检查
    for pattern in patterns:                     # 模式检查 (8行)
        if re.search(pattern, path): return error("dangerous")
    try: resolved = realpath(path)               # 路径解析 (4行)
    except: resolved = path
    for prefix in prefixes:                      # 前缀检查 (8行)
        if resolved.startswith(prefix): break
    else: return error("escape")                 # 权限拒绝
```

```python
def validate_path(self, path, allow_create=False):  # 复杂度<8，~15行
    # 构建验证链 (7行)
    chain = ValidationChainBuilder() \
        .add_empty_check() \
        .add_length_check(max_len) \
        .add_pattern_check(patterns) \
        .add_path_resolution_check() \
        .add_prefix_check(prefixes, allowed_paths) \
        .add_existence_check(allow_create) \
```

```c
// 使用统一的检查宏
sync_result_t sync_spinlock_create(sync_spinlock_t* spinlock,

    CHECK_NULL_RET(s, SYNC_ERROR_MEMORY);              // 统一宏
    // ...

// sync_semaphore.c 使用相同的宏
sync_result_t sync_semaphore_create(...) {
    CHECK_NULL_RET(semaphore, SYNC_ERROR_INVALID);     // 统一宏
    // ...
}
```

3. **可读性提升**：`CHECK_NULL_RET`宏明确表达意图
