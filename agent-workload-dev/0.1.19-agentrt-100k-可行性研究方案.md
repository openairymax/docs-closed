## 0. 摘要（TL;DR）

**结论三段式：**

1. **命题 P（就地不迁出）为假。** 在「`agentrt` 树内八模块全部就地计量、且 `|S₀∖S₁| = 0`（不减少任何设计能力）」的前提下，总量 < 100,000 行**不可行**。实测下界约 **190,000 行**，缺口约 **−90,000**，且该缺口无法由塌缩/生成/清扫填补——因为这些通道可减量经实测仅 **≈−34,000**。

2. **命题 P′（边界重定 + 策略数据化 + 深度塌缩）可行。** 若采纳文档**自身既有规划**（`daemons` 用户态服务化迁往 `services/` 子仓，见 [04-microkernel-strategy.md:149-170](file:///home/spharx/spharxworks/airymaxhub/docs/docs-closed/agent-linux-dev/03-microkernel-design-ref/04-microkernel-strategy.md#L149-L170)），则 `agentrt` 树整体可落至 **< 100,000**，且 `|S₀∖S₁| = 0` ——**搬迁非删除**，能力全部保留，仅宿主仓改变。

3. **前提裁定点。** 「< 100k」在文档中**本就是「内核态必需代码」的预算**（[01-sel4-deep-analysis.md:124](file:///home/spharx/spharxworks/airymaxhub/docs/docs-closed/agent-linux-dev/00-reviews/_research_0.2.5/01-sel4-deep-analysis.md#L124)、[:1588](file:///home/spharx/spharxworks/airymaxhub/docs/docs-closed/agent-linux-dev/00-reviews/_research_0.2.5/01-sel4-deep-analysis.md#L1588)「建议 5-10 万行」；[04-microkernel-strategy.md:74,93,241](file:///home/spharx/spharxworks/airymaxhub/docs/docs-closed/agent-linux-dev/03-microkernel-design-ref/04-microkernel-strategy.md#L74) 微内核目标 < 80K LOC），**而非整个发行树的预算**。故「整体」的正确外延 = **机制核整体**（原子件 + 能力格 + 协议网关 + 堆存 + 组织码），服务面/体验面/协议厂商面迁出后不再计入 `agentrt` 树。此即须请用户裁定的边界。

## 2. 工程思想重研

### 2.1 微内核极简原则（seL4 唯一思想来源，ADR-014）

文档锚定（[04-microkernel-strategy.md:91-102](file:///home/spharx/spharxworks/airymaxhub/docs/docs-closed/agent-linux-dev/03-microkernel-design-ref/04-microkernel-strategy.md#L91-L102)）对标：

| 系统 | 代码规模 | 备注 |
|---|---|---|
| seL4 | ~1.44 万行 C | 内核核 |
| Zircon | ~200K LOC | 对照 |
| Minix3 | ~15K LOC | 对照 |
| **AirymaxOS 目标** | **< 80K LOC** | 「微内核越小越好，但 AI 场景需要适度扩展」 |
| Linux | ~3,000 万行 | 宏内核对照 |

**「内核态必需代码」预算 = 5-10 万行**（[01-sel4-deep-analysis.md:124](file:///home/spharx/spharxworks/airymaxhub/docs/docs-closed/agent-linux-dev/00-reviews/_research_0.2.5/01-sel4-deep-analysis.md#L124)、[:1588](file:///home/spharx/spharxworks/airymaxhub/docs/docs-closed/agent-linux-dev/00-reviews/_research_0.2.5/01-sel4-deep-analysis.md#L1588)）——**含 agent 调度原语**。

**⟹ 文档从未主张「整个发行树 < 100k」；文档主张的是「内核态/微内核 < 80K、内核态必需代码 5-10 万行」。** 「< 100k」的正确适用范围 = **机制核**。

### 2.2 服务用户态化清单（阶段二，文档明文）

[04-microkernel-strategy.md:149-180](file:///home/spharx/spharxworks/airymaxhub/docs/docs-closed/agent-linux-dev/03-microkernel-design-ref/04-microkernel-strategy.md#L149-L180) 明文：

> 「将 12 个 daemons 从内核态迁移到 services 子仓，实现用户态服务化。」
> 迁移后位置：`services/agentd`、`services/schedd`、`services/memd`、`services/cognitived`、`services/securid`、`services/netd`、`services/fsd`、`services/toold`、`services/monitord`、`services/logd`、`services/configd`、`services/cloudd`
> 「迁移策略：每个 daemon 先在当前内核中实现 IPC 接口 → 逐步迁移到用户态 → 迁移完成后**移除内核中的旧实现**」
> 验收：`12 daemons 迁移 | 全部迁移完成，功能无退化 | 功能回归测试`（[:228](file:///home/spharx/spharxworks/airymaxhub/docs/docs-closed/agent-linux-dev/03-microkernel-design-ref/04-microkernel-strategy.md#L228)）

**⟹ `daemons` 迁出 `agentrt` 树是文档既定的阶段二验收目标，且验收标准明确要求「功能无退化」——即 `|S₀∖S₁| = 0`。**

### 2.3 机制与策略分离（四层模型）

| 层 | 内容 | 载体 | 计入 `.c/.h` LOC？ |
|---|---|---|---|
| L1 机制 | 无策略的算法/原语 | 代码 | 是 |
| L2 契约 | 公开头 | 头文件 | 是 |
| L3 注入 | `ops` 函数表 + `.manifest` | 数据 | **否** |
| L4 策略 | 数据/生态 | `.json/.yaml/.toml` | **否** |

门禁 **G18 策略数据化** / **G19 机制核零策略载荷（fail-closed）**。**⟹ 策略从 `.c` 搬进数据清单，是**合法且被门禁鼓励**的减重通道**，且不损失能力（策略仍在系统内，只是不再编译进代码）。

### 2.4 功能守恒 G1

`|S₀∖S₁| = 0`（不丢能力）**且** `|S₁∖S₀| = 0`（不夹带新能力）。**搬迁非删除满足 G1**：能力被保留在系统内，仅宿主仓/载体改变。

## 5. 可行性判定（深度推理 + 形式化）

### 5.1 命题形式化
