## §1 架构总纲

### 1.1 一条纲领

**机制与策略极致分离**。

`agentrt` 的一切代码只用一个问题裁定归属：**这是机制，还是策略？**

- 答「**机制**」→ 留核，原子化、填格、成面；
- 答「**策略**」→ 让位，经 `ops` 函数表 + `.manifest` **数据化注入**，或整体**迁到生态层**。

机制核**零策略载荷**：不含厂商名、不含产品名、不含业务阈值、不含 `if (vendor == …)`。凡出现，即为架构违例（门禁 G18 / G19 静态断言，fail-closed）。

> **三义辨（防混算）**：**(a) 体积核**（LOC 硬门禁）= `atoms` + `commons` + `heapstore` + `gateway` + `cmake/`，**SLOC 有效行**锚定值 **85,535**（0.1.19 r3 锚，0.1.20 沿用）；**(b) 策略扫描面**（G19）= `agentrt/` **八模块全量**，**非体积口径**；**(c) 纲领留核** = 机制/策略**语义裁定面**。三者不可混算。

### 1.2 主线三步

| 步 | 名             | 内容                                             | 验收执法                      |
| - | ------------- | ---------------------------------------------- | ------------------------- |
| 1 | **立格** Slot   | 能力格构成永久坐标系；**格固定不变，且不留空格**（留格建件）       | G17 `slots` 字段 / G11 准入留痕 |
| 2 | **造件** Atom   | 每格一件；同类件塌缩归一；准入三问裁定什么够格当原子件                    | G9 N 判据 / G32 双达标         |
| 3 | **成面** Facade | 原子件经 `⊗` 装配为组合件，按职责面收敛为形态面；`main.c` 只启动组合件 | G16 五件套 / G15 四面不混        |

**格件关系**：**固定的是格，变化的是件。** 讨论「要不要加一个模块」时，先问「它填哪个格」；答不出格的，就是不该造。

### 1.3 三条减法托底

功能一行不减，体积靠三条减法达成：

| 减法     | 含义                            | 通道   |
| ------ | ----------------------------- | ---- |
| **迁出** | 策略与体验面离开机制核（搬迁，非删除；功能在别处继续提供） | 迁出账  |
| **塌缩** | 同类件收敛为每格一件                    | K 通道 |
| **生成** | 五件套样板由生成器产出，不手写               | S 通道 |

## §2 架构语言：Slot / Atom / Composite / Facade

### 2.1 四个概念

| 中文      | 英文            | 定义                    |
| ------- | ------------- | --------------------- |
| **能力格** | **Slot**      | 能力的最小归类槽位，**固定不变**    |
| **原子件** | **Atom**      | 填入某个格、不可再分、只含机制的最小实现件 |
| **组合件** | **Composite** | 两个及以上原子件按 `⊗` 装配得到的组件 |
| **形态面** | **Facade**    | 按职责面暴露的组合件集合，是服务层的「面」 |

> **统一自检句**：`Taskflow is an atom in the flow slot, exposed by the sched_d facade.`

### 2.2 核心关系式

```
面 Facade = 声明（manifest）+ 生成（样板）+ 组合件装配（Composite 承载）
格 Slot   ←固定→   件 Atom ←可变→
功能 = 原子件 ⊗ 装配 → 组合件 ⊗ 再装配 → 形态面
单向约束链：立格 → 造件 → 成面 → 挂载（顺序不可逆）
```

### 2.3 术语规范

**用语规范（全文强制）**：「死码」→ **死代码**；「出清」→ **清理**；「收口」→ **收敛**；「方言」→ **适配实现**；「打样」→ **样板改造**。

**禁止旧称（不得新增使用）**：capability lattice、aspect、面化、功能面、形态层、原子原语、原子组件、复合件、composition；**`Atomic`** **不得作可数名词**；`manifest` 字段 `aspects` 更名 **`slots`**。

### 2.4 演化面（0.1.20 三词体系唯一扩展，显式记录）

**定义**：**演化面（Facade of Evolution）**是形态面归属坐标系中承载「**自我改进**」职责的面——GRAD 双思考校验、GCCP、元认知、**金丝雀**等以系统自身为对象的演化能力，归属此面。

**为何独立成面（三条理由，缺一不立）**：

1. **代码实态跨两侧**：演化代码分布 `products/cognition`（GRAD/GCCP/MC，策略侧）+ `products/canary`（金丝雀件，策略侧）+ `agentrt/atoms/coreloopthree`（三层认知循环机制核），任何单侧归属都切断演化链条；
2. **自指准入权**：演化面产出的变更，由演化面自己的金丝雀格裁决准入——**裁判与被告同面**，形成自演化闭环；若散落他面，则「谁审计审计者」无解；
3. **归属即准入**（INV-4）：形态面归属是准入项，不是文档装饰——不立此面，第 21 族（金丝雀治理格）无处归属。

**边界（不是免检通道）**：演化面**不豁免**任何既有纪律——准入三问照常适用、机制/策略分流照常执行、爆炸半径硬约束照常生效。演化面只是**归属坐标轴**，不是特权态。

> **演进纪律**：三词体系（Slot/Atom/Facade）在 0.1.20 仅此一处扩展；此后再扩须走架构裁决，不得无名扩张。

## §3 能力格坐标系

### 3.1 格总表

| 层       | 格数 | 格名                                               |
| ------- | -- | ------------------------------------------------ |
| **基础层** | 10 | 同步 · 互斥 · 调度 · 隔离 · 命名 · 通信 · 序列化 · 事务 · 复制 · 恢复 |
| **中间层** | 8  | 增删改查（增/删/改/查 4 格合一族）· 发现 · 配置 · 缓存 · 路由          |
| **应用层** | 7  | 计算 · 校验 · 流转 · 通知 · 授权 · 记录 · 展示                 |
| **补充格** | 3  | 韧性 · 流 · 校准                                      |

### 3.2 留格建件（不留空格）

格是坐标系，坐标系上每个格位都是**架构承诺**。格上无件 = 能力缺位，靠各处私搭乱建维持；有件无扇入 = 死件占格。

**因此不留空格**：每个格都要有件，每个件都要有有效扇入。

### 3.3 格格双达标（全格无豁免）

| 判据         | 内容                                                                 | 不达标处置                                      |
| ---------- | ------------------------------------------------------------------ | ------------------------------------------ |
| **① 有效扇入** | 真实消费点（跨模块符号调用/链接引用的消费者文件数）实测 **≥ 3**；`#include` 仅作初筛 | 扇入 0 = 死件（G28 清扫）；扇入 1\~2 = 低扇入（就地内联或补消费者） |
| **② 运行正常** | 落点件有 tests 且接线 CI，golden 全绿                                        | **有测试未接线 = 未达标**（等同没测）                     |

## §4 组合件与形态面

### 4.1 组合代数：`⊗` 与 `⊙`

| 算子             | 时相  | 边界  | 类型                  | 通道                      |
| -------------- | --- | --- | ------------------- | ----------------------- |
| **`⊗`** **装配** | 装配期 | 进程内 | `A×A→C/F`、`C×A→C/F` | 函数调用                    |
| **`⊙`** **编排** | 运行期 | 跨进程 | `F×F→F_sys`         | **IPC / syscall（唯一通道）** |

**`⊗`** **五性质**：类型律（`A×A→C/F`，`C×A→C/F`）· **地位律（`F⊗F` 非法——面不能与面装配）** · 闭合律 · 结合律 · 幂等律。违反地位律即 fail-closed 拒绝（门禁 G14，不是警告）。

### 4.2 两根坐标轴（0.1.20 显式辨析）

系统存在**两根互相独立的四面坐标轴**，语料库并存、严禁混算：

| 坐标轴 | 名称 | 四值 | 断什么 |
| --- | --- | --- | --- |
| **进程职责视图**（0.1.19 起） | daemon 视图四面 | ingress / execute / state / governance | 一个 daemon 进程内部的职责切面；四面是它的视图，不是四个可拆进程 |
| **形态面归属**（0.1.20 起） | 形态面归属四面 | 用户面 / 平台面 / 策略面 / 演化面 | 一个 ops 族（能力格）的归属面；归属即准入（INV-4） |

**形态面归属表**：

| 形态面 | 职责 | 代码位置 |
| --- | --- | --- |
| **用户面** | 人机交互：CLI / TUI / 向导 | `sdk/tui` + `agentrt/tools/airy_cli/src/tui` |
| **平台面** | 运行时：推理、工具、IPC、持久化、网关 | `agentrt/atoms` + `agentrt/daemons` + `agentrt/commons` |
| **策略面** | 策略载荷：什么该做、什么不该做 | `products/*` |
| **演化面** | 自我改进：GRAD、GCCP、元认知、金丝雀 | `products/cognition` + `products/canary` + `agentrt/atoms/coreloopthree` |

**归属纪律（三条，0.1.20 固化）**：

1. **机制不得下沉策略**：`products` 不得被 `agentrt` 反向依赖（`link-whitelist.txt` 强制）；
2. **策略不得上浮机制**：判据阈值、灰度比例、重试次数一律在 `products` 或配置，机制核只执行；
3. **形态面不得互相穿透**：用户面只能读平台面提供的**只读观测字段**，不得直接持有 `canary_t*` 等机制核句柄。

> **编号警示（铁律 13 沿袭并扩展）**：`coreloopthree` 的「三面」（认知/规划/执行）≠ daemon 视图四面（3≠4）；daemon 视图四面 ≠ 形态面归属四面（两根轴）。三者严禁互称。

### 4.3 五件套（形态面的物理形态）

| 件    | 形式                        | 约束                        |
| ---- | ------------------------- | ------------------------- |
| ① 声明 | `.manifest`（含 `slots` 字段） | 机器可读，缺失即门禁失败；发布即冻结        |
| ② 入口 | `main.c`                  | **≤ 150 行**（只做装配与启动，不写逻辑） |
| ③ 实现 | `svc.c`                   | 主体逻辑                      |
| ④ 组合 | `modules/`                | 装配清单，声明用了哪些原子件            |
| ⑤ 装配 | **唯一私有头**                 | 全模块唯一一个私有头                |

### 4.4 禁薄胶水组合

**不能用薄胶水层的方式组合——薄胶水组合使系统不稳定**（无契约、无测试、复杂度散落、无问责）。**替代：组合一律经组合件（Composite）承载**——`⊗` 显式装配、组合件有自己的 tests 接线 CI、可测扇入；`main.c` 只启动组合件。

### 4.5 两条冻结律

- **引用律**：形态面**只引用公开头**；跨面调用必须经公开头，不得直接触碰他人私有头。
- **冻结律**：`.manifest` 一旦发布即**冻结**，变更须走版本递增，不得原地改语义。

## §5 机制与策略分离（纲领落地）

### 5.1 分离四层（自内向外）

| 层         | 内容                             | 形态       |
| --------- | ------------------------------ | -------- |
| **L1 机制** | 不含任何策略的原子件                     | 代码       |
| **L2 契约** | 接口与数据结构                        | 公开头      |
| **L3 注入** | 策略经 `ops` 函数表 + `.manifest` 注入 | 数据       |
| **L4 策略** | 具体决策（阈值、厂商、权重、规则）              | 数据 / 生态层 |

### 5.2 两条硬规

1. **策略只经 `ops` 函数表 + `.manifest` 注入**——不得在机制件内 `#include` 具体策略、不得 `if (vendor == …)`。
2. **机制核零策略载荷**——机制核内出现厂商名、产品名、业务阈值即门禁失败。

### 5.3 原子件准入三问

| 问                 | 判据                        | 不过的后果             |
| ----------------- | ------------------------- | ----------------- |
| **① 是机制吗？**       | 不含业务策略、不含厂商名、不含产品决策       | 不是 → 归**策略**，迁生态层 |
| **② 是收敛型抽象吗？**    | 收编后总行数下降，且抽象带**语义**而非仅签名  | 不是 → 是**伪抽象**，禁止  |
| **③ 复用 N ≥ 3 吗？** | 独立使用点 ≥ 3（N=2 须证同构，N=1 禁） | 不是 → 不建件，就地内联     |

### 5.4 金丝雀治理格与自演化准入（0.1.20 新增）

**四层级定位**（格→插槽→件→面）：

| 层级 | 实体 |
| --- | --- |
| **格**（第 21 格/第 20 族） | 金丝雀治理格 `dpolicy_canary_ops_t`——灰度会话门控与流量路由 |
| **插槽** | `dpolicy_set_canary_ops()` 注入入口；宿主 `svc_canary.c` 的 `g_ops` 装配 |
| **件** | `products/canary/`（金丝雀原子件，A-1~A-5 五判定全过） |
| **面** | 演化面 |

**五态机**：

```
C0 提案 PROPOSED → C1 影子 SHADOW → C2 本地灰度 CANARY
    （10% → 50% → 100%，每级驻留 ≥2h）
→ C3 采纳 ADOPTED（写 local overlay manifest，记 base SHA-256）
→ C4 回滚 ROLLED（恢复上一 manifest，只回 overlay 不碰 base）
```

**硬约束**：

| 约束 | 内容 |
| --- | --- |
| **爆炸半径** | 一次演化 ≤1 模块 / ≤3 文件 / ≤200 行 |
| **G30 准入** | 演化补丁新增函数 ≤150 行、修改后 ≤200 行（`canary_admit` 静态校验） |
| **门禁阈值** | K1 正确性 ≥99.9%；K2 性能保持 ≥95%；K4 回滚 ≤5min；指标未知（`CANARY_K_UNKNOWN` = −8）**不滚、不推进** |
| **kill switch** | 三通道（环境变量 / 文件哨兵 / CLI），命中即停止一切自演化写入 |
| **base 漂移** | base 变化 → manifest 标记待重放，禁止静默合并 |

**自指准入权**：演化面产出的变更由演化面的金丝雀格裁决——金丝雀格挂载点缺席即旁路（A-5 缺席即降级：`dpol_can_gate` 在 `e->canary == NULL` 时放行），系统退化为「无自演化审计的普通运行态」，**功能守恒不破**。

**投递方式不立格**（问二裁定）：灰度投递是演化面的内建语义（`canary_route` 采样路由），不是第 22 个族——族是格，挂载点是件；立新格即 G-S1 格子膨胀反模式。

## §7 运行视图

### 7.1 进程与通道

- **跨进程**：唯一通道 = **IPC / syscall**（`⊙` 编排）；**零进程内符号引用**（G23）。
- **进程内**：唯一装配方式 = `⊗`（函数调用），装配经**组合件**承载。
- **层界单向**：不出现反向依赖（G21）。

### 7.2 运行不变量（五条）

1. **路由不得由错误驱动**——传输选择在 init 期一次性定型，调用路径零 try-fail-fallback。
2. **健康 = 端到端可达**——代理指标（socket 文件存在、进程存活）不得冒充健康。
3. **硬依赖缺失必须降级态显式上报**——禁止静默 ready。
4. **时间序单调**——排序与耗时按 monotonic，绝对时刻按 wall。
5. **失败必可行动**——错误载荷带 cause + remedy。

### 7.3 金丝雀运行视图（0.1.20 新增）

- **挂载点缺席即旁路**：`dpol_can_gate` 在 ops 未注入时返回放行（A-5）——金丝雀机制核缺席不阻塞主链路，属**降级显式态**而非静默 ready 的反例（降级由宿主 manifest 声明）。
- **指标未知即停**：`canary_gates` 返回 `CANARY_K_UNKNOWN` 时，宿主不得滚、不得推进状态机——**门禁不可判定 ≠ 门禁通过**。
- **热路径锁 free**：`canary_route` 为多线程安全（C11 原子），状态转移函数由宿主串行调用（commit 路径）。
- **kill switch 单向性**：CLI 通道熔断持久化哨兵文件，重启后仍生效；TTL 1s 缓存保证探测低频。

### 7.4 体验面：TUI 只是 CLI 的渲染

```
TUI 输出 = fold(CLI 事件流)
```

TUI 是 CLI 事件流的**纯投影**，**零业务决策**；CLI 父进程持除终端外的一切，TUI 子进程唯一持终端；同一终端同时只有一个持有者。唯一实现：`sdk/tui`。

### 7.5 认知负载

认知负载**只打在 `think_d`**（G22）。

## §9 架构速查

### 9.1 一页纸

```
纲领      机制与策略极致分离
主线      立格(Slot) → 造件(Atom) → 成面(Facade) → 挂载
坐标系    能力格（基础 10 · 中间 8 · 应用 7 · 补充 3）+ ops 族实体账（20 族，Gate 43 双向闭合）
件        每格一件；同类件塌缩归一；准入三问（机制？收敛？N≥3？）
轴①      daemon 视图四面（ingress/execute/state/governance）——进程职责
轴②      形态面归属四面（用户面/平台面/策略面/演化面）——归属即准入
组合      ⊗ 装配（进程内）· ⊙ 编排（跨进程）· F⊗F 非法 · 禁薄胶水
演化      演化面（唯一扩展）：GRAD/GCCP/MC/金丝雀；金丝雀五态机 C0→C4；
          爆炸半径 ≤1 模块/≤3 文件/≤200 行；K 未知不滚；kill switch 三通道
验收      格格双达标（扇入 ≥3 + tests 接线 CI）· Gate 43 归属双向闭合 · selfcheck 能红
运行      路由不由错误驱动 · 健康=端到端可达 · 降级必显式 · 时间序单调 · 失败必可行动
体积      机制核 85,535 → <80,000（SLOC 有效行）；形态面子账 61,426 只降不升
体验      sdk/tui 不设上限；TUI = fold(CLI 事件流)
```

### 9.2 自检句

- `Taskflow is an atom in the flow slot, exposed by the sched_d facade.`
- 「这是机制，还是策略？」——答不出，即违例。
