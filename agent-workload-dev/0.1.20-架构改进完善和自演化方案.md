## 2. 工程哲学：原子化 · 能力格 · 形态面

### 2.1 三词的权威定义

> 来源：`0.1.19-架构文档 §2.1`。本版**不改定义**，只补落地判定与反模式。

| 词 | 定义 | 判定问句 |
|---|---|---|
| **能力格（Slot）** | 能力的**最小归类槽位**，固定不变。一格只表达一种能力语义 | "这个函数属于哪一格？换一格是否语义就变了？" |
| **原子件（Atom）** | 填入某个格、**不可再分**、**只含机制不含策略**的最小实现件 | "去掉它，该格是否就空了？它内部是否含业务判断？" |
| **组合件** | 两件及以上按 `⊗` 装配的产物 | "装配后是否只做转调，不引入新语义？" |
| **形态面（Facade）** | 按**职责面**暴露的组合件集合（用户面 / 平台面 / 策略面 / 演化面） | "调用方看到的是职责还是实现细节？" |

> **术语约定（P3-1 终裁）**：**原子化**指工程纪律本身（凡章题、方法论语境一律用此）；**原子件**专指上表定义的不可再分实现件（凡指称"件"的语境一律用此）。二者非同义词，混用即 P3-1 型术语缺陷。

**三词的关系是一条单向约束链**：

```
立格（先定槽位与契约）
  → 造件（往格子里填唯一实现）
    → 成面（按职责把件装配成面）
      → 挂载（面通过 ops 挂载点接入运行时，缺席即旁路）
```

**反向操作被禁止**：不允许"先写函数再发明格子"（格子膨胀），也不允许"面直接调用另一面的内部件"（形态面穿透）。

**第 9 格的语义订正（P1-10 选项②后果）**：`airy_ipc_ops_t` 的"进程间通信"**不由 binder 承载**。
binder 是进程内回调/环形队列总线（`kern_ipc.h:8-20` 头注明文 *in-process only*，
`airy_ipc_get_fd()` 恒返回 `-1`）；跨进程唯一通道是 AF_UNIX / loopback TCP（`daemon_rpc_client.c:6` "L1 socket 通道"）。
因此本格的判据是**负向的**：`airy_ipc_*` 仅限 `atoms/corekern/`，`.rpc` 后缀构造为 0（Gate 24 E1/E2）。

### 2.3 造件：原子件的五条判定

一个实现件可称"原子件"，当且仅当**五条全满足**：

| # | 判据 | 反例（本仓实证） |
|---|---|---|
| **A-1** | **单格**：只服务一个能力格 | `engine_process.c` 曾同时处理执行与记账 → 违反，C9 已拆 |
| **A-2** | **不可再分**：再拆则任一子件都无法独立完成格语义 | `canary_core.c` 按**职责**拆出 `canary_manifest.c` / `canary_sha256.c`，属可接受边界 |
| **A-3** | **只含机制**：不含业务阈值、不含策略选择 | **r76 订正**：K1/K2/K4 三阈值（`CANARY_OK_FLOOR` / `CANARY_PERF_FLOOR` / `CANARY_RB_MAX_SECS`）是格契约常量，落 `products/canary/include/canary.h:45-47`（**策略面内**，非 `agentrt` 机制核）；宿主只持采集口径与样本下限（`svc_canary.c:45 CAN_TICK_SLICES`、`:49 CAN_MIN_SAMPLES`）→ 合规 |
| **A-4** | **零反向依赖**：不调用形态面，只调用同层或更低层 | `products/canary` 零 libc 之外依赖（`CMakeLists.txt` 有 `AIRY_COMPLIANCE_IMPL` 豁免）→ 合规 |
| **A-5** | **缺席即降级**：不挂载则系统仍能运行 | `dpol_can_gate` 在 `e->canary == NULL` 时返回 0（放行）→ 合规 |

**A-3 与 A-5 是本项目最容易破的两条**，历史上两次重大事故都源于此：

- 0.1.19 `degraded` 上报机制件已落地但 llm_d 未接线 → **A-5 方向对，接线缺席**；
- 0.1.20 `svc_canary` 的三阈值落在策略面 `canary.h:45-47`（A-3 合规），宿主只持采集口径（`CAN_TICK_SLICES` / `CAN_MIN_SAMPLES`）；但 **K1/K2 指标源接入前判据是空的** → S1 已补（§5.6），r76 复验六门禁全部可触发（Gate 38 七码各有用例）。

### 2.4 成面：四个形态面与归属纪律

| 形态面 | 职责 | 代码位置 | 体积约束 |
|---|---|---|---|
| **用户面** | 人机交互：CLI / TUI / 向导 | `sdk/tui`（Rust）+ `agentrt/tools/airy_cli/src/tui`（C） | G30 单文件 ≤800 行 |
| **平台面** | 运行时：推理、工具、IPC、持久化、网关 | `agentrt/atoms` + `agentrt/daemons` + `agentrt/commons` | **机制核 79,999 硬线** |
| **策略面** | 策略载荷：什么该做、什么不该做 | `products/*` | 无硬线，受质量门禁 |

**归属纪律（三条）**：

1. **机制不得下沉策略**：`products` 不得被 `agentrt` 反向依赖（`link-whitelist.txt` 强制，Gate 24 执法）；
2. **策略不得上浮机制**：判据阈值、灰度比例、重试次数一律在 `products` 或配置，机制核只执行；
3. **形态面不得互相穿透**：用户面只能读平台面提供的**只读观测字段**，不得直接持有 `canary_t*` 等机制核句柄。

### 2.5 装配算子 `⊗` 的三条纪律

- **`⊗` 只做转调**：组合件内不允许出现 `if (策略) {...}`；
- **`⊗` 保持幂等**：重复挂载同一 ops 表不改变行为（`dpolicy_set_canary_ops` 已是覆盖语义）；
- **`⊗` 可逆**：任何挂载必须有对应卸载路径，且卸载顺序受时序约束（§5.4）。

### 2.6 三类反模式（挂靠门禁）

| 反模式 | 现象 | 后果 | 拦截手段 |
|---|---|---|---|
| **格子膨胀** | 为单个函数新造 ops 族 | 21 族变 30 族，挂载点失去意义 | Gate 43 + Q9 裁定（不立第 22 族） |
| **原子件越界** | 机制件里出现 `if (profile == "fast")` | 策略不可配置、不可回滚 | Gate 24（`layer-check.sh`） |
| **形态面穿透** | TUI 直接调 `canary_step()` | 交互与机制生命周期耦合 | Gate 24 + `facade-attribution-check.sh` |

### 2.7 演化面 = 独立形态面（0.1.20 唯一一处体系扩展）

r13 只有三个形态面（用户/平台/策略）。0.1.20 把**演化面独立出来**，理由是实测：

- 演化代码分布在 `products/cognition`（GRAD/GCCP/MC）、`products/canary`（金丝雀）、`agentrt/atoms/coreloopthree`（编排侧演化统计），**跨越平台与策略两侧**；

- 独立后，演化面拥有**自指的准入权**：演化面产出的变更，由演化面的金丝雀格裁决。

**该扩展已由 S2 登记落文**（`0.1.20-架构文档.md` 演化面实体表 + 第 21 族条目），Gate 43 机械执法。

### 4.3 五条需专门说明的条目

#### 4.3.1 P1-10：能力格跨进程 —— 以**选项②（socket-only 语义降级）**结案

**这是本版最容易被误读的一条。它不是"未修复"，是"以另一种方式修复"。**

诊断四证据（r29）：

1. **binder 不是传输层**：`atoms/corekern/include/kern_ipc.h:8-20` 头注明文 *in-process only*，`airy_ipc_get_fd()` **恒返回 `-1`**，越界使用被 layer gate 拒绝；
2. **零生产调用方**：`binder_find_node_locked()` 的两处调用（`binder_channel.c:100/189`）均为**进程内回调/环形队列**语义，不是跨进程寻址；
3. **第二套路径已被根除**：`.rpc` 派生由 `8fcd6dd` 删除（10 文件 / −2,901 行）；r64 实测 `atoms daemons commons products` 全树 `".rpc"` 构造 **0 命中**；
4. **符号属公共 ABI，不可删**：`airy_ipc_*` 是对外契约，删除即破坏 ABI。

**裁决**：选②不选①（Q20 建议默认是①，即"实现真正的跨进程注册/发现"）。理由：

- 选项①要求 binder 承担跨进程寻址 → **会再造第二套平行传输路径**，与 §2.1「单向约束链」和 §2.6「形态面穿透」冲突；
- 事实是**跨进程可达的承载者一直是 socket**（`daemon_rpc_client.c:6` 注释 "L1 socket 通道"），binder 从未承担该职责；
- 因此正确动作不是"补实现"，而是**补登记**：把第 9 格 `airy_ipc_ops_t` 的语义订正为"按名可达的承载者 = socket `sun_path`"（§2.2）。

**代价（必须记账的语义成本，不入 LOC 预算）**：能力格的"按名寻址"在**单进程内**成立，在**系统级**由 socket 路径承担；两者不是同一种"按名"。这一语义降级由 Gate 24 E1/E2 机械执法，**不允许反向回潮**（回潮即 E2 转红）。

#### 4.3.2 P1-11：GRAD-B 仲裁 fail-open 已收口

`products/cognition/src/grad/grad_llm_s1_arbiter.c:647-656`——服务故障/空裁决显式上报，错误码透传与主路径（L495）同语义，B 未参与时**可归因、可判读**。

#### 4.3.3 P1-12：截断事实在 wire 面显式化

`agentrt/daemons/llm_d/src/rpc/response.c:69-74`——仅当 `llm_finish_is_truncated()` 为真时输出 `"truncated": true`（完备回答零噪声，与 `timings` / `capacity` 同风格）。**机制只报告事实，处置归调用方策略侧**——这是 A-3（只含机制）的正例。

#### 7.5.1 裁定记录：账本判据从「梯级名」改为「数值 pin」

**起因**：A5 复核发现账本记录与 `loc-budget-check.sh` 实测差 3,686 行，且旧判据以梯级名 `current=K4` 为键——
梯级自带 500~2000 行松量，而 Gate 41 的 pin 解析器只认 `KEY=数字`，**梯级键完全逃逸棘轮审计**。
结果是「账本可长期偏离代码，而所有门禁皆绿」。这不是数值错误，是**判据错误**。

**裁定（四条）**：

1. 不做激进减重来迁就旧数字——那是用系统风险换账本好看；
2. 不以「上移上限」冒充减重——上限上移是事实登记，不是工程成果；
3. 判据改**数值 pin**：三账各自 pin 实测值，删去已 dead 的梯级阶梯与 `--advance`；
4. 职责切分：**「不得超过」归 Gate 18，「不许滞后」归 Gate 42**。减重后不作 `--converge` 落账即红，
   使落账成为减重的强制组成部分，而非可选的收尾礼仪。

**事实**：+3,686 行全部来自 0.1.19 实施期间的真实落地（`llm_d` 自托管链、`coreloopthree` 演化面、cognition 接线），
非虚增，已按 `RATCHET-JUSTIFY` 约定在 tools 仓同 commit 登记；`facade` 61,576→64,240→**64,232**（r45 上移附理由、r46 回落 −8）
与 `cupolas` 17,009→17,314→**17,342** 的上移中，**facade 有登记、cupolas 的 17,314→17,342（+28）在 baseline 无登记注释**（r65 观察项）——
棘轮按设计工作的前提是"上移必附理由"，缺登记即 BK-2 未闭合，0.1.21 须补记理由或回退。

### 8.3 三级回滚（三级不可混用）

| 级别 | 手段 | 适用 | 关键约束 |
|---|---|---|---|
| **L1** | 单 commit `git revert` | 某逻辑变更被证明有害 | 一 commit 一逻辑变更；revert message 须写明「原 commit 门禁结果 vs 现状」 |
| **L2** | 批次 tag `0.1.21-bN` | 某批出口未达需整体退回 | tag 携带该批门禁结果摘要；回退后**下一批必须重过入口条件** |
| **L3** | 金丝雀 overlay 回滚 | 采纳（ADOPTED）后发现问题 | **只回 overlay**，base 不动；依据 `MAN_PREV`；`can_roll()` 不得吞 `canary_step()` 的 `-2`（§5.4 I2） |

> **L3 与 L1/L2 不在同一层**：L1/L2 是开发期回滚，L3 是运行期回滚。
> 混为一谈会得出「金丝雀有 git 就够了」的错误结论——**git 回滚需要人在场，overlay 回滚不需要。**

### 8.4 commit 纪律（六条，Gate 45 部分覆盖）

1. **一个 commit 一个逻辑变更**。bisect 友好是硬要求，不是风格偏好。
2. **标题**：`airy/<子系统>: <祈使句摘要>`，≤72 字符，结尾无句号，禁 `[PATCH]`/emoji/自指表述。
   子系统取 `airy/sched`、`airy/mem`、`airy/ipc`、`airy/lsm`、`airy/vm`，本版新增 **`airy/evolve`**（金丝雀与演化面）。
3. **落款**：修复类 `Signed-off-by: Decheng Li <lidecheng@spharx.cn>`；功能类 `Signed-off-by: Liren Wang <wangliren@spharx.cn>`。
4. **修复必须带 `Fixes:`**（hash ≥12 字符，`hash ("原标题")` 格式，**不拆行**）；外部报告加 `Closes:`。
5. **每批最后一个 commit 专用于「门禁转绿」**：只改门禁脚本 / 基线 / selfcheck，**不改产品代码**。
   作用是把「代码改动」与「判据改动」在 git 历史上**物理分离**——混在一个 commit 里，任何「改判据让测试过」都不可审计。
6. 禁止把 diffstat 写入 commit message；`---` 之后的内容不进 `git log`。

## 9. 门禁体系（Gate 1–45 重基线）

### 9.0 重基线裁定

r13 规划 G33–G63（29 个新增 / 共 58 号），实践中造成三次事故：
Gate 27 假绿（缺脚本被算跳过）、r63 标题重号、文档与编排器编号脱节。
**0.1.20 的裁定是：Gate 1–45 为唯一权威序列，`G33`–`G63` 幽灵编号永久作废**，
旧名保留在函数名中（`gate_logic_g38()` 打印 `Gate 27`）作为考古线索，但**不得出现在任何文档正文**。

**执法方式**：Gate 45 机械校验「文档中每个 `Gate N` 必须在编排器 `grep` 到」。
这条把「编号纪律」从人的自觉变成脚本判据——**这是 0.1.20 门禁体系最重要的一次方法升级**。

### 9.2 fail-closed 四规则

| # | 规则 | 反例后果 |
|---|---|---|
| **F-1** | **缺被测物即红**，不得 skip | Gate 27 曾是 skip，导致全绿建立在缺失之上 |
| **F-2** | **缺环境即红**，不得降级为 WARNING | 无构建树时 G38 曾直接跳过 |
| **F-3** | **零样本即红**，不得视为「无违规」 | Gate 38 `handler_n == 0` |
| **F-4** | **元门禁自身必须能被红** | 不能红的门禁是装饰（Gate 44 的存在理由） |

> **四条的共性**：**「无法判断」一律映射为红，绝不映射为跳过**。
> SKIP 一旦参与全绿加总，全绿就不再是结论，而是一种修辞。

### 9.3 selfcheck 的判别力要求

每个新增门禁必须带 `gates/selfcheck/<gate>.sh`，且**删掉被测物后必须变红**。
只验「通过」不验「会红」的用例，等于只测了 happy path——这正是 `test_canary.c:140`
`CHECK(canary_admit(0,200) == -1)` 把缺陷固化成契约的同一类错误：**错误的测试比没有测试更危险**。

### 9.4 门禁与批次的绑定（含「红项白名单到期」机制）

- 每批只要求「该批交付的门禁」为绿，未到激活批的门禁允许为红；
- 但必须在批次 tag 说明中列出**白名单**，每项带**到期批次**；
- **白名单不是豁免**：`g30-deferral.txt` 的自指闭环已被判为反模式（§10.2 AP-4），
  白名单必须写「到期批次」，**不得写「后续版本」**。

### 10.0 提炼口径与淘汰原则

本章不是「读后感」，而是**把历史方案里被反复验证过的判断，固化成 0.1.21 可直接引用的编号条目**。
来源文档共 **15 份**（0.1.9 / 0.1.11 / 0.1.12 / 0.1.13 + 生产级就绪审查 / 0.1.15 / 0.1.16 + 0.1.16-A / 0.1.17 + 收敛问题点 / 0.1.18 / 0.1.19 + 架构文档 + TUI 建设方案 / 0.2.x），提炼得 **60 条**原始条目，去重合并为 **四组 37 条**。

**入组三条标准**：

1. **可判定**：能被写成「看到 X 就判红」的判据，不是态度；
2. **可复现**：在本仓至少有一次实证（事故、门禁、或 commit 链），不是外部经验；
3. **不重复**：同一判断只保留**最强表述**，其余作为附注。

**淘汰原则**：凡是「基于当时假设、已被施工推翻」的条目，**不进入本章，只进入 §10.5 淘汰表**。
把作废条目留在正文，是 AP-10（多值并存取大者）的直接诱因。

### 10.3 架构不变量（INV-1 ~ INV-9）

这组条目**永不随版本改变**，任何版本违反即架构回退。它们与 §2.4/§2.5 的纪律同源，但表述更硬。

| # | 不变量 | 违反后果 |
|---|---|---|
| **INV-1** | **单向依赖**：`products → agentrt`，反向永不成立 | 机制被策略污染，不可回滚 |
| **INV-2** | **缺席即旁路**：任何 ops 挂载点为空时，系统以降级但可运行状态继续 | 挂载失败导致整体不可用 |
| **INV-3** | **机制只执行、策略只声明**：阈值/比例/次数一律不进机制核 | 机制不可配置、不可跨产品复用 |

> 这不是"降低标准"，而是**把错误假设从架构里剔除**（否则 Gate 24 会一直守护一个不存在的能力）。

> 一个没有终态断言的金丝雀，跑得越久，越难判断它到底回滚了没有。

### 12.3 怎么做完（0.1.21 执行序列）

```
H-1（V8 终态断言）
  → H-2（CI 45/0 口径）
    → D-0（配减准入：Q2 裁定 + 可回收清单 + 账一余量确认）
      → D1 → D3 → D4 → D5 → D2 余量
        → W8（TUI 演化面板，依赖 H-1）
          → E-2（6 个 CCN 27–45 函数拆解，§13.9）
            → V2（OS × AgentRT 联合验收）
              → 发版闸门
```

**三条顺序理由**：

1. **H-1 必须最先**：W8 面板展示的是"自演化状态"，若 V8 本身名不副实，面板就是**把未坐实的状态可视化**（§10.2 AP-2）；
2. **D-0 必须在 D 面之前**：账一已越线 1,097 行（r65 实测），缺口 ≥5.10K，不配减就开工 = 在越线上叠加（§6.3）；
3. **V2 必须在最后**：它是**唯一能证伪前六步的东西**——前面全是单进程证据。

**E-2 为何排在 W8 之后、V2 之前**：拆解会改函数边界与调用链，必须在**行为已被 H-1 固定**之后做（否则无法判断重构是否改了语义），又必须在 V2 联调**之前**完成（否则联合验收跑的是将被重写的代码）。
