#### 0.4.4 「SWA Bounded Replay」定义的两次误读与定稿

该术语在前两轮被误读两次，现依 DeepSeek-V4.1-Flash 报告 §3.2.2 原文（[B] 级镜像）定稿：

| 轮次 | 错误定义（撤回） | 复核事实 | 级别 |
|---|---|---|---|
| 第一次 | 「SWA Bounded Replay = 结构化输出匹配状态的**有界重放**」 | **错**。那是 `structure_output/so_matcher_builder.py` 的 `replay_tokens`，与 SWA 无关；二者**同名不同物，不可混用**（`MAX_ROLLBACK_TOKENS` 属 SO 侧，见 §11.2 证伪靶） | [B] |
| 第二次 | 「SWA Bounded Replay = YoCo 的 prefill 截断（少算前缀）」 | **不完整**。`yoco.py` 的 `mask`/`compact` 与 `environ.py` 的 `KEEP_TOKENS` 下界是该机制的**实现落点之一**，但不是定义本身 | [B] |
| **定稿** | — | 报告 §3.2.2：hybrid 策略在「持久化 SWA KV」与「精确重建的计算」间权衡；精确重建需重放最近 `L × n_win` 个 token（L 层数、n_win SWA 窗口）；V4.1-Flash 改为**只重放最近 `n_win` 个 token 近似重建**跨层 SWA KV，从而「avoid persisting SWA KV cache to SSD while incurring a small amount of prefill recomputation」，实测 negligible performance degradation、persistent KV footprint 降至 V4-Flash 约 1/8 | [B] |

**对 0.1.20 的实际影响**：AirymaxRT 不持有 KV 缓存，故该机制**不进任何施工项**（§5.3 不迁移清单）；被取用的只有 **P14**——「近似/降级方案必须把失真上界、实测代价、收益三项同时写进文本」，落到 D3 摘要失真声明、D4 回滚等价性判据、D5 降级标记携带失真说明。0.4.1 第三行「真缺口是按生命期分层 + 精确/近似标注」的表述继续有效：前者说要标注，后者规定标注到什么程度才算合格。

#### 0.4.5 2026-10-22 B50 复验：三项判据的验证与证伪

对 §5.2.2 D 系列的主要立论，在 B50（单卡 Intel Arc Pro B50 / SYCL / llama.cpp b11712，双实例 `Qwen3.5-9B` 与 `qwen2.5-coder-7B`）上做了一轮**可证伪的**实测，结果如下。**本节结论优先于本轮之前的所有推断**。

- **学实现方式** = 可迁移的工程形态，限定为七类：① 数据结构（封闭枚举、`optional`、段表、位图、重映射表）；② 控制流骨架（探测-提交两段式）；③ 契约写法（实现者义务）；④ 断言位置（构造期 fail-fast）；⑤ 成本模型写法（系数表 + 排除项声明）；⑥ 测试与基准形态（对可读参照做微分、越界金丝雀、入库基线 + 双门阈值、废弃路径负向回归、无分配的设备张量做纯契约测试）；⑦ 平台差异装配（差异收敛到单文件、缺口具名可捕获、失败极性分级、观测差分）；
- **不迁移** = 其 kernel、存储、分布式与调度器内部策略（§5.3 不迁移清单）。

## §2 纲领与不变契约

### 2.1 一条纲领：受约束的自演化

自演化不是"系统想改什么就改什么"，而是：**系统自主改变自身一切可改面；改变本身受不可变契约约束**。安全不靠限制"能做什么"，靠四律兜底（§2.4）与三环边界（§2.2）。

### 2.2 三环模型（修订包络）

| 环 | 范围（示例） | 谁批准 | 层级 |
|----|--------------|--------|------|
| **自主环** | 策略载荷、目标函数、阈值/权重、策略选择、模型配置、工具参数 | 系统自主（全链审计 + 可回滚） | Tier 1 直接生效；Tier 2/3 经演化流水线自动 |
| **批准环** | 机制代码、对外契约、能力格形态、跨模块接口 | 流水线全门禁自动验证；**触碰契约或不可逆扩张时强制人工闸口** | Tier 2 生成+验证，Tier 3 上线 |
| **禁改环** | 见 §2.3 清单 | **一律禁止自改**（硬拒绝 + 告警 + 账本） | 全期 |

**元条款**：**三环分类本身不可自改**——否则自演化可将禁改项移入自主环实现自我扩权。分类修订只能由人工经特批流程完成。

### 2.3 不变契约（禁改环清单 —— 自演化的宪法）

1. **安全护栏**：SafetyGuard 桥、os_sandbox 工作区边界、审批链（tool_approval）——改之即逃逸自身沙箱；
2. **回滚框架**：撤销变更的机制本身——改之即自锁无退路；
3. **演化账本**：追加写、哈希链式防篡改——改之即无审计；
4. **人类监督通道**：冻结开关（kill switch）与人工闸口——改之即失控；
5. **三环分类**（§2.2 元条款）；
6. **发布链硬门禁**：e2e-clean-room 等 publish `needs` 硬门禁——改之即绕过验证。

### 2.4 自改四律（一切变更，无一例外）

1. **可回滚**：任何变更携带回滚路径，回滚本身经演练（G33/G35）；
2. **可审计**：任何变更写入演化账本，含提案、证据、批准、部署、结果；
3. **可复现**：任何变更可从账本条目完整复现（含构建输入与验证证据）；
4. **功能守恒**：对外功能一个都不能少（承 0.1.19 最高约束）。

### 2.5 守恒律四条对自演化的延伸适用

- **三账分立**：演化变更分别记入体积账（口径 (a)/(b)）、功能账、质量账，不得互抵；
- **净减为正**：Tier 2/3 生成的代码提案，合并后口径 (a) 总量不得上升；
- **归位不记账**：演化触发的代码搬迁按 0.1.19 归位律处理；
- **禁双轨**：演化上线新路径后，旧路径必须同版本删除，禁止"新旧并存观察一版"——观察期由金丝雀承担，不由双轨承担。

### 3.2 `think.process` 返回 `-32603` 的真实根因

**不是 think_d 失效，而是调用方先超时**：

- gateway 侧存在约 **120 s 硬超时**，该值**不在任何环境变量或配置项中**（`gateway_d` 二进制内建），`model.yaml` 的 `think.timeout_ms: 240000` 只作用于 think_d 内部；
- phase-2 的 8192-token 综合调用单次 **69.8 s**，叠加**上游 47.3 s 抖动**即击穿 120 s；
- 日志时序证明：`think_d` 在 `23:25:23.917` 已 `process ok (result_len=2734)`，而调用方在 **123.9 s** 收到 `-32603`。

**结论**：`-32603` 是**超时被误报为内部错误**——错误码没有透传"我等太久了"，而是伪装成"对方内部错误"。这直接支撑 D5（失败语义分级）与不变量 5（cause + remedy）：**错误码必须能区分"超时"与"对端故障"**，否则上层重试策略与降级决策全部建立在错误前提上。

### 3.4 服务化与容器化：三类依赖事故与性能标定

**镜像**：`airy/llama.cpp-sycl:b11712`，1.34 GB，基底 `ubuntu:26.04`。

**三类依赖（缺一不可，且故障现象差异极大）**：
1. **DT_NEEDED 直接依赖**：34 个 `.so`，约 380 MB——`ldd` 可见，缺失即启动报错；
2. **dlopen 隐藏依赖**：如 `libigc.so.2`——`ldd` 不可见，运行时才炸；
3. **oneDNN OCL 引擎回退**：**只在特定 matmul 形状触发**——大部分请求正常，个别形状失败。

**故障链（一次真实事故的完整链路）**：
`libOpenCL.so.1` 缺失 → `Arc(TM) Pro B50 Graphics OpenCL device not found` → `could not create a primitive` → `ggml_sycl_op_mul_mat` → 进程重启。

**三条工程结论**：
- **ICD 必须写镜像内绝对路径**（写宿主路径会在容器内失效）；
- **`HEALTHCHECK` 通过 ≠ 能推理**——健康判据必须是一次端到端最小推理调用（不变量 2 的实证）；
- **端口 11435/11436 接管可零改上层**——服务化不必改调用方。

**性能标定（全部 [A]）**：

| 项 | 9B | 7B |
|---|---|---|
| 单流 eval | 34.41 tok/s | 41.43 tok/s |
| 2 路并发 | 55.71 tok/s | 69.66 tok/s |
| 干净重建后单流 | 34.38 tok/s | 41.49 tok/s |
| 4 槽容量（`-c 65536 -np 4` = 4×16k） | 34.50 tok/s | — |
| **双模型同时常驻合计** | **35.4 tok/s** | — |

**容量与饱和**：`-c 65536 -np 4` 即 4×16k，实测 34.50 tok/s——**容量提升几乎不损失单流速度**，故"容量必须保守"的假设不成立。而**双模型同时常驻合计仅 35.4 tok/s，GPU 已饱和**——这直接否掉了 0.1.20 早期"双模型并行"的设计假设，定稿为**串行/分时调度，双模型常驻只作暖启动优化**。

**10 分钟 soak**：369 请求，0 失败。

### 3.8 G47 断点：「审→补」契约

**这是本轮最重要的单点发现。**

- 语义判据：9B **15.30 → 16.00（+3.5 pp）**，7/10 有改动，token **+255.0%**；7B 仅 +0.60。
- **断点**：9B 出现 **4/4 次非法 JSON**（缺最外层 `}`、`len 1569`、`column 1568`），而 `xjson()` **不补闭合、不重试** ⇒ `verdicts` 静默降级为 `{}` ⇒ 补丁侧 9 token 返回空 `{"patch_nodes":[],"removed":[]}`。
- **性质**：不是模型能力不足，而是**客户端契约缺失**——补三处客户端契约后，**0/4 → 9/10**，闭环 **7/10**。
- 另一条：**thinking 关掉时补丁产出 0 节点**——关思考与"能产出结构"是耦合的，配置有副作用。

### 3.10 提示词复用与传阅预算实测（2026-10-22，B50）

本节是本方案 **D1/D3 判据重写的直接依据**，全部为真机实测 [A]，实验脚本与原始输出留在 B50 `/tmp`（中间产物，不入库）。

**实验装置**：`llama.cpp b11712` SYCL 镜像，三个后端对照——11435（9B `Qwen3.5-9B-Q4_K_M`，GPU，默认参数）、11436（7B `qwen2.5-coder-7b-q4km`，GPU，默认参数）、11440（9B `Q3_K_M`，`-ngl 0` + 显式 `--cache-reuse 256`）。计量一律用 `/tokenize` 与响应 `timings`（`cache_n + prompt_n == prompt 总 token` 全部实验恒成立）。

**（1）八种布局形态对照：复用前提是「严格前缀」，且只对纯注意力架构成立**

| 形态 | 9B `qwen35`（hybrid SSM） | 7B `qwen2.5-coder`（纯注意力） |
|---|---|---|
| 完全相同 prompt 重复 | 94.6% | 98.7% |
| append-only 追加尾部（严格前缀） | **97.3%** | **97.7%** |
| 删掉末尾 20 token | 99.1% | 99.1% |
| 稳定段在前 + 异尾替换 | **5.0%** | **95.7%** |
| 中部插入一段历史（其余字节不变） | **5.0%** | 45.4%~46.1% |
| 标准 chat 多轮（历史在中部累积） | **0.0%（6 轮全 0）** | 65.2% → 83.5% |
| 固定问在前 + 历史追加在后 | 72.2% → 86.8% | 71.9% → 86.6% |
| chat 布局 + 尾部固定后缀 | — | 59.8% → 80.1% |

**（2）9B 侧根因取证：不是布局问题，是架构问题**

- GGUF 头（直接解析二进制 KV，非注释、非文档）：`general.architecture = qwen35`、`qwen35.ssm.conv_kernel=4`、`qwen35.ssm.state_size=128`、`qwen35.ssm.group_count=16`、`qwen35.ssm.time_step_rank=32`、`qwen35.ssm.inner_size=4096`、`qwen35.full_attention_interval=4`、`block_count=32`、`context_length=262144`、`embedding_length=4096`、`attention.head_count=16`、`attention.head_count_kv=4` ⇒ **混合注意力 + 递归状态层**。
- 服务端明文（11440，显式传 `--cache-reuse 256`）：`cache_reuse is not supported by this context, it will be disabled`；且 11440（CPU、带该开关）与 11435（GPU、默认）**逐项数字完全一致** ⇒ 该开关在本模型上被服务端否决，**不是配置问题**。
- 行为学解释：递归状态（conv/SSM）不可回退，任何非前缀复用都需要「从最近可判定状态重放」，llama.cpp 不做 ⇒ 只有「本次 prompt 是缓存序列的严格前缀」才可复用。
- 交叉验证：同一装置换成纯注意力 7B，「稳定段在前 + 异尾」立刻回到 95.7% ⇒ **实验装置无偏，结论来自模型架构**。

**（3）传阅面预算实测：现状 `sched_dag_engine.c:59-116` 的 4096 字节均分截断**

| 上游数 N | 现状（截断拼接）token | 句柄形态（引用+摘要+计数） | 相对现状 | 全文不截断 | 相对现状 |
|---|---|---|---|---|---|
| 1 | 1357 | 63 | **−95.4%** | 2735 | +101.5% |
| 2 | 1528 | 118 | **−92.3%** | 4630 | +203.0% |
| 3 | 1376 | 181 | **−86.8%** | 6477 | +370.7% |
| 4 | 1410 | 225 | **−84.0%** | 7730 | +448.2% |

- **字节预算 → token 成本的分散**：同一 4096 字节上限在四类真实产物上折合 1018（中文散文）/ 1242（补丁）/ 1319（中文列表）/ 1642（JSON）token，**1.61 倍**；且 N=2 的 token 数高于 N=3（JSON 被截得更少但密度更高）⇒ 字节预算对 token 无约束力。
- **截断不是语义边界**：N∈{2,3,4} 的 9 个截断位中 **4 个落在多字节字符中间**（`n-csset` 在 N=2/N=3、`n-risk` 在 N=3/N=4，尾部字节如 `e999a9e7`、`83bde587`），直接产出非法 UTF-8 交给 tokenizer/JSON。
- **展开面反转（G51 必须双账）**：若下游确实需要这些产物，(a) 一次性展开全部 ⇒ 净 **+208.0%（N=2）/ +459.7%（N=4）**；(b) 逐件展开（每轮前缀重发）⇒ 净 **+570.7% / +2438.5%**。即：**传阅面 −84%~−95% 的节省，会被一次「把该看的都看完」全部吃掉并倒挂**。

**（4）本轮实测对方案的三条直接修正**（详见 D1/D2/D3 行与 §11.2 靶 3/4/5）

1. D1 的收益前提是「模型支持非前缀复用」；当前主力 9B **不支持**，收益只能来自「append-only 严格前缀」这一条；
2. D3 的 ≥30% 只在**传阅面单账**成立，必须写成「传阅面 + 展开面」合计口径，否则是把成本转移到下游；
3. 「按字节预算 + 按字节截断」两件事在当前代码里同时存在，但两者在 token 与字符两个维度上都不可靠。

#### 5.2.5 借鉴后推理链的五段优化点（构造期 → 执行期 → 传阅期 → 收敛期 → 事后）

把 §5.2.4 的形态按推理链的时间顺序排布，得到 0.1.20 可施工的优化点。**顺序不可颠倒**，理由是每段的判据依赖前一段的产出。

4. **可调刚度**：自主/批准边界可配置——**只可收紧，不可放宽越过禁改环**。

### 8.3 审计链

提案 → 证据 → 批准 → 部署 → 结果 → （必要时）回滚：全链条目化、追加写、不可自改；账本 = 复现凭据 = 证伪素材。

### 8.4 演化账本与 mem_ledger 的关系（裁决项）

mem_d 台账（`ledger.c:23-54`：`seq/entry_id/session_id/token_in/token_out/ref_id` + DoS 上限 `DEFAULT_MAX_ENTRIES 200000`、`DEFAULT_BUDGET 32768`、水位 0.8）已具备**会话成本条目语义与回溯链**（`ref_id:43`），但其为**纯内存链表、无序列化、无防篡改**，且上限语义是防 DoS 丢弃（与审计"不可丢"相反）[B]。裁决（§11.1 待决 2 一并定）：演化账本**复用其条目语义（seq/引用回溯/水位告警），不复用其实现**；账本体落新介质：追加写 JSONL + 哈希链 + fsync，落点候选 `monit_d` 扩展 vs 独立设施。

## §12 三问成文回答

### 12.1 有哪些技术要点真正能启发 AirymaxRT

**方法先于结论**：不从「它们有什么」出发，而从 AirymaxRT 的失效现象出发，反推「要什么样的结构才能让这类失效不可发生」，再看参考实现里是否存在该结构的成熟写法。因此下面每一条都按同一顺序给出：**失效机理 → 结构形态 → 可判定准则 → 反例位置**。准则若不能指到反例位置，即为空话，不入本方案。

> 与 §5.2.4 的关系：那里按「十九条 → 六句话」做的是**形态侧归类**（哪几条 M 属于同一动作）；本节做的是**准则侧改写**（该动作要求什么可判定条件、在 Airymax 何处失守），分割相同而用途不同，不构成两套分类。本节另加 12.1.7 一条反向判断——那是不进方案的部分，故不出现在 §5.2.4 的形态表里。

#### 12.1.1 准则一：一个取值域必须与它的可观测状态同构

**失效机理**：`0` 同时承担「零消耗」与「未上报」；`roles = opinion_count` 让「1 个角色成功」与「4 个角色里 3 个失败」产出同一份 decision；`wh_state_terminal()` 用字符串比较判终态。三者共同点不是「缺少检查」，而是**信息在写入时就被压缩到不可还原**——一旦落库，下游无论做多少校验都无法区分。

**结构形态**：`sequence.hpp:30-64` 用枚举序把「是否终态」写成区间判定（`status >= FINISHED_STOPPED`），新增状态非落进区间即落出区间，不可能「漏改一处而静默」；`outputs.hpp:60-62` 用 `optional` 让「无值」占一个独立取值位；`scheduler.hpp:194-200` 把多资源准入折成三值并取最保守者。三者是同一动作的三种形态：**让「未知」在类型上拥有位置，且该位置不能被当作「零」或「成功」消费**。

**可判定准则**：任何字段，若「未上报」与「零值」语义不同，则二者在类型层必须可分；不可分的字段，不得进入任何守恒式、任何门禁判据、任何成本归因。

**反例位置**：`governance.c:348`（0 作哨兵）、`cog_review.c:329`（`roles=opinion_count`）、`work_hall_sched.c:40-44`（字符串判终态）。

#### 12.1.2 准则二：可复用性必须被写成数据，不能被写成巧合

**失效机理**：`sched_dag_engine.c:59-116` 每轮把上游产物全文 memcpy 进 prompt（`:111`），字节均分（`:78`）、裸截断（`:86-87`）。它**不具备表达「这一段与上一轮相同」的能力**，所以复用只能碰巧发生且无人知晓。代价在 B50 上已被量出：A 每轮 10 次调用、云 token 占 57.8%、token 是 B 的 2.3~2.5 倍（§3.6）；双思考 prompt 侧 +34.4%；审计形态全量 +255.0%（§3.7）。这些不是推理成本，是**重复传输成本**。

**结构形态**：`zos.cpp:147-176` 用 `remap_indices`（`-1` = 新行 / `>=0` = 复用上轮同行）把「要不要重算」变成一张整型表；`block_load_plan.cpp` 的 `BlockLoadSegment{src_block_id, src_begin, src_end, dst_offset}` 用 `src_block_id=-1` 表示 zero-fill；recipe 用 `segment_kind` 让「这一截能不能拼」成为标签而非默认假设。三者共性是：**复用判断从运行期分支退化成可打印、可 diff、可断言的表**。

**可判定准则**：凡跨轮或跨节点传递的内容，必须能回答「哪一段是新的、哪一段可复用、复用依据是什么」，且该回答以数据结构存在，不以函数名或注释表达。回答不出来的，一律按「全部是新的」计价——这正是 A 现状成本结构偏高的机制解释。

**反例位置**：`sched_dag_engine.c:111` 的全文 `AIRY_MEMCPY`；`taskflow_advanced_schedule.c:169-181` 多前驱只留最后一个 `prev_out`。

**B50 复验补强（2026-10-22）**：复用能力不是布局的函数，而是**模型架构类的函数**——同一「稳定段 + 异尾」布局，纯注意力 7B 命中 95.7%，hybrid SSM 9B 只有 5.0%（§3.10）。因此准则二的产物「复用表」必须带一个架构维字段；缺该维，同一份布局数据在换模型后会静默失效，而失效表现恰好是「数据看起来仍然齐全」。这使准则二从「写下来」升级为「写下来且标注其对谁成立」。

#### 12.1.3 准则三：把不可恢复的错误前移到可恢复的位置

**失效机理**：`work_hall_sched.c:99-116` 先提交、后回探、再补救——补偿路径与主路径并存，中间态对外可见；B50 的 `-32603` 是 120 s 超时被伪装成「内部错误」（§3.2），上层据此决策必然错误；配置错配能启动全绿并跑很久才炸。

**结构形态**：`scheduler.hpp:504-527` 探测段所有失败路径统一 `break`（零副作用），用一行注释划界，提交段一次性改状态/分配/出队；`scheduler.hpp:101-104` 启动即断言；`validation.rs` 把非法组合在转换期判 400。三处共同点：**让「失败」发生在还没有需要撤销的东西之前**。

**可判定准则**：任一操作若失败后需要补偿，则它必须可拆成「零副作用的判定」与「一次性的提交」两段；拆不开的，必须在构造期拒绝进入运行态。

**反例位置**：`governance.c:291-329` 顺序准入 + 失败补偿；`gateway_llm_api.c:192` 附近的超时到错误码映射。

#### 12.1.4 准则四：凡「模型没算的部分」，必须在源码里署名

**失效机理**：`ledger.c:25` 的 32768、`work_hall_sched.c:84` 的 `token_per_node × node_count` 都只有赋值没有依据；`messages.c:37-43` 把三项求和后命中与未命中不可区分。后果是**「读数偏低」与「模型漏算」无法区分**，于是任何成本改进都无法归因，也无法被证伪。

**结构形态**：`flops_estimator.hpp:13-27` 写成「系数表 + 逐条排除项声明」（draft/padding/replicas 不计、norms/activations 不计）；`cache_engine.py` 把一块 buffer 的尺寸拆成三条独立理由分层叠加，约束写成下界推导式且默认值故意非法；`StreamTokenizer` 把四条义务写在 trait 上。共性是：**「依据」「未计入项」「实现者义务」三类信息都出现在源码里，而不是留在作者脑子里**。

**可判定准则**：每个常量与每个估算式须同时给出依据与未计入项；缺少未计入项声明的估算，不得作为预算或门禁的自变量。

**反例位置**：`ledger.c:25`；`grad_llm_call.c:72-75`；`messages.c:37-43`。

#### 12.1.5 准则五：差异只允许在一个可寻址的位置存在

**失效机理**：provider/平台差异散落在调用点的 `if` 分支与硬编码前缀表（`service_request.c:162-174`、`local.c` 的 Ollama 遗留参数），于是「这个后端不支持某能力」只能靠返回 NULL 或静默降级表达——与准则一是同一条病在装配层的复发。

**结构形态**：`ops.py` 全 32 行自陈 "backend selection happens only in this file"，缺 kernel 抛 `KernelUnavailableError(AttributeError)`（继承 `AttributeError` 以保住 `hasattr` 协议）；`graph_timer.hpp` 用 `#ifndef WITH_NPU` 连字段与私有构造一起裁剪，使缺口边界恰好等于「需要裸句柄的操作」；`asc_utils.cpp:44-70` 面对一个对应三根因的模糊错误码 `507899`，前置 `TORCH_CHECK` 把远端错误翻译成本地可读断言。

**可判定准则**：新增一个后端或平台，若其差异不能被一次 grep 定位，则该接入方式不合格；「不支持」必须以可捕获、可判型的对象表达，不得以返回值表达。

**反例位置**：`service_request.c:162-174`；`local.c` 的 `LOCAL_EXTRA_PARAMS`。

#### 12.1.6 准则六：判据的效力由负向用例决定，不由通过率决定

**失效机理**：§3.3 的三条全绿与三条空转同时成立——`verdict` 90/90 accept、`e04` 90/90 pass、`c_verify` 90/90 error=0，而 `handler` 0/90、`s2_plan` 4/90。全绿不是证据，因为判据从未被置于「应当失败」的输入上。G47 断点更直接：`xjson()` 不补闭合、不重试 ⇒ `verdicts` 静默降级为 `{}` ⇒ 补丁 9 token 返回空，而这一切在「成功率」指标上毫无痕迹（§3.8）。

**结构形态**：`swa_index.py` 用「接口 + `_ref` 可读参照 + 测试同文件」三件套，测试是对参照做微分而非比对期望常量；越界写用 `91919` 金丝雀哨兵；`benchmark_baselines` 用相对门 `0.15` 叠加绝对下限 `3.0 µs`；`test_reject_mixed_cache_shape([584,592])` 为已废弃格式留负向回归；纯布局契约用 `device="meta"` 免加速器即可验证。

**可判定准则**：任一门禁上线的必要条件，是它至少有一条「必须失败」的用例，且该用例当前确实失败——**先看见红，再允许转绿**。

**反例位置**：`tests/unit/test_cog_review_strategy.c:135-179`（构造了生产不可达的同角色双意见，才凑出覆盖）；`sched_dag_engine.c:59-116` 的传阅布局（任何「100 次哈希恒等」式判据在它上面都会 100% 通过，但实测命中率仅 5.0%）。

**B50 复验补强（2026-10-22）**：D1 原有的构造成立判据「同一调用点构造 100 次，稳定段字节哈希恒等」本身就是本条准则的反例——哈希恒等是**必要条件**，实测中它恒成立而命中率仍只有 5.0%（9B）／0.0%（9B 标准 chat），**通过率 100%、效力 0**。故判据必须换成「有负向用例的前缀断言」：构造一组「字节前缀断裂」的输入，断言命中读数必须下降；若该用例不红，则判据无效。这条修正同时解释了为什么本方案把 G49 的主判据从前缀哈希改为架构类分档命中率（§9）。

#### 12.1.7 反向判断：哪些**不能**从这两个项目学到（本节的真正结论）

前六条是「照做」，这一条是「不照做」，而它比前六条更容易被忽略。

**其一，成本口径不同。** DeepInfer 优化「单位 token 的算力成本」，Airymax 优化「单位任务的有效 token」。前者靠 kernel、量化、KV 复用、批调度；后者靠信息复用与计量可见。所以 DeepInfer 的绝大多数成果对 Airymax **不是可借鉴，而是已在他处解决**——Airymax 采买或自托管推理引擎即可（这也是 §5.3 不迁移清单的真实理由：不是「不先进」）。**Airymax 若去追 kernel 级优化，等于用自己的短板换别人的长板，且永远追不上。**

**其二，真正稀缺的不是 kernel，是举证方式。** DeepInfer 最值得学的不是它算了多快，而是它**知道自己在哪里近似、近似多少**：`common.py` 写出 reject sampling 的输出分布上下界 `q[j] - eps/(1+eps) <= A[j] <= (1+eps)*q[j]`；`rstd_1ulp.py` 点名外部数值标准并要求运算顺序一致；`cache_engine.py` 把一个尺寸拆成三条独立理由。Airymax 的对应问题是「知道自己在哪里降级、降级多少」——而现状连降级都未被枚举（D5），更谈不上界。**「取思想不取实现」在此处的准确含义是：取它的举证方式，不取它的算力成果。**

**其三，正确性的锚不同。** 这两个项目的正确性锚是**数值可证**（对 `_ref` 微分、入库基线、1 ulp 标准），可自动判定；Airymax 的正确性锚只能是**语义可证**（谁在什么条件下被允许降级、降级后谁负责、缺席是否可见）。因此照搬它们的测试形态**不够**——Airymax 必须自建「语义金标」，而这正是 §3.3 的教训：90 个 workspace 的金标准全是正向样例，判别力为零。**这是本方案 §9「判别力通则」与 D5/D6 的真正来源，不是从外部抄来的。**

**其四，它们的强假设不可继承。** DSpark 的半自回归草稿 + 置信度调度验证、Mega-mHC、Engram 条件记忆，均以「持有模型权重与训练侧信息」为前提；Airymax 处在**取用方**位置，这些能力只能以「调用参数」或「引擎能力查询」的形式被消费，不能自行实现（§0.5 非目标）。判据是：**若某能力要求 Airymax 看到模型内部，则它只能被消费、不能被实现**。

**六条准则 + 一条反向判断的总判断**：可迁移的不是「先进功能」，而是**举证与约束的写法**——让不可靠变成不可表达（准则一）、不可重复付费（准则二）、不可拖到运行期（准则三）、不可无据（准则四）、不可散落（准则五）、不可自证（准则六）。前五条是**结构**，第六条是**结构的验收**；缺第六条，前五条都会退化成「写得更整齐的现状」。

### 12.2 哪些可以借鉴进 0.1.20

**取舍不是「重要不重要」，而是三条轴的联合判定**：

1. **可控轴**——该能力是否落在 Airymax 自己的代码面内（能改、能测、能回滚）。落在外部引擎内的，只能「消费」，不能「实现」。
2. **可证伪轴**——该改动是否能在本机被一条「必须失败」的用例证伪（准则六）。不能证伪的，不进 0.1.20，哪怕方向正确。
3. **账簿轴**——体积净增是否有同版本净减抵消（§10.3 第 2 条）。抵不掉的，后移。

三轴全过 → 0.1.20；缺可控轴 → 永不（只能消费）；缺可证伪轴 → 降到「只观测、不设阈值」；缺账簿轴 → 后移到下一版本。按此判定，六条语义项与十九条形态项的分流如下：

| 借鉴项 | 判定 | 落点 |
|---|---|---|
| D0/D1/D2/D3/D5/D6 | 三轴全过（能改、有负向用例、净增可由 L6 清扫抵消或计入形态面子账） | **0.1.20 必做 ~6.3K** |
| D4 检查点回滚 | 可控 ✓、账簿 ✓、可证伪 ⚠（「回滚后是否真更优」在 B50 上需先建立劣化基线） | **0.1.20 可选**（待决 11）；无基线前不进 |
| M1~M19 形态项 | 三轴全过，但**不新增生产码**，只改写法/装配/测试 | 随 C/D 同批落，测试侧 +0.4K |
| 推理引擎 / KV cache / 分布式拓扑 | 可控 ✗（在外部引擎内） | **永不**，只消费（0.1.20 自托管 llama.cpp / 0.1.21 GPU 服务） |
| xgrammar 语法编译 / tokenizer 本体 | 可控 ✗ | **永不**，只消费 |
| MTP / DSpark 解码策略 / SWA kernel | 可控 ✗ + 需模型内部信息 | **永不**（§5.3 不迁移） |
| 演化 Tier 1~3 | 可控 ✓、账簿单列（演化账）、可证伪 ✓（G33~G36） | 0.1.20 起逐层解锁（§5.4/§5.5） |

**语义层（D0~D6，必做六项 ~6.3K）**：D0 计量单一权威点 + 四元组（含 `hit=null`）；D1 布局契约 + 命中可观测（**不改答案缓存键**）；D2 预算 reserve→settle→refund 四件事 + 判定提交分离；D3 DAG 传阅引用化（句柄 + 摘要 + token 计数 + 复用索引）；D5 三值降级枚举（cause 区分超时与对端故障）；D6 CPR 缺席语义显式化（位图 + `partial` + `absent_reason`）。**这六项的共同前提是同一件事：先让「成本与降级」成为可读的数据**——否则后面任何优化都无法判断是否真的优化了（这正是 B50 验证 1 里「人工梳理 10 次调用归属表」的处境）。

**工程形态（M1~M19，不新增生产码项）**：M1~M11 约束**代码怎么写**（封闭枚举、`optional`、重映射表、系数表 + 排除项、探测-提交骨架、构造期 fail-fast、段语义标签、实现者义务、显式开关）；M12~M19 约束**测试与装配怎么写**（单点装配 + 具名缺口、参照微分 + 金丝雀 + 入库基线 + 负向回归、未实现精确到单操作、常量多理由分层 + 下界推导式、别名与生命周期声明、差分观测、失真界入模块头）。二者体积后果仅在测试侧 +0.4K。

**判据（P1~P14）**：十四条第一性原理是**准入闸门**——任何借鉴落不进其一即不采纳；不迁移清单（Wide-EP/3FS/NCCL/PD 分离/MTP/DSpark/SWA 实现/xgrammar/tokenizer 本体）是**硬边界**，理由均为「取用方不可见、不可控」而非「不先进」。

**不进 0.1.20 ≠ 以后再说**：推理引擎、KV cache、分布式拓扑、语法编译器、tokenizer 本体、能力格形态变更（§0.5）属于**永不自行实现**一类——AirymaxRT 的定位是推理的**经济学与治理**，不是推理本身。把这条边界写清楚，比多列十个「未来计划」更有价值：它解释了为什么本方案的体积增长必须被严格限制在语义层与形态层。

### 12.3 借鉴后推理链有哪些可优化的设计

**五段，顺序不可颠倒**（§5.2.5）。每一段给出三件事：改什么、**跳过的可观测后果**、**最小可验证切片**——第三件事决定了这段能不能在本机被证伪，而不是只在设计上成立。

**① 构造期**——架构类判定 + 布局契约 + 段表 + 稳定段哈希。`reactive.c` 改 system+user，`gccp.c` 历史改 append-only，构造期对稳定段做**字节前缀断言**（哈希恒等仅作必要条件）。
*跳过后果*：同一笔 token 永远分不清是稳定段还是可变段，于是 D1 的命中读数无法归因，后续三段的判据全部失去分母。
*最小切片*：同一调用点连续构造 100 次，断言①稳定段字节哈希恒等（必要条件，单独不成立判据）；②每次构造的串以稳定段为**严格前缀**；③按架构类分档核对命中率——递归态（SSM/hybrid）只认 append-only，须 ≥90%（实测 97.3%）；纯注意力 chat ≥60%（实测 65.2%→83.5%）；④反向用例必须红：把稳定段前插一段可变文本，命中率须显著下降（实测 9B 5.0%、7B 45.4%）；⑤三档 provider（本地 / 云 / 缺席）填法一致。无需跑完整任务。

**② 执行期**——计量四元组 + 预算两段式 + 联合准入。llm_d 出口成为唯一填点；`has_actual` 取代 0 哨兵；去钳位、单立 `overshoot_total`；`register`/`submit` 收进同一原子段。
*跳过后果*：refund 在 4 条 terminal 路径上保持不可达（`governance.c:348` 的 0 哨兵 + 4 处调用点全传 0；仅 `:307/:316` 的 register 失败回滚可达），超支读数继续漂移；A 的成本结构只能继续靠人工梳理调用归属表（§3.7 验证 1 的真实处境）。
*最小切片*：一次 `reserve` 后强制注入失败，`settle(0)` 与 `settle(null)` 必须产生**不同**的账目（前者退款、后者记「未上报」），且守恒式在两种情形下都成立；单测级，不需要集群。

**③ 传阅期**——句柄 + 摘要 + token 计数 + 复用索引。产物落 heapstore，图里传句柄；预算按 token；截断按段边界；未变段按索引复用。
*跳过后果*：每轮重付全部产物。这是 B50 上最贵的一项：A 的 token 是 B 的 2.3~2.5 倍、云 token 占 57.8%（§3.6），审计形态 +255.0%（§3.7 验证 2）证明「看得全」不可持续；**而结构性下限 +120%~+150% 说明提示工程已到顶，只剩结构改造**。
*最小切片*：三节点链、第二轮上游产物不变；①**传阅面**断言该段 token 降幅 ≥30%（句柄形态实测 −84.0%~−95.4%）；②**合计账**断言传阅 + 一次展开后总 token 不高于现状（实测反例：只报传阅面时 N=4 净 +459.7%，逐件展开 +2438.5% ⇒ 单账视为失败）；③复用断言必须带架构条件——递归态（SSM/hybrid）只有「严格前缀」可复用，故只在 append-only 布局下断言该段 `cache_n>0`，纯注意力才可放宽到「稳定段+异尾」；④下游解析结果与全文拼接**逐字节等价**且零非法 UTF-8（现状 9 个截断位中 4 个为非法 UTF-8）；⑤再注入一次段内变更，断言只有受影响节点重算。

**④ 收敛期**——检查点 + 增量重放 + 封闭终态。revise 前落 JSONL 检查点，劣化回滚重放，只重跑变化节点。
*跳过后果*：劣化后只能整图重跑或整图放弃；前者成本翻倍，后者丢掉已确认产物。
*最小切片*：回滚后 `grad_verifier` 通过（`grad_verifier.c:549-559` 的复核确定性且零 token，故可断言「该轮新增 LLM 调用 = 0」）；这是 Airymax 相对 DeepInfer 的**成本优势形态**——它的 `MAX_ROLLBACK_TOKENS` 要付重算代价，Airymax 的复核不花钱。

**⑤ 事后**——降级三值枚举 + 缺席位图 + 口径声明。错误标记随产物走，`partial=1` 的下游必须走 `skip_with_mark`，派生量附口径。
*跳过后果*：B50 的三类静默失败继续不可见——`handler 0/90`（字段缺失不报错）、`verdicts` 静默 `{}`（非法 JSON 降级）、`-32603`（超时伪装成内部错误）。**这三者共同的特征是「成功率指标上毫无痕迹」**。
*最小切片*：构造 n=1/2/4 三档 CPR 输入，decision JSON 必须两两可区分（G54①）；再注入一次 n=4 但 3 个角色失败，断言 `partial=1` 且 `absent_reason` 指到具体角色，而不是 0.95 的先验置信度。

**四层依赖是本方案对「推理链优化」的核心回答**：没有布局契约，计量读数无法归因；没有权威计量，token 预算没有依据；没有段表，检查点没有粒度；没有回滚能力，降级信号没有基线。因此它不是五个可任选的改进点，而是一条**必须按序铺设的证据链**——每一段的判据都建立在上一段的产出之上。**也因此，任何试图从③直接跳到⑤的做法，都会得到一个「标记齐全但读数不可信」的系统**，比现在更难排障。

**0.1.20 的边界**：①②③⑤ 全落（即 6.3K）；④ 仅 D4 可选。超出此界的（MTP/DSpark 解码策略、SWA 滑窗 kernel、Wide-EP、PD 分离）见 §5.3 不迁移清单。
