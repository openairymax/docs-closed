### 0.2 三铁律

1. **功能守恒 G1**：每一步减重必须 `|S₀∖S₁| = 0` ∧ `|S₁∖S₀| = 0`（不丢能力、不夹带新能力）。
2. **棘轮只降不升**：机制核与两个子账（形态面 85,434 / 应用壳 27,035）任一不得回升；**不得以子账缩水抵扣机制核**。
3. **口径不可腾挪**：减重必须来自「机制核本体行数下降」，**不得**通过改口径、移出计量面或改计数规则冒充。

### 1.3 关键发现（决定刀法取舍）

| # | 发现 | 数据 | 对减重的意义 |
|---|---|---|---|
| **D1** | **有效代码已 < 100k** | code **85,535** < 100,000 | 缺口 **−33,881 全部由「空行 18,752 + 注释 29,593 = 48,345 行（占 36.1%）」与代码结构性冗余构成** |
| **D2** | **注释密度超标** | 注释 29,593 / 133,880 = **22.1%**（C 语言典型 ≈15%） | 与项目规范「代码区非必要不注释」不符；**规范化冗余行内注释是最大单一合法杠杆**，且不触碰 G1 |
| **D3** | **头文件占比高** | `.h` **43,222（32.3%）**；`commons` 头占比 **40.6%** | L2 契约层可收敛（内部分解头折叠、伞头去重、重复声明消除） |
| **D4** | **文本级重复已归零** | 机制核同名文件仅 `error.h` / `export.h` / `syscalls.h` 三对；克隆门禁实测 **21 行** | 「消除 copy-paste」**不再是**减重通道（与 `可行性研究方案` §3.1 一致） |
| **D5** | **策略静态表已基本外置** | 机制核 `static const` 大表实测仅 **46 行**；厂商载荷 21 文件 / 36 行 | 「策略数据化」红利**已基本吃尽**，不可高估 |
| **D6** | **`.manifest` 缺失** | 机制核（`atoms`/`commons`/`heapstore`/`gateway`）`.manifest` = **0 件** | 形态面注入机制（L3）未建；这是 `gateway` 减重的**根因**，也是补齐后方能下沉策略的前提 |

> **⟹ 结论**：机制核减重**不是**「消重复」问题（D4 已归零），也**不是**「策略外置」问题（D5 已吃尽），而是**「契约层收敛（D3）+ 注释/空行规范化（D2）+ 结构归并 + 死码清扫」**的组合问题。其中 **D2 与 D1 是最关键的两个事实**：账面 133,880 中仅 85,535 是代码。

- **低风险**（纯规范化/外置/清扫，不触碰控制流）：B、D、E → 保守合计 **−11,000**

## §4 汇总账（两阶段）

### 4.1 阶段划分（分级门禁，先落地后推进）

| 阶段 | 刀法 | 目标减量 | 落点 | 达成里程碑 | 风险 |
|---|---|---:|---:|---|---|
| **P1** | **E + B + D + F(首刀)** | **−16,000** | **117,880** | **K1 ≤119,000 ✓**、K2 ≤112,000 ✗ | 低（规范化/外置/清扫） |
| **P2a** | **A + C** | **−12,000** | **105,880** | K3 ≤105,000（贴线，需 P2a 达上限） | 中（结构性改写） |
| **P2b** | **B/C/F/G 续 + E 续** | **−7,000** | **98,880** | **K4 <100,000 ✓**（余量 1,120） | 中高 |

### 4.2 结论

- **K1（≤119,000）可达**：仅靠「注释/空行规范化 + 策略外置 + 死码清扫 + gateway 首刀」等**低风险**手段即可，**无需任何能力改写**。
- **K4（<100,000）可达但有条件**：必须叠加**契约收敛（刀 A）与结构归并（刀 C）**，且**刀 E 贡献须达 −8,000 以上**。若刀 E 受限（见 §6 R-E），则需 P2b 从刀 C/A 补足，**余量收窄至千行级**——与 `可行性研究方案` §6.2「余量 351 极紧」的警告同源。
- **有效代码视角**：机制核有效代码 **85,535 已 < 100,000**；账面缺口本质是 **D1（48,345 行空行+注释）与 D3（43,222 行头）**。**凡以「删注释/删空行」达成者，若超出「代码区非必要不注释」规范边界，须经用户裁定**（见 §7）。

## §6 风险与阻断项

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| **R-E** | 刀 E 若被裁定为「不得精简注释」 | 失去最大单一杠杆（−6,500~−12,000），K4 余量收窄至千行级 | P2b 从刀 A/C 补足；或调整 K4 达成时点（不调数值） |
| **R-A** | 契约收敛触及公共 API | 破坏下游（`daemons`/`protocols`/`tools`/`cupolas`）编译 | 只折叠**内部**头；公共头符号集冻结校验 |
| **R-B** | 策略外置后运行时加载失败 | G19 fail-closed 触发，功能不可用 | manifest 校验 + 缺策略降级显式上报（架构文档 §7.2 运行不变量第三条） |
| **R-C** | 结构归并引入回归 | 能力退化，违反 G1 | 逐族回归 + 克隆门禁 + 圈复杂度 <2.5 |
| **R-F** | `gateway` 建 `.manifest` 改变加载契约 | 启动失败 | 先并行（manifest + 旧路径），验证后切 |
| **R-T** | 三架构/三端 | x86/ARM/RISC-V + Windows/Linux/macOS 屏蔽不得破 | 每波三架构构建；platform 收敛须三端兼容 |
| **R-M** | 余量贴线（K3 阶段仅余 880） | 任一波未达即停线 | 分级门禁；未达梯级即停线整改，不带入下一梯级 |

**阻断项（不可减）**：`cmake/`（184，组织码）；`atoms/syscall` 对外 syscall 契约；`commons/platform` 三端基线（仅可归并不可删能力）；`protocols` 归形态面后不在本方案计量面内（见 §0 口径）。
