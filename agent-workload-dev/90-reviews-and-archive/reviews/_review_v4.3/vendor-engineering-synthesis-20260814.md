## 摘要

DeepSeek、Kimi、智谱三家分别代表了国内大模型工程的不同侧面：**DeepSeek 是成本与基础设施的极致**（受限算力下的系统效率）、**Kimi 是 agent 平台工程的粒度之最**（上下文取舍、工具协议、协作架构）、**智谱是 agent 产品交互与可信度建设的范式**（中间界面解耦、异步确认、影子上线）。

三家的方法论在八个维度高度收敛，构成「行业级 agent 工程的共识基线」；而 agentrt 的定位——**对标 Kubernetes 之于容器编排，成为 Agent 编排的行业标准底座**——恰恰需要把这些共识转化为「标准化的机制、契约化的接口、可组合的底座」。本报告给出三方共识提炼、对标 K8s 的底座要素映射、以及与 agentrt 现状的差距清单和 P0/P1/P2 融入路线图。

## 一、三方共识：行业级 Agent 工程的 8 条基线

三家在以下八个维度独立得出相同结论，可视为**行业共识**（详见分厂商文档，此处给精简版）：

| # | 共识 | DeepSeek | Kimi | 智谱 | agentrt 落点 |
|---|------|----------|------|------|-------------|
| 1 | **规划与执行显式解耦**，独立评测独立迭代 | 任务级分时调度 | agentic 轨迹管线 | 中间界面 | think_d（规划）/ 执行 daemon（落地）分层，双指标 |
| 2 | **按任务复杂度分配思考预算**（多档思考） | 三档 Think | reflex/thinking | 交错/轮级/档位 | 双思考 → sched_d 可调度「思考预算」 |
| 3 | **可验证奖励优先，主观评价兜底且限量** | R1 规则奖励 | RLVR + Self-Critique Rubric | 可验证任务课程 | GRAD/RLVR 只对可验证结果开放强化通道 |
| 4 | **轨迹即资产**：结构化执行轨迹 + 可验证性即质量标签 | 拒绝采样沉淀 | 四阶段轨迹管线 | 过程日志 | 执行轨迹落 L1→L4，与 memoryrovol 对齐 |
| 5 | **软约束替代硬惩罚**（可调偏置/预算） | 无辅助损失均衡 | 动态工具加载 | 资源克制 | sched_d 软路由 bias；gateway 按需注入工具 |
| 6 | **两级检索：廉价粗筛 → top-k 精读**，「少结构」原则 | DSA 先索引后精读 | MoBA | HiSparse | 四层记忆两级召回，需演进期校准 |
| 7 | **评测体系先行**：真实场景基准 + 可复现工具 | 机制级消融 + 公开数据 | NIAH 矩阵 + agentic 基准 | ARC 三轴 12 项 | 调度/思考/工具/记忆基准矩阵随版本发布 |
| 8 | **异步执行 + 关键节点人工确认 + 过程实时可见** | 任务级分时共享 | Agent Swarm 实时可见 | 云手机 + 确认节点 | 任务大厅交互模型 + GRAD 审批原语 |

## 二、各方独特思想与互补性

| 维度 | DeepSeek | Kimi | 智谱 | 互补关系 |
|------|----------|------|------|---------|
| 系统效率 | 计算-通信重叠、FP8/FP4 全链路、智效比 | Muon 2× 计算效率、上下文缓存 | 参数效率（激活 vs 总参）、推测解码 | 三者都是「把成本写进目标函数」的不同切面 |
| 存储/记忆 | 3FS 计算-存储分离 + CRAQ 强一致 | 上下文超限取舍规则（保工具闭环） | 「大上下文兜底 + 结构化沉淀」 | DeepSeek 给架构范式，Kimi 给取舍规则，智谱给两级策略 |
| 调度/协作 | 任务级分时共享、EPLB 热副本 | Agent Swarm「冻结队员只练教练」 | 课程式难度分级调度 | DeepSeek 给资源层，Kimi 给编排层，智谱给成长层 |
| 稳定/可信 | batch-invariant 确定性、可抢占 rollout | MuonClip 最小干预、熵坍缩控制 | 影子上线、渐进式部署、关键动作护栏 | 三方各从正确性/稳定性/流程可信度切入 |
| 平台/生态 | 可组合底座开源（MIT 小组件） | OpenAI 兼容 + 工具即服务 + 前缀缓存 | 能力分层商品化 + API Key 作用域 | 三者共同勾勒「agent 平台服务化」的完整图景 |

**三方互补性总结**：DeepSeek 解决「怎么高效」、Kimi 解决「agent 怎么干活」、智谱解决「人怎么与 agent 协作」——三者恰好对应 agentrt 底座的三层命题：**运行时效率、Agent 编排机制、人机交互与可信**。

## 三、对标 K8s：行业标准底座的要素映射

agentrt 定位「K8s 之于容器编排 = agentrt 之于 Agent 编排」。K8s 之所以成为行业标准，核心要素有四，映射到 agentrt 与三方借鉴如下：

### 3.1 稳定、契约化的 API 面（对应 K8s 的 kube-apiserver）

K8s 的 kube-apiserver 提供统一 REST API + 资源对象模型，所有控制面组件只通过 API 交互。

| K8s 要素 | agentrt 现状 | 三方借鉴 |
|----------|-------------|---------|
| 统一 API 面 | gateway JSON-RPC 路由到各 daemon（已具备） | **Kimi**：OpenAI 兼容层 + 可选参数扩展；**智谱**：能力开关化（thinking/工具/缓存/结构化输出） |
| 资源对象模型 | 任务/蓝图/Agent 描述符（已具备） | **Kimi**：工具 JSON Schema + strict 约束；**智谱**：可配置智能体（知识库+角色+工具权限） |
| 标准工具协议 | GCCP（已具备） | **Kimi**：动态工具加载（按需注入降 token 提准确率）；工具即服务（执行与推理分离、独立限流灰度） |

> 结论：agentrt 的底座地位取决于 gateway 契约是否成为「Agent 编排的 kube-apiserver」——即**任何 Agent 框架都能通过统一协议接入**。借鉴 Kimi 的 OpenAI 兼容策略 + 工具即服务，智谱的能力开关化与 Scope 分级。

### 3.2 控制面 / 数据面分离（对应 K8s 的 controller / etcd / kubelet）

K8s 控制面（controller manager、scheduler）只做决策，数据面（kubelet、容器运行时）只做执行，状态存 etcd（强一致）。

| K8s 要素 | agentrt 现状 | 三方借鉴 |
|----------|-------------|---------|
| 声明式控制面 | sched_d 调度 + 蓝图（已具备） | **DeepSeek**：无辅助损失软路由（bias 软调节替代惩罚）；任务级分时共享 + EPLB 热副本 |
| 强一致状态 | 记忆 L3 结构层（事务 KV，演进中） | **DeepSeek**：3FS 计算-存储分离 + CRAQ 强一致 + POSIX 接口（L1 原始卷/ L3 事务 KV 的架构范式） |
| 确定性 | — | **DeepSeek**：batch-invariant 确定性内核——同蓝图同输入多次执行结果一致，可审计可回放 |
| 可抢占 | — | **DeepSeek**：可抢占 + checkpoint 容错的 rollout 服务（长任务抢占后续跑） |

> 结论：底座地位需要「控制面只做决策、状态强一致、执行可复现」。三家中 DeepSeek 对控制面/数据面/状态层的工程思想最系统，是 agentrt 运行时治理的主要借鉴源。

### 3.3 可组合、可扩展的底座（对应 K8s 的 CRD/Operator 生态）

K8s 通过 CRD + Operator 让第三方能力以标准对象接入，生态由此爆发。

| K8s 要素 | agentrt 现状 | 三方借鉴 |
|----------|-------------|---------|
| 标准扩展机制 | GCCP 工具协议 + daemon 插件化（已具备） | **DeepSeek**：可组合底座开源——生产级小组件（MIT）+ 公开 profile 数据，而非巨型框架 |
| 能力注册 | gateway 能力发现（演进中） | **智谱**：原生融合优于模块拼装——daemon 协同围绕共享记忆卷状态设计，能力边界统一注册 |
| 职责收敛 | 17 daemon | **智谱**：CodeGeeX 聚焦教训——「一个 daemon 一个职责面」，新能力以 GCCP 工具加入，不无限新增 daemon |

> 结论：底座地位取决于「第三方能否以标准机制扩展」。DeepSeek 的「生产级小组件」策略与智谱的「职责收敛」构成扩展机制的信任与克制两翼。

### 3.4 生态信任：开放、可复现、评测先行（对应 K8s 的 CNCF 治理）

K8s 成为标准靠的是开放治理 + 可移植性 + 生态测试（CNCF conformance）。

| K8s 要素 | agentrt 现状 | 三方借鉴 |
|----------|-------------|---------|
| 开放协议 | IPC magic 0x41524531、JSON-RPC（已具备） | **Kimi**：OpenAI 兼容降低集成成本；**智谱**：能力分层商品化 |
| 可复现 | 三平台构建矩阵 + 覆盖率门禁（已具备） | **DeepSeek**：机制级消融 + 确定性 + 公开数据 = 可复现三件套 |
| 评测体系 | — | **智谱**：ARC 三轴 12 项基准矩阵 + 可复现工具 + 真实 query 标注；**Kimi**：NIAH 多位置×多长度矩阵、agentic 多步闭环基准 |

> 结论：底座地位最终取决于「是否成为行业默认的事实标准」，这需要评测体系公开化——agentrt 应发布自己的「调度/思考/工具/记忆」基准矩阵（对应 CNCF conformance 测试）。

## 四、与 agentrt 现状的差距清单

基于三方共识与 K8s 要素映射，梳理 agentrt 现状差距（按可落地性排序）：

| 级别 | 差距项 | 现状 | 三方来源 |
|------|--------|------|---------|
| P0-1 | sched_d 软路由 bias（负载均衡不惩罚） | 有 is_available 门控，无软偏置 | DeepSeek |
| P0-2 | 思考预算三档（普通/交错/深度）接入双思考 | 双思考已有，预算未参数化 | 三家共识 |
| P0-3 | 任务轨迹结构化落 L1（目标/工具调用/成败） | 任务完成可统计，轨迹未落记忆 | Kimi / 智谱 |
| P0-4 | gateway 按需动态注入工具子集 | 工具全量注入 | Kimi |
| P0-5 | 记忆两级检索（粗筛→top-k 精读） | 四层记忆有索引，无两级召回策略 | 三家共识 |
| P1-1 | 记忆超限取舍规则（保工具闭环弃旧推理） | 无显式降级策略 | Kimi |
| P1-2 | gateway 前缀缓存（≥阈值才缓存） | 无 | Kimi / 智谱 |
| P1-3 | 任务大厅难度分级 + 失败任务回流复盘 | 有任务大厅，无课程调度 | 智谱 |
| P1-4 | 关键节点人工确认（破坏性操作） | GRAD 有审批原语，未形成交互范式 | 智谱 / Kimi |
| P1-5 | 双指标评测（蓝图失败率 vs 动作成功率） | 无分离统计 | 智谱 |
| P2-1 | 可抢占 + checkpoint 恢复的长任务 | 无 | DeepSeek |
| P2-2 | batch-invariant 确定性调度 | 无 | DeepSeek |
| P2-3 | RLVR 可验证奖励通道（GRAD 升级） | GRAD 评审存在，无 RLVR | 三家共识 |
| P2-4 | 基准矩阵随版本发布（调度/思考/工具/记忆） | 无 | 三家共识 |
| P2-5 | 新 daemon/蓝图影子上线灰度 | 无 | 智谱 |

## 五、融入路线图

### P0（低成本高杠杆，机制已有基础，直接实施）

1. **sched_d 思考预算三档**：`task` 对象增加 `thinking_budget` 字段（normal/interleaved/deep），按任务类型/复杂度默认指派，双思考据此选择轨迹；简单任务即时响应、工具链任务交错思考、长程任务深度思考。
2. **sched_d 软路由 bias**：每个 daemon 注册带权重 bias 与实时负载/延迟反馈，调度优先选「空闲且 bias 高」者，替代（或补充）现有 is_available 硬门控——不惩罚慢 daemon，只软调整路由。
3. **任务轨迹结构化落 L1**：任务完成后把 `task_id / 目标 / 工具调用序列 / 中间结果 / 成败 / 耗时` 写成结构化记录写入记忆 L1 原始卷，作为 L2/L3/L4 沉淀的原材料（与 memoryrovol write_raw 打通）。
4. **gateway 按需工具注入**：任务蓝图声明所需工具子集，gateway 只把该子集的 schema 注入 LLM 上下文，降低 token 消耗并提升工具选择准确率。

### P1（中期，需设计评审）

5. **记忆超限取舍规则**：上下文/记忆超限时「保工具闭环、弃旧推理文本」，由记忆 daemon 自动执行 L1→L2 降级压缩，动作记入审计日志。
6. **gateway 前缀缓存**：固定前缀（系统提示、daemon 身份、常驻工具定义）自动缓存复用，≥256 token 才参与缓存，控制小请求缓存开销。
7. **任务大厅课程调度 + 失败回流**：按 Agent 成熟度分配任务难度；失败任务自动生成「复盘任务」回流，与 L4 模式层联动。
8. **双指标评测**：蓝图失败率（规划质量）与动作成功率（落地质量）分离统计——think_d 与执行 daemon 各自优化，互不掩盖问题。
9. **记忆两级检索**：L2 粗筛索引 → top-k 精读，支持全量/稀疏无缝切换；检索参数（块大小、top-k、阈值）建立基准实验校准。

### P2（长期演进，1.0.1+）

10. **可抢占 + checkpoint 恢复**：think_d/执行链做成可抢占 rollout 服务，长任务抢占后续跑。
11. **batch-invariant 确定性**：同蓝图同输入多次执行结果一致，作为可审计/可回放前提。
12. **GRAD → RLVR 通道**：只对可验证任务结果（退出码、测试通过、验收标准）开放强化通道；开放型任务 rubric 自评兜底。
13. **基准矩阵随版本发布**：调度效率 / 思考效率 / 工具成功率 / 记忆命中率四维度基准 + 复现工具（对标 CNCF conformance）。
14. **影子上线灰度**：新 daemon/蓝图先在真实任务流旁路记录对比，达标后接管。

## 六、战略结论

1. **三方共识即行业基线**：规划/执行解耦、思考预算、可验证奖励、轨迹资产、软约束、两级检索、评测先行、异步确认——这 8 条是行业级 agent 工程的共识基线，agentrt 全部已有对应机制雏形，升级方向明确。

2. **agentrt 的差异化不是「再做一个 agent 框架」，而是「标准底座」**：对标 K8s 的四要素（契约 API 面 / 控制面-数据面分离 / 可组合扩展 / 生态信任），agentrt 已具备大部分机制（gateway JSON-RPC、sched_d 控制面、GCCP 协议、三平台构建），差距主要在**确定性、可抢占、评测公开化、灰度治理**四项——这些恰是「行业标准」与「能用」的分水岭。

3. **借鉴优先级**：运行时治理借鉴 DeepSeek（软路由、确定性、可抢占、存储分层），Agent 编排机制借鉴 Kimi（上下文取舍、动态工具、协作架构），人机交互与可信借鉴智谱（中间界面、异步确认、影子上线）。
