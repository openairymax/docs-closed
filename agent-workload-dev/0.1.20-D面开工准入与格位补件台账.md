### 2.4 D5 · 受管外部进程环境隔离（隔离格补件，**真缺陷**）

| 项 | 内容 |
|---|---|
| 面 | 平台面 |
| 格 | 隔离 |
| 件 | `sup_spawn_env_scrub()` —— 派生外部受管进程前按声明清洗 `LD_*` |
| 挂载点 | `supervisor_d` → `spawn_posix()` 子进程分支（fork 后 execv 前） |

**立项证据**：0.1.20 r68 §13.8 A7-5 首跑失败——宿主 `LD_LIBRARY_PATH` 污染导致受管 `llama-server` 报 `libstdc++.so.6: version GLIBCXX_3.4.30 not found`；`env -u LD_LIBRARY_PATH -u LD_PRELOAD` 后全绿。**当前 supervisor_d 无任何 `LD_*` 处理**（全树 `grep` 仅 3 处测试内 `unsetenv`，零生产代码）→ 缺陷在树内可复现。

**可证伪判据**：①在污染环境（`LD_LIBRARY_PATH=<坏路径>`）下 `sup_proc_spawn` 拉起的子进程不再继承该变量；②声明 `AIRYRT_LAUNCH_KEEPENV_<name>=LD_LIBRARY_PATH` 时保留（策略声明，机制不写死）；③新增单测覆盖「默认清洗」与「声明保留」两分支并接线 CI。
**认领门禁**：Gate 32（双达标：扇入 + 测试接线）、Gate 28。
**预算**：≤0.15K 净增；单 commit（≤3 文件/≤200 行）。
**状态：✅ 已闭环（daemons `9fa1cb5` + `8298327`，五级推送完成）**——机制落 `sup_proc_t.keepenv` + `sup_env_scrub()`（`internent.h` 声明 `SUP_ENV_MAX 128`），`spawn_posix()` 子进程分支 execv 前调用，默认清洗 `LD_LIBRARY_PATH` / `LD_PRELOAD` / `LD_AUDIT`；策略声明路径 `AIRYRT_LAUNCH_KEEPENV_<name>=LD_LIBRARY_PATH` 由 `decl.c:apply_keep_line()` 解析、`proc.c:env_keep()` 消费；单测 `t_env_scrub` / `t_decl_keepenv` 覆盖两分支，README 补 `BIN_` / `EP_` / `KEEPENV` 声明说明。判据①②③全绿。
