## 2. 审查方法与口径

1. **计划卡片逐卡解析**：对 `0.1.21-架构改进方案.md` 的 A~L 面任务表按
   `| <ID> | ... | <状态> |` 最后一列统计；对 §23.5.2 的 240 张 X 面卡按表格
   结构核查是否存在状态列与回执。
2. **代码取证**：凡文档声称完成的能力，均在源码中定位实现点（文件 + 行号），
   检索不到即判「未落地」，不采信文档描述。
3. **证伪优先**：上一轮「0.1.21 全部完成」的结论即由本方法推翻——文档状态列与
   代码事实双向不符。
4. **版本自证**：核对 `VERSION`、git tag、远端 tag、`install.sh` 兜底版本号。

## 4. 三项生产缺陷的根因与闭环证据

### 4.1 缺陷①：新机装完仍需手动 `export PATH`，`airymaxrt` 拉不起

根因三层，已逐层修复：

| 根因 | 修复 | 位置 |
|---|---|---|
| 安装器只写单一 shell 的 rc，换 shell 即失效 | 遍历 `.bashrc/.profile/.zshrc(+fish)` 中已存在文件写入，带幂等标记 | `agentrt/scripts/install.sh` `path_bootstrap()` |
| 软链创建失败无回验，用户不知情 | `ln -sf` 后回验可执行并打印兜底入口 | 同上 |
| `doctor` / `status` 依赖安装期快照，与真实 shell 状态脱节 | `status` 实时扫描 `$PATH`；`doctor` 三段式判定（缺链接 / 不在 PATH / 已掩盖但解析不到） | `tui/scripts/airymaxrt` |

提交：agentrt `570247f40`、tui `5cace0b`、agent-workload `3b89f8b`、顶层 `d311a37`。

### 4.2 缺陷②：配好密钥后对话报「服务不可达 / 请求失败：未知错误」

根因两个，均已修复：

1. `agent_d` 在失败路径丢弃上游 `error_code/error_msg`，终端只能显示兜底文案；
2. TUI 仅匹配英文字面量，中文环境下落到「未知错误」。

修复后语义：保留失败明细并按 error class 分类——
`provider_unreachable`（可重试）/ `provider_error`（不可重试）/ `config_missing`
（无可用模型）/ `budget_exhausted` / `tool_fuse` / `approval_denied` / `empty_result`。

实现点：`daemons/agent_d/src/run/agent_run_exec.c`（`fail_transport`、`AGENT_RUN_RC_LLM_FAIL`）、
`agent_run_loop.c`、TUI `health.rs`（中文摘要 + 原因码）。
提交：daemons `8d01c83`、agentrt `8e4f07264`、tui `e2cd540`、agent-workload `8b85844`、顶层 `0a58555`。

### 4.3 缺陷③：自托管无交互页面、多机器装不上 llama、命令不成体系

五处根因级修复：

| # | 根因 | 修复 |
|---|---|---|
| 1 | CLI 读 `local/registry/installed.env`，安装器写 `local/llamacpp/installed.env` → 服务永远不可见 | CLI 改为安装器路径优先、旧路径回退；新增单测锁定优先级 |
| 2 | supervisor 假死判定 3 tick（约 15s）即 SIGKILL，大模型加载期必被杀 | 新增 `AIRYRT_LAUNCH_READY_<NAME>` / `AIRYRT_SUP_READY_MS` 启动宽限，窗口内维持 STARTING |
| 3 | 变体缺省恒为 `sycl`，非 Intel GPU 机器冒烟必败 | 按 DRM vendor 自动判定，无 Intel 显示设备回落 `cpu` |
| 4 | 安装先 `rm -rf` 再落位，失败即毁坏既有安装 | 新目录装配 + 冒烟通过后整目录切换，失败回滚 |
| 5 | 无交互入口、声明链断裂 | `airy-local setup` 向导 + `airymaxrt local` 子命令 + `AIRYRT_MANAGED_READY` 经 bootstrap 贯通为 `AIRYRT_LAUNCH_READY_*` |

可见性补齐：`airymaxrt status` 与 `status --json` 新增 `managed` 段，按 `managed.d/*.env`
声明与进程表呈现自托管服务在线状态与端点。

提交：daemons `6c66c3f`；agentrt `6ce3462a0`、`52273d3b1`、`84ea3049b`、`0a4173ab6`；
tools `1cea14d`；tui `8e8d3ff`、`ff1a0ea`；sdk `a85a388`、`cb702b8`；
agent-workload `e3dc8ed`、`e393631`、`c59a083`。

验证：`supervisor_d` / `airy_cli` 构建通过；`sup_test_supervisor_core`、
`cli_model_reg_unit` 通过；`test_airy_local.sh`、`test_airy_local_model.sh`、
`test_managed_decl.sh` 通过；`bash -n` 全部脚本通过。

## 6. 巡检结论

- 三项社区生产缺陷已完成根因级修复并推送全部远端，可从「用户可感知故障」清单移除；
- 0.1.21 的机制面并非空转，但 **X 面（TUI 重建）与 47 张 A~L 卡尚未开始，整体不具备
  发行条件**；「全面完成」表述撤回，后续验收一律以「卡片状态 + 可复跑证据」为准；
- 下一阶段优先级：X 面 240 卡开工 → A~L 47 卡收口 → 14 卡补验收证据 →
  历史债（U-1/U-2/U-7/S2）清零 → 版本自证与发行台账。
