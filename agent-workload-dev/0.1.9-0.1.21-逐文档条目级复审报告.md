## 1. 结论摘要

### 1.1 三句话结论

1. **历史计划未清零**：16 份文档共抽取 **235 条**未竟/技术债/验收条目，`已完成 122 (51.9%)`、
   `部分完成 43 (18.3%)`、`未完成 59 (25.1%)`、`不适用 11 (4.7%)`。也就是说，
   约 **四分之一的历史承诺至今没有代码证据**。
2. **社区三缺陷：两项闭环、一项找到了更硬的根因**——`airymaxrt` 拉起链与失败明细透传已证实落地
   （含本轮补的两处缺口：`install.sh` 兜底旧版本、fish rc 覆盖，均已修）；
   自托管**不是「只缺命令暴露」**：向导/子命令/状态段确实都在代码里，但发行包
   根本没打包 `airy-local`，二进制安装的机器上该功能是硬缺失（**本轮 R-4 已修**）。
3. **0.1.21 未完成是事实，不是判断**：361 张 A~L 卡中 **不达标 49 张**
   （待启动 47 + 主状态未验证 2），另有 **12 张「已完成但带未验证注记」**；
   X 面 **240 张卡零状态列、零回执、229 张无实现锚点**。

   **但「命令暴露」不是唯一缺口**——本轮追到一条更硬的根因：发行包 `pkg_stage_bootstrap()` 只拷 `ops/templates/*` 与 `ops/bin/agentrt-bootstrap.sh`，**`ops/bin/airy-local`、`ops/lib/`、`llama-pin.list` 等一并缺失**；二进制安装无 `${AIRY_SRC_DIR}` 源码树，`install.sh:1650` 直接落到「自托管工具链未部署」告警，`airymaxrt local setup` 报「安装包缺少 airy-local」并 `exit 1`。即：**从发行包安装的机器上，自托管功能是硬缺失，而非「不易发现」**。
   另附架构面事实：`llama-pin.list` 覆盖 `linux-x64[-sycl] / linux-arm64 / macos-arm64|x64 / win-x64[-sycl] / win-arm64` 共 8 条，**无 linux-riscv64、无 win-x86-32**；这两个 0.1.12 已支持的发行目标上，`airy-local install` 无可用 pin 资产。（包内缺失 → 本轮 R-4 修复；pin 缺口 → 列入 §8 P1）

### 5.4 主审对 5.3 的订正（重要）

G6 在块3 对缺陷②给出「TUI 未实现七类错误分类」的否定判定。主审逐行复核后**部分推翻**该判定：

| 层次 | 事实 | 证据 |
|---|---|---|
| C 端原因码 | 七类（`budget_exhausted` / `tool_fuse` / `approval_denied` / `empty_result` / `provider_unreachable` / `config_missing` / `provider_error`）全部定义，另有 `agent_error` 等 | `commons/include/airy_run_stream.h:124-136` |
| 失败载荷 | `origin` / `code` / `reason` / `retryable` / `next_action` / `verification` 六个字段逐项下发，`fail_transport` 决定「不可达」还是「被拒」 | `daemons/agent_d/src/run/agent_run_exec.c:826-841` |
| TUI 消费 | `fail_text()` 对全部 11 个 reason 逐项给出中文文案（含「模型服务不可达」「模型服务拒绝了请求（检查 API Key / 模型名 / 配额）」「未配置可用模型」） | `sdk/tui/src/client/stream.rs:592-613` |
| TUI 归因 | `classify()` 把文案归到 9 个 `Cause`（quota/auth/model/config/rejected/timeout/unreachable/backend/unknown），`unknown` 只在全部关键字都不命中时出现 | `sdk/tui/src/engine/health.rs:273-400` |
| 回归保护 | 有单测断言 `reason` 字段透传到 TUI | `sdk/tui/src/client/tests.rs:831` |

**结论**：缺陷②在**功能语义上已闭环**（用户不会再因服务端给了原因码却只看到「未知错误」）；
G6 的否定只对「TUI `Cause` 枚举名不等于线上七类名」这一层成立，属**呈现层命名差异**，
不构成功能缺失。唯一可继续改进项：`Cause` 增加 `wire_reason` 字段直读 `reason`，
消除关键字匹配的脆弱性（P2，非阻断）。
