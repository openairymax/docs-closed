**三段式方法论说明**：

1. **第一阶段：Euler 参考提取**  
   从 openEuler 24.03 LTS 的技术参考文档和 OLK 6.6 源码映射中提取关键的技术决策和工程实践。这些构成了 AirymaxOS 的继承基础。

2. **第二阶段：行业理论融合**  
   将 Euler 提取的实践与行业最新理论（01-latest-theory.md）和最佳实践（02-best-practices.md）进行对比和融合，识别差距、验证方向、发现创新点。

   综合前两阶段的成果，形成 AirymaxOS 的最终技术方案，包括决策清单、设计原则、实施路径和协同设计。

### 4.3 关键技术决策详解

#### D-01: 微内核架构

- **来源**：行业理论 (T-01 seL4 MCS, T-02 Liedtke 原则重新审视)
- **决策**：采用微内核架构，内核代码控制在 80K LOC 以内
- **理由**：AI Agent 运行时需要高可靠性和强隔离性，微内核架构天然适合
- **风险**：IPC 开销可能影响性能，需要通过零拷贝等机制缓解

#### D-02: SCHED_AGENT 调度器

- **来源**：Euler (E-01 sched_ext 可扩展调度框架)
- **决策**：基于 sched_ext 理念设计 SCHED_AGENT 可扩展调度框架
- **理由**：参考 Linux sched_ext 的成功经验，提供调度策略可扩展性
- **创新点**：融入 Agent 感知和 Token 能效优化

#### D-03: Capability 安全模型

- **来源**：行业实践 (P-01 seL4 Capability) / 行业理论 (T-03 动态权限)
- **决策**：采用 Capability 安全模型，支持动态权限分发
- **理由**：比 SELinux 更灵活，更适合 Agent 动态权限需求
- **创新点**：支持时序能力收回和批量授权优化

#### D-05: KV 分页管理

- **来源**：行业理论 (T-04 LLM 调度特性) / 行业实践 (P-04 vLLM PagedAttention)
- **决策**：内核原生支持 KV-cache 分页管理
- **理由**：LLM 推理工作负载的特殊需求，需要 OS 层面的支持
- **创新点**：将 KV 分页作为一等公民管理

#### D-06: Token 能效调度

- **来源**：行业理论 (T-05 Token 能效) / 自主创新
- **决策**：将 Token 能效作为一级调度指标
- **理由**：AI Agent 工作负载的核心价值是产生的 Token 数
- **创新点**：全新的调度指标，行业首创

## 5. 与 agentrt 的协同设计

### 5.1 IRON-9 v2 三层模型

AirymaxOS 的 agentrt 子系统采用 IRON-9 v2 三层模型：

| 层次 | 代号 | 功能 | 实现位置 |
|------|------|------|----------|
| 调度控制层 | [SC] | Agent 调度策略、资源分配 | 内核态 SCHED_AGENT |
| 安全隔离层 | [SS] | Agent 安全沙箱、权限控制 | 内核态 Capability + 用户态 Cupolas |
| 基础设施层 | [IND] | 推理引擎、存储、网络 | 用户态 services |

### 5.2 三层交互关系

```
+--------------------------------------------------+
|  [SC] 调度控制层 (SCHED_AGENT)                     |
|  - Token 能效感知调度                              |
|  - KV-cache 亲和性调度                             |
|  - 异构加速器调度                                  |
+--------------------------------------------------+
        | 调度决策下发             | 指标上报
        v                         v
+--------------------------------------------------+
|  [SS] 安全隔离层 (Capability + Cupolas)            |
|  - Agent 能力分发与收回                            |
|  - 内存隔离与共享                                  |
|  - Wasm 沙箱管理                                  |
+--------------------------------------------------+
        | 资源分配               | 状态反馈
        v                       v
+--------------------------------------------------+
|  [IND] 基础设施层 (services)                       |
|  - 推理引擎 (vLLM/TensorRT-LLM)                   |
|  - 存储服务 (KV-cache 管理)                        |
|  - 网络服务 (AgentsIPC)                           |
+--------------------------------------------------+
```

### 5.3 协同设计原则

| 原则 | 说明 |
|------|------|
| 机制与策略分离 | 内核提供机制，用户态实现策略 |
| 最小信任计算 | 每个 Agent 只获得最小必要权限 |
| 可观测性优先 | 所有调度和安全决策都可观测 |
| 优雅降级 | 单组件故障不影响整体系统 |
| 能效优先 | 所有设计决策以 Token 能效为第一优化目标 |
