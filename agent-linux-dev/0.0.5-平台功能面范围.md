## 1. 定位

本文件是 `0.0.5-极境OS任务方案.md` 的追加范围，只回答一件事：**功能归属册里
仍标 `0.0.5` 的 34 条平台功能面，在本版如何收口**。

原图纸 §2.1 的 44 个 WP 全部落在引导 TUI、输入、意图、适配层、内核两条与 Rust
供应链；34 条平台功能面虽被归属册判在 `0.0.5`，却没有对应 WP。范围裁定为
**全部在 0.0.5 内实现**，因此按原图纸 §3 的任务卡口径追加 P 系列 WP，编号从
`P-01` 起到 `P-31`，一条不多、一条不少，与归属册 34 行逐行对应。

本文件不改变原图纸已有的 44 个 WP、AC 判据与日历；它只补上缺失的那一段，
并按原图纸 §2.4 的规则同步改三处：本文件、`completeness-audit.md`、原图纸
§2.1 的范围表（追加一节指向本文件）。

## 4. 工程约束

- 任何一项不得以桩函数、空实现或「只到接口」收口；归属册的判据是「有二进制与
  数据面」，只加头文件不计。
- 每个 WP 自带一条门禁与至少一条失败路径用例；门禁只消费既有产物，不新增
  「演示性检查」。
- 内核侧新增文件必须同时更新 `kernel-consistency` 的文件清单与 KUnit 注册，
  否则 KUnit 不执行等于没有实现。
- 代码规范遵循 `50-engineering-standards`：重复率 <3%、圈复杂度均值 <2.5、
  函数名 ≤15 字节、文件头中文注释。
- 每个 WP 完成后回填 `completeness-audit.md` 对应行的判据列，指向门禁与产物；
  未在 285H 实跑的行只改判据、不改归属。

## 5. 账本回填

归属册 34 行的「承接版本」列维持 `0.0.5`；「判据」列按本文件 WP 矩阵逐行替换为
交付物路径与门禁名。回填只在产物落地后进行，禁止先改判据后补实现。
