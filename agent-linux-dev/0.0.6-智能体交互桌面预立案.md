# AirymaxOS 0.0.6 预立案：智能体交互桌面

> **文档定位**：0.0.6 的立项前预立案，锁定布局、渲染、复用边界与部署前置；
> 不替代 0.0.6 任务方案（后者在立项时按本文件展开为 WP 与验收）。
> **版本**：0.1.0（预立案）
> **最后更新**：2026-11-17
> **上游依据**：`0.0.5-极境OS任务方案.md` §0.10 裁定 3；
> `10-references/base-definition-and-replacement.md` §6.2
> **读者**：桌面组、runtime 组、打包组

---

## 1. 一句话定义

在既有 UKUI 桌面上让出右侧一条固定栏位，内置 AirymaxRT 的智能体能力，
使「对话即操作计算机」成为桌面的一等交互，而不是外挂应用。

## 2. 布局契约

| 项 | 值 | 说明 |
|---|---|---|
| 桌面区宽度 | 3 份 | 原 4:3 语义改为 3:3，桌面让出右侧一条 |
| dock 宽度 | 1 份（默认 25%） | 可调区间 20%–40% |
| 最小可用宽度 | 320 px | 低于此值 dock 折叠为图标条，不隐藏 |
| 多显示器 | 仅主屏出现 dock | 副屏保持完整桌面 |
| 全屏应用 | dock 自动隐藏，热区唤出 | 不改变应用的可用分辨率声明 |
| 会话恢复 | 记住用户宽度 | 存会话配置，不写系统默认 |

「3:3 + 1:3」是**宽度语义**，不是像素常量；分辨率变化时按比例计算，
不出现按机型写死的宽度值。

## 3. 渲染与进程

| 项 | 决定 | 理由 |
|---|---|---|
| dock UI | Slint | 轻量、可声明式布局、Rust 原生、无 WebView 运行时依赖 |
| 进程 | 独立进程，崩溃不拖垮桌面 | dock 是增强，不是桌面的前置条件 |
| 与 boot TUI 关系 | **不复用运行时、不复用渲染器** | 0.0.5 裁定：一个契约层、两条独立通路 |
| 与 AirymaxRT 关系 | 复用其智能体能力（gateway） | 不重写计划与工具执行 |
| 中文输入 | 走 IBus（系统既有闭包） | GUI 会话已有 IBus，dock 不再自建 IME |

dock 不链接 agentrt 的 C 库；与 gateway 之间只走 HTTP/JSON-RPC + SSE。

## 4. 能力边界

### 4.1 能做什么

- 接收文本/语音意图（语音经 0.0.5 的 ASR 网关，或桌面既有录音栈）。
- 展示智能体的计划、步骤、结果与失败原因。
- 对高危动作发起确认，确认结果作为审批记录回传 runtime。
- 把结果转成可操作入口（打开文件、定位设置页、重跑任务）。

### 4.2 不能做什么

- 不自行决定策略；判定权在安全通道。
- 不绕过审批执行破坏性动作。
- 不在 gateway 不可用时伪造「已完成」；必须显示 `runtime=unavailable`。
- 不接管窗口管理、不替换 UKUI 的既有组件。

## 5. 两条通路的契约一致性

dock 与 boot TUI 共用 `docs-linux/30-interfaces/11-input-ingress.md` 的 Intent、
`trace_id`、信任级别、审批记录与错误语义。二者差异只允许在：

1. 执行器是谁（本地 `airy-*` vs AirymaxRT runtime）；
2. UI 形态（终端 vs Slint）。

每季度用同一组语料各跑一次，契约字段差异必须为 0。

## 6. 部署前置

| # | 前置 | 判据 |
|---|---|---|
| P-1 | AirymaxRT 以 RPM 交付 | 镜像内可 `rpm -q` 到固定 NEVRA，不依赖源码树 |
| P-2 | gateway 以 systemd 单元托管 | 开机自启、崩溃重启、日志进 journal |
| P-3 | 运行时资产按 digest 校验 | manifest 与实物不符即拒绝启动 |
| P-4 | 无网络可用 | 断网下 dock 与本地模型路径可用 |
| P-5 | 卸载干净 | 移除 dock 后桌面恢复 4:3 全宽，无残留单元 |

P-1 是硬前置：dock 不能要求用户先装开发环境。

## 7. 降级矩阵

| 情形 | 桌面 | dock | 用户可见状态 |
|---|---|---|---|
| gateway 未启动 | 正常 | 显示不可用 | `runtime=down` + 重试按钮 |
| 模型缺失 | 正常 | 仅结构化动作可用 | `model=missing` |
| SSE 断流 | 正常 | 保留最后事件，标断点 | `stream=closed@<seq>` |
| dock 进程崩溃 | 正常 | 自动重启一次 | 重启失败则保持折叠 |
| 审批服务不可用 | 正常 | 禁止高危动作 | `approval=unavailable` |

任何降级都不得改变桌面区的可用性；dock 是增强项，不是前置项。

## 8. 验收判据（预立案级）

| # | 判据 |
|---|---|
| D-1 | 默认 25%，可在 20%–40% 调整并持久化 |
| D-2 | 桌面区按 3:3 + 1:3 布局，多分辨率下比例不变 |
| D-3 | 对话可完成一次真实计算机操作（含审批与结果回显） |
| D-4 | gateway 停止时桌面不受影响，dock 显式不可用 |
| D-5 | 与 boot TUI 的契约字段差异为 0（同语料双跑） |
| D-6 | 卸载后桌面恢复全宽，无残留单元与配置 |
| D-7 | 断网下本地模型路径可用 |

## 9. 风险

| 风险 | 应对 |
|---|---|
| dock 与 UKUI 争窗口管理 | dock 只做普通置顶窗口，不注册窗口管理器角色 |
| Slint 版本与基底 Rust 版本不匹配 | 以 `lang-policy.yaml` 钉版；不达标则降级为纯 GTK 前端（需重新立项） |
| 智能体动作误触 | 高危动作强制审批；默认拒绝 |
| 25% 在小屏不可用 | 320 px 下限触发折叠；折叠仍可唤起 |
| 双通路漂移 | 季度同源断言 + `trace_id` 联查 |

## 10. 非目标

- 不做多 dock、不做插件市场。
- 不做脱离桌面的独立智能体应用。
- 不重写 AirymaxRT 的计划器或工具层。
- 不在本版替换 UKUI 自身组件。
