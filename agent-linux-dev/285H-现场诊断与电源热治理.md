# 285H 现场诊断与电源热治理复核

> 记录 2026-11-02 至 11-03 在 285H（Airymax@192.168.3.19，6.6.157-alk，
> SELinux Enforcing）上的断连/重启取证、电源与热状态复核、0.0.4 装机验证
> 与实时性实测。所有结论只依据已经取到的现场输出，未取到的项目明确标为
> 「待取证」。

## 1. 结论摘要

1. 现有 4 个 boot 记录中，3 次重启均为 **clean reboot**
   （`systemd-reboot.service` 正常走完关机和重启目标），与双标记取证、
   grub 配置复验的人工重启一一对应，没有 panic、MCE、OOM 或掉电留下的
   异常记录。
2. 首次失联时 285H **AC 不在线**（`ACAD online=0`），电池
   `energy_now=20.68Wh`，放电功率 `30.07W`，按当时负载约 **41 分钟**耗尽。
   该镜像 **未安装 airymax-power**（release 早于 release 9），没有任何
   低电量告警或降档动作，电池耗尽时表现为整机直接断电。这条缺口已由
   release 10/11 的档位控制与低电量动作闭合。
3. 装到 **0.0.4-17** 后，`airy-power.timer` 为 active，
   `sudo airy-power apply` 返回 `state=ok landed=49/49 rc=0`，16 个核的
   `C3_ACPI` 全部 `disable=1`。电源治理在 285H 上首次完整生效。
4. **实时性根因是空闲深度**：285H 的 `C3_ACPI` 退出延迟 1048 µs，本身已
   超过软实时 1000 µs 预算。关闭深空闲后，典型最大延迟从 900–1000 µs
   降到 100–400 µs；16 核 `yes` 满载三轮为 **10 / 10 / 92 µs**。
5. 仍存在 **偶发毫秒级尖峰**（实测 7997/8610 µs，tracer 下 443079 µs）。
   已排除 direct reclaim（`allocstall`、`pgscan_direct` 不增长，`pswpin`
   仅 +6）、单一活跃模型（暂停 27B 实例后仍复现）与内核异常路径
   （`wakeup_rt` 栈均为正常调度路径）。尖峰与**内存超卖窗口**相关，
   属 0.0.4 X-05「桌面与 RT 共存」范围。
6. 内存超卖是硬事实：三个 `llama-server` 实例 RSS 合计约 **29.5 G /
   30 G 物理**，swap 已用 **11 G**，`MemFree` 长期 250–380 MB。这不是
   实时性问题，而是整机稳定性问题，必须靠资源治理而不是延迟调参解决。

## 4. 实时性实测（X-04）

测量工具为 `airy-rt-lat`（`-p 90 -i 200 -D 30`），不绑核、不 pin，
与 `rt-accept.sh` 口径一致。全部单位为 µs。

| 场景 | 各轮最大延迟 | 判读 |
|------|-------------|------|
| 空闲 6×30 s | 162 / 317 / 31 / 436 / 165 / 110 | 全部 < 1000 |
| 16 核 `yes` 满载 3×30 s | 10 / 10 / 92 | 满载未恶化 |
| 干净 10×20 s | 91 / 20 / 85 / 118 / 133 / 378 / 67 / 303 / 194 / 106 | 全部 < 400，kswapd Δ≈0 |
| 带 `vmstat` 采样 6×30 s | 103 / 354 / 412 / **8610** / 849 / 198 | 尖峰非 direct reclaim |
| 暂停 27B 实例后 6×30 s | 227 / **7997** / 101 / 88 / 192 / 448 | 单一活跃模型不是唯一来源 |
| `wakeup_rt` tracer 6×30 s | 2233 / 10661 / **443079** / 4590 / 1385 / 278 | 栈为正常调度路径 |

`wakeup_rt` 取到的 1362 µs 唤醒栈为 `__schedule` →
`exit_to_user_mode_loop` → `do_syscall_64`，即 python3 唤醒测量进程的
正常路径，没有锁竞争、缺页或驱动回调证据。tracer 自身的 `stacktrace`
开销会放大数字，443079 µs 不能当作系统延迟上限。

基线记录（`sudo python3 distro/tests/rt/baseline.py record --rounds 3
--duration 30`）为 281 / 55 / **1199**，`max_us=1199`、`limit_us=1000`、
`grade=soft`、`machine=83JK`。按 `baseline.py` 的口径，1/3 轮未达门禁，
数据照常落盘但**不能作为合格基线**。这份记录留在现场侧
（`/tmp/rt-285h-004.json`），不进源码树。

两点判读：

1. `governor no` 是因为 285H 的内核只有 `performance`/`powersave`，

   统计全 0 是因为探测未产生事件，不是节点缺失。

## 6. 空闲深度根因与治理（release 17）

`C3_ACPI` 的退出延迟 1048 µs 与软实时预算 1000 µs 同量级，任何一次
进入 C3 后的唤醒都可能直接越线，这与「空闲/轻载时才出现 900–1000 µs、
满载反而 10–92 µs」的现象完全吻合——满载时 CPU 根本不进 C3。

治理策略写在 `system/services/airymax_power/idle.py`，与 governor/EPP
同级纳入同一份 `Knob` 证据链：

- 判据不是「禁用空闲」，而是「退出延迟 ≤ 1000 µs」；在预算内的
  `C1_ACPI`/`C2_ACPI` 保留，只关超预算的深态。
- 条件与档位一致：**AC 且热区未到 hot** 才收紧；电池或过热时恢复
  固件默认，不为实时性牺牲续航与散热。
- `inspect` 只读回读、`apply` 才写；`landed` 以回读的 `disable` 与
  延迟为准，不把「写过」当「生效」。

实机结果：16 核 `C3_ACPI disable=1`，`state=ok landed=49/49`，
典型延迟降到 100–400 µs。

## 7. 负载与内存超卖（X-05 范围）

现场三个 `llama-server` 实例：

| PID | 模型 | 端口 | 参数 | RSS | 备注 |
|-----|------|------|------|-----|------|
| 3288 | Qwen3.5-9B | 11435 | 12 线程 / 4 slots | 10.5 G | CPU 666% |
| 3289 | Qwen3.5-9B | 11436 | 子进程 | 1.0 G | — |
| 3656 | Qwen3.8-27B | 11437 | 4 线程 / 1 slot | 18.5 G | nice 19 |

合计 RSS ≈ 29.5 G，物理内存 30 G，`SwapFree` ≈ 5.1 G（已用 11 G），
`MemFree` 长期 250–380 MB，`MemAvailable` 约 14 G，`Dirty` 828 kB，
`kswapd0` 累计仅 8 s。内存相关参数：`swappiness=60`、
`min_free_kbytes=67584`、`watermark_scale_factor=10`、
`overcommit_memory=0`；THP `enabled=always`、`defrag=madvise`，
`compact_stall=4`、`compact_fail=4`、`pgmigrate_success=599320`。

判读：

1. `MemAvailable` 14 G 是「可回收」估算，不等于「可分配」；三个实例
   同时申请大页时仍会触发直接回收或 OOM，这正是毫秒尖峰出现的窗口。
2. `kswapd0` 累计 8 s 说明回收是**突发**而非持续，与「多数轮次正常、
   偶发一轮越线」的测量分布一致。
3. 这不是调 `swappiness` 能解决的问题。需要的是并发上限与内存配额：
   同一模型多实例、多 slot 会把 RSS 叠加到物理内存之上。

## 8. 已落地的治理（0.0.4 release 10–17）

- release 10：`airy-power.service`/`airy-power.timer`，每 60 s 按供电、
  电量、热余量与节流增速重新评估档位；`status` 只读，`apply` 写入并
  回读；退出码 0/3/1 供门禁判读。
- release 11：低电量动作。`charge <= 10%` 广播一次，`<= 5%` 请求
  `systemctl poweroff --no-block`；只在电池或弱适配器供电时动作，
  动作等级记在 `/run/airy-power/duty` 以去重。
- release 12：`airy-rt-coexist` 单元对与 `coexist` 子命令，桌面 slice
  权重跟随 CPU 压力，而不是固定值。
- release 13：`airy-rt-lat` 取代 `cyclictest` 作为基线工具；取不到
  `SCHED_FIFO` 时拒绝输出数字。
- release 14：整机负载纳入电源策略。PSI 可用时取 `some avg10`，
  否则用 loadavg/meminfo；swap 占比单独计分；负载高时 AC 档位保持
  `balanced` 并把 EPP 抬到 `balance_performance`。
- release 15：`airy-rt-lat.c` 先复制进构建树再编译，修复 openEuler
  `find-debuginfo` 归因失败导致的安装期报错。
- release 16：压力告警与档位共用同一个 `strain` 结论；只在等级变化时
  广播一次。
- release 17：空闲深度按实时预算收敛，见 §6。
