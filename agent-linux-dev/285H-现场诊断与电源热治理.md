# 285H 现场诊断与电源热治理复核

> 记录 2026-11-02 至 11-03 在 285H（Airymax@192.168.3.19，6.6.157-alk，
> SELinux Enforcing）上的断连/重启取证、电源与热状态复核，以及机器失联后
> 无法继续执行的部分。所有结论只依据已经取到的现场输出，未取到的项目明确
> 标为「待取证」。

## 1. 结论摘要

1. 现有 4 个 boot 记录中，3 次重启均为 **clean reboot**（`systemd-reboot.service`
   正常走完关机和重启目标），与双标记取证、grub 配置复验的人工重启一一对应，
   没有 panic、MCE、OOM 或掉电留下的异常记录。
2. 285H 当时 **AC 不在线**（`ACAD online=0`），电池 `energy_now=20.68Wh`，
   放电功率 `30.07W`，按当时负载约 **41 分钟**耗尽。该镜像 **未安装
   airymax-power**（release 早于 release 9），没有任何低电量告警或降档动作，
   电池耗尽时表现为整机直接断电——不在 journal 留下任何关机记录，与「意外
   断连、随后完全不可达」的现象一致。这是当前证据下最可能的根因。
3. 热状态正常：`x86_pkg_temp` 51–52 °C，本区 `critical` 80.05 °C；
   `package_throttle_count`/`core_throttle_count` 为 67910/32493，多次采样
   不增长，说明当时没有发生新的节流。
4. 机器随后完全失联：`ping` 100% 丢包，`ip neigh` 显示
   `192.168.3.19 dev eth0 INCOMPLETE`，开发机（192.168.3.6）到网关
   192.168.3.1 正常。二层无应答，无法区分「已断电」与「已挂起/网卡下线」。

## 3. 假设与判别

| 假设 | 支持证据 | 判别方法（机器恢复后） |
|------|---------|----------------------|
| H1 电池耗尽后掉电 | AC 离线、30W 放电、无低电量动作、失联前无异常日志 | 查 `journalctl --list-boots` 是否出现无关机记录的 boot；查 `journalctl -b -1 | tail` 是否有 `Reached target ... Shutdown` |
| H2 挂起或网卡下线 | 二层 ARP 无应答也可由挂起造成 | 查 `journalctl -b -1 | grep -iE "suspend|hibernat|link is down"` |
| H3 内核崩溃/看门狗复位 | 现有日志无 panic/MCE；iTCO 可复位整机 | 查 `journalctl -k -b -1 | grep -iE "panic|mce|soft lockup|watchdog"` |
| H4 适配器未被 EC 识别 | `ACAD online=0`，若实际已插电则属固件/EC 问题 | 插电后看 `ACAD online` 是否变 1；不变则转固件侧 |

## 4. 已确认的低风险项

`watchdog did not stop!` 出现在关机后段：systemd-shutdown 会按
`ShutdownWatchdogSec`（缺省 10 分钟）武装看门狗，若内核在关机末尾未显式停止
iTCO，就会留下该行。它不改变关机结果，但会拖长关机可见时间；处置方式是在
shutdown 前显式 disarm，或把 `ShutdownWatchdogSec` 收紧到与关机预算匹配。
本项列入 0.0.4 遗留债，未在本次改动。

## 5. 已在 0.0.4 落地的治理

- `airymax-power` 包与 `airy-power.service`/`airy-power.timer`（release 10）：
  每 60 s 按供电、电量、热余量与节流增速重新评估档位；`status` 只读，
  `apply` 写入并回读；退出码 0/3/1 供门禁判读。
- 工作站 kickstart 显式启用 `airy-power.service`、`airy-power.timer` 与
  `airy-rt-bandwidth.service`；服务器档位保持禁用，sysfs 不动。
- 低电量：`charge <= 10%` 按 cool 档处理（降频、降平台档位）。
