# UKUI 4.24 可行性成册（R1-10 / UK-02）

> 版本: 1.0.0
> 成册日期: 2026-11-02
> 判定: 0.0.4 不追 4.24；取基底最高稳定组件代（3.1）。4.24 自建闭包顺延。

---

## 1. 问题

0.0.4 的桌面决策目标是 UKUI 4.x。需要回答两件事：

1. 基底 openEuler 24.03 LTS 全条线仓库里到底有没有 4.2x；
2. 若没有，是自建源码包闭包追 4.24，还是取基底内最高稳定组件代。

结论必须能由仓库数据复算；未成册即判 BLOCKED（UK-02）。

---

## 2. 实测事实

证据见 `ukui-delta.md`，唯一事实源为
`agent-linux/distro/lockfile/ukui-components.yaml`。

| 事实 | 取值 |
|---|---|
| 24.03 LTS 及 SP1~SP4 组件代 | 窗管 1.0.5、面板 3.1.0、会话 3.1.0、控制中心 3.1.2 |
| 24.03 LTS 全条线 4.2x | 无 |
| 24.09 / 25.03 / 25.09 组件代 | 4.0 / 4.0 / 4.10，仍无 4.2x |
| `ukui-shell` | 全条线无此包；壳层由 `ukui-kwin` 承担 |
| `ukui` 元包 | 全条线无此包 |
| 组件所在段 | 仅 `EPOL/main`（24.03-LTS 首发线的控制中心勘误在 `EPOL/update/main`） |

外部前提：据 openKylin 3.0 的发布口径，UKUI 4.24 属 openKylin 3.0 线。
该前提只用于界定自建闭包的源码来源，**不作为基底版本证据**，也不参与
版本号比较。

---

## 3. 路线 A：按 openKylin 上游重组包名自建源码包闭包

### 3.1 工作项

| 编号 | 工作项 | 产出 | 风险 |
|---|---|---|---|
| A-1 | 源码取得与许可复核 | 每个组件的源码 tarball、SPDX、许可证清单 | GPL/CC 资产混入，主题与图标许可不清 |
| A-2 | 包名重组与拆分规则 | 与基底 `ukui-*` 不冲突的命名表 | 同名不同源，升级路径不可判定 |
| A-3 | 构建依赖对齐 | 对 oe24.03 的 Qt5/KWin/glib 版本矩阵 | 4.24 假设的 Qt/KWin 版本高于基底 |
| A-4 | 会话与登录集成 | 新 `ukui.desktop`、greeter、lightdm 配置 | 与既有 `ukui-session-manager` 冲突 |
| A-5 | 主题、图标、壁纸 | 资产包与品牌默认集 | 资产许可与体积 |
| A-6 | 补丁与 CVE 维护 | 每组件补丁队列与安全跟踪 | 自建即自维护，无上游发行版兜底 |
| A-7 | 构建、签名与 SBOM | 全量 RPM、签名链、SBOM 条目 | 签名与 SBOM 需重走 0.0.4 全套门禁 |
| A-8 | 装机与回归 | 285H 真机装机、会话 smoke、23 进程基线 | 一次性引入整代新组件，回归面最大 |

### 3.2 代价

- 组件数量按上游拆分在 30 个以上，每个都要独立源码包、补丁队列与
  安全响应；
- 与基底既有 `ukui-*` 3.1 组件并存会产生文件路径、D-Bus 名与
  systemd 单元冲突，必须整代替换，无法局部升级；
- 自建闭包绕过基底 repodata，版本证据从「仓库实测」退化为「本仓构建
  记录」，与 J-35 的取证口径冲突，需要额外的可复算账本；
- 4.24 依赖的 Qt/KWin 代际高于 oe24.03 基底，抬高内核基线之外的第二条
  版本线，违反「内核基线优先」（J-36）的收敛原则。

### 3.3 结论

0.0.4 不采用路线 A。工作项登记在册，作为 0.0.5 之后的候选，触发条件
见 §5。

---

## 4. 路线 B：取基底内最高稳定组件代

### 4.1 内容

- 以 24.03 LTS-SP2 的 `EPOL/main` 3.1 组件代为唯一桌面基线；
- 组件 NVRA 逐字钉在 `ukui-components.yaml`，comps 与冻结输入同源；
- 版本证据、复算命令、段位分布全部落在 `ukui-delta.md`；
- 会话、适配层与 23 进程基线由 R1-11 承接，桌面显式依赖由 R1-13 承接。

### 4.2 代价与风险

- 与 4.24 存在功能代差，桌面观感与交互停留在 3.1；
- 组件安全更新依赖 openEuler EPOL 的 SP 勘误节奏，不能自行加速；
- 若未来基底 SP 线引入 4.2x，需要重新走 R1-10 的取证与差异清单，
  不能直接改版本号；
- 4.24 独有能力（新壳层交互、设置项）在本版不可用，须在发布说明中
  如实声明，不得以「UKUI 4.x」表述交付。

### 4.3 结论

0.0.4 采用路线 B。它满足三条硬约束：版本证据可复算、内核基线不动、
装机闭包可解析。

---

## 5. 取舍与顺延

| 维度 | 路线 A（4.24 自建） | 路线 B（基底 3.1） |
|---|---|---|
| 版本证据 | 本仓构建记录，需另建账本 | 仓库 repodata 实测，可直接复算 |
| 内核基线 | 不冲突，但引入第二条组件代线 | 不冲突 |
| 维护成本 | 30+ 源码包、补丁队列、CVE 自担 | 随 EPOL 勘误 |
| 装机风险 | 整代替换，冲突面最大 | 与基底同源，闭包可解析 |
| 交付节奏 | 需完整重走构建、签名、SBOM、真机回归 | 纳入既有 R1 任务卡 |
| 0.0.4 结论 | 顺延 | 采用 |

再评估触发条件（任一成立即重开本册）：

1. 24.03 LTS 的后续 SP 在 `EPOL/main` 出现 4.2x 组件；
2. openKylin 提供与 oe24.03 基线兼容、可直接消费的 RPM 仓库；
3. 0.0.5 排期允许单列「桌面组件代升级」工作包，且具备独立维护人力。

顺延不等于放弃：路线 A 的八个工作项已结构化登记，重开时按 A-1 至 A-8
逐项评估，不从头再来。

## 6. 与铁律的关系

- J-35：版本只认仓库实测。路线 B 的每个 NVRA 都能用 §5.1 的
  `dnf -q repoquery` 复算；路线 A 无法用同一命令复算，故不选。
- J-36：内核基线优先。桌面组件代不得反过来牵引内核或基底换代。
- UK-02 的 BLOCKED 条件在本册成文后解除；若后续任一实测值与
  `ukui-components.yaml` 不一致，本册与台账同时回退为 BLOCKED，
  先重新取证再改结论。
