## 3. SSoT 权威性分析

### 3.1 当前 SSoT 声明覆盖范围

审查工程标准规范附录 A L1348 的 SSoT 声明：

> **SSoT 声明（2026-07-15 升级）**：本附录为闭源侧摘要登记，**完整规则编号登记的唯一权威来源**为 `09-ssot-registry.md`...

**问题**：当前 SSoT 声明**仅覆盖规则编号**（OS-IRON / OS-BAN / OS-STD 等），未覆盖以下关键权威源：

| 权威源 | 当前状态 | 问题 |
|--------|---------|------|
| syscall 编号 | 无 SSoT 声明 | `07-syscall-registry.md` 的绝对权威地位未在闭源文档中声明 |
| ABI 契约 | 无 SSoT 声明 | `unistd.h` / `syscall_64.tbl` / `syscall.xml` 三方一致性无强制约束 |
| codegen 管道 | 无 SSoT 声明 | `syscall.xml` 作为 codegen 契约源的权威地位未声明 |
| ABI 检查工具 | 无 SSoT 声明 | `abi_check.py` 作为 CI 强制检查工具的权威地位未声明 |

### 3.2 SSoT 权威性差距

当前 SSoT 声明存在 **4 个权威空白**：

1. **syscall 编号 SSoT**：`07-syscall-registry.md` 是 syscall 编号唯一权威，但闭源文档未声明
2. **ABI 三方一致性 SSoT**：SSoT / unistd.h / syscall_64.tbl 三方必须一致，无强制约束声明
3. **codegen 契约 SSoT**：`syscall.xml` 是 codegen 契约唯一源，未声明
4. **ABI 检查工具 SSoT**：`abi_check.py` 是 ABI 一致性检查唯一工具，未声明

### 3.3 SSoT 权威加强需求

需要在工程标准规范中新增 **OS-IRON-018** 铁律，将 SSoT 权威从"规则编号"扩展到"syscall 编号 + ABI 契约 + codegen 管道 + ABI 检查工具"四大权威源。

## 7. SSoT 权威加强方案

### 7.1 新增 OS-IRON-018~021 四条铁律

在工程标准规范附录 A.1 OS-IRON 工程铁律中新增 4 条：

```
| OS-IRON-018 | syscall 编号 SSoT——`07-syscall-registry.md` 是 syscall 编号唯一权威源，所有文档/代码/工具的 syscall 编号必须以此为准，禁止在任何其他位置重新定义 syscall 编号 | §15.6 |
| OS-IRON-019 | ABI 三方一致性——SSoT 文档 / `unistd.h` / `syscall_64.tbl` 三方 syscall 编号必须完全一致，由 `abi_check.py` 在 CI 中强制检查，任何一方变更必须同步更新其他两方 | §15.6 |
| OS-IRON-020 | codegen 契约 SSoT——`syscall.xml` 是 codegen 管道契约唯一源，所有 syscall stub 生成必须基于此契约，禁止手写 syscall 编号定义 | §15.6 |
| OS-IRON-021 | ABI 检查工具 SSoT——`abi_check.py` 是 ABI 一致性检查唯一工具，CI 流水线必须强制执行，6 项检查全部 PASS 方可合并 | §15.6 |
```

### 7.2 新增 §15.6 SSoT 权威源体系

在工程标准规范第 15 章新增 §15.6 章节，声明四大权威源体系：

```
### 15.6 SSoT 权威源体系（v3.0 新增）

agent-linux 的 SSoT（Single Source of Truth）权威源体系由四大权威源构成：

| 权威源 | SSoT 文档/工具 | 覆盖范围 | 强制约束 |
|--------|---------------|---------|---------|
| 规则编号 SSoT | `09-ssot-registry.md` | OS-IRON/BAN/STD/ACC 等全部规则编号 | OS-IRON-015 |
| syscall 编号 SSoT | `07-syscall-registry.md` | 4 核心 syscall + 20 预留 + op-dispatch 映射 | OS-IRON-018 |
| ABI 三方一致性 | SSoT + `unistd.h` + `syscall_64.tbl` | syscall 编号三方必须一致 | OS-IRON-019 |
| codegen 契约 SSoT | `syscall.xml` | syscall stub 生成契约 | OS-IRON-020 |
| ABI 检查工具 SSoT | `abi_check.py` | CI 强制 ABI 一致性检查 | OS-IRON-021 |

**冲突裁决规则**：当任何文档/代码/工具与 SSoT 权威源冲突时，以 SSoT 为准。任何对 syscall 编号的变更必须先更新 SSoT，再通过 `abi_check.py` 验证三方一致性，最后同步下游文档。
```

### 7.3 SSoT 权威加强效果

加强后的 SSoT 权威体系将实现：

1. **编号唯一性**：syscall 编号只能在 SSoT 中定义，禁止在其他位置重新定义
2. **三方强制性**：ABI 三方一致性由 CI 强制检查，任何一方变更必须同步
3. **codegen 强制性**：syscall stub 必须从 codegen 契约生成，禁止手写
4. **检查强制性**：ABI 检查工具 6 项全部 PASS 方可合并
